# pf2e-automato — правила автоматизации

Обязательны для Руководителя и всех агентов. Каждое правило — ошибка, которую уже исправляли. Перед планом и перед сдачей работы пройди по списку.

## 1. Правила игры

1. **Ограничения способностей и заклинаний — часть автоматизации.** Требования к использованию, «один раз за раунд», досягаемость, частота, условия «только если» реализуются сразу, без вопроса пользователю.
   - Форма: действия нет, предупреждение «что не так и что сделать», обход Alt при клике (решение ГМа). Образец — `scripts/builtin/melee-reach.mjs`, `scripts/builtin/impulse-gate.mjs`.
   - Примеры: импульс без кинетической ауры, второе переполнение за раунд, Удар вблизи вне досягаемости.
2. **Текст правила — из источника, не по памяти.** Сверяй с описанием предмета (`tools/out/items.json`, `descEn`) и с описанием черт в pf2e (`systems/pf2e/lang/en.json`, `TraitDescription*`). Например, переполнение — «одно **за раунд**», а не «за ход».
3. **Сначала проверь, что pf2e уже делает сам** (grep по `pf2e.mjs`). Не дублируй проверку системы. Например, Стихийный взрыв без ауры pf2e блокирует сам («No kinetic gate»).
   - Если встроенная автоматизация pf2e мешает удобству пользователя (ручной переключатель, неполная механика), её можно отключить и взять механику на себя. Условия: отключение обратимо (без модуля поведение pf2e возвращается) и нет двойного эффекта (§3.5).
4. **Механизм делается для всей группы предметов**, а не для одного (импульсы — все 128, а не одна колонна). Каждое решение — для всего множества по черте или признаку.
5. **Без переключателей, где условие можно вычислить.** Если модуль сам может проверить условие способности (союзники в досягаемости, состояние цели, расстояние), опция броска подставляется в момент броска, а не через `RollOption` с `toggleable` на листе и не через шаг `rollOption`, который его щёлкает. Переключатель — только для решения игрока, которое модуль узнать не может. Пример: «Стайный» считает союзников цели в досягаемости при броске урона, без переключателя.
   - Переключатель вычисляемой опции не показывается ни в токен HUD, ни на листе: лишние переключатели захламляют HUD. Скрывать нужно штатно, через данные правила, а не CSS по каждому модулю.

## 2. Названия и тексты

1. **Названия не придумывать.** Название предмета в строке UI — с листа актёра (`item.name`, перевод уже применён), а не текстом в lang. Термины — из pf2ru-translation (`DESIGN.md` §строки). Пример ошибки: «Направить стихию» вместо «Проведение стихийной энергии».
2. **Заголовки и подписи на карточке — на языке игрока.** Английский `label` из каталога правил пользователю не показывать, вместо него — название предмета.
3. Каждая строка — через `lang/ru` и `lang/en`. Где есть подпись pf2e (`PF2E.DamageLabel` и т. п.), бери её.

## 3. Карточки и кнопки

1. **Единообразие.** Одно действие — одна и та же кнопка на всех карточках. Урон всегда бросается кнопкой «Урон», а не кликом по формуле в описании (`scripts/damage-button.mjs`). Продолжительный урон не бросается, а накладывается кнопкой «Наложить продолжительный урон» по итогу спасброска цели. То же правило — для спасброска и применения эффекта.
2. **Порядок сверху вниз по ходу действия:** описание → спасброски/атака → урон → применение эффектов. Игрок не должен прыгать по карточке вверх-вниз.
   - **Одна кнопка в один момент:** кнопка следующего шага появляется, только когда шаг наступил. «Урон» — после размещения области, после итогов спасбросков всех целей, после попадания атакой; атаки скрываются после броска урона. Правило общее для всех карточек (заклинания, импульсы, действия, расходники), не для одного предмета.
   - Шаги «применить сразу» (`onUse.apply`) — часть самого использования: их блок стоит над спасбросками. «Применение эффектов» в конце порядка — это применение по степеням успеха.
3. **Нет кнопки для того, что модуль делает сам.** Например, урон опасной местности наносит зона при входе — кнопки «Урон» для этой формулы нет. Двух путей к одному результату быть не должно: это двойной урон.
4. **Свои броски модуля не блокируются его же проверками.** Если сценарий модуля уже решил, что действие законно (Реактивный удар), бросок идёт через обход (`unchecked`).
5. **Без двойного нанесения.** Перед автоматическим уроном или эффектом проверь отметки ручных путей: кнопки pf2e, Блок щитом, Toolbelt. Откат pf2e должен работать.

## 4. Проверка

1. **Живой прогон** — на копиях («Тестовые копии (автоматизация)» в RustySpirit), после прогона всё убрать. Сцену «Тест» пользователя не трогать.
2. **Если в мире свежие сообщения или изменения пользователя** (он тестирует руками), свои сообщения удаляй точечно, чужое состояние (эффекты, флаги) не меняй. Результат, полученный на чужом состоянии, не засчитывай.
3. Перед коммитом — Критик по диффу. Коммит — только по явному «коммить».
4. **Изъян — проверить всю группу и сообщить о ней.** Если дефект может быть не только у найденного предмета, а у группы сущностей (тип карточки, вид предметов, общий селектор или хук), проверь всю группу: по коду и живым прогоном. Без этого исправление не считается готовым.
   - В отчёте назови проблемную группу и её состав, затем дай итог по каждому члену: подтверждено и исправлено, не воспроизводится, ограничение.
   - Пример: Огненный шар показывал три кнопки шагов сразу. Группа — «кнопки шагов на карточках»: заклинания (спасбросок, атака, область, варианты), способности, расходники, импульсы, карточки модуля. Проверка всей группы нашла ещё пять дефектов с общей причиной.
