# ROADMAP: оптимальная автоматизация всего контента pf2e

Цель: максимум автоматизированного контента при минимуме уникального кода на одно правило. Сначала кампания TheGreatRoute,
затем общий контент, затем полный компендий для публичного релиза.

Связанные документы:
- контракт схемы правила — `plan.md` §1;
- архитектура — `architecture.md`;
- стиль UI — `DESIGN.md`;
- снимок покрытия — `coverage.md`.

## 2. Четыре слоя (от дешёвого к дорогому)

Каждый предмет относится к первому подходящему слою.

1. **Уже сделано другими.** pf2e (`selfEffect`, Rule Elements, `EphemeralEffect`, тиски, `Aura`), pf2e-automations, Toolbelt, Workbench. Модуль уступает через реестр «уже автоматизировано». После каждого обновления pf2e реестр пересматривается: система сама дописывает автоматизацию (пример: «Жуткие удары»).
2. **Вывод из разметки.** Парсер `deriveFromMarkup` (`scripts/rules.mjs`) прогоняется пакетно по компендиям. Результат — черновики правил с уверенностью:
   - **high** — сразу в каталог;
   - **low** — в очередь просмотра в «Мастерской» с пробным запуском.
3. **Декларативные примитивы схемы.** Каталог (`rules/catalog*.json`) и правила на предметах. Новый механизм сначала появляется как встроенный обработчик. На третьем похожем случае он становится полем схемы (см. §3).
4. **Код.** Только для уникальной механики: несколько Ударов с выбором оружия, распределение снарядов, особые окна. Ожидается несколько процентов контента.

## 3. Примитивы схемы

Уже есть: виды шагов `condition` / `effect` / `note` / `visibility` / `persistent`, `challenge`, `check`, `byDegree`, `zone`, `onAttacked`, `escape`, проверка дальности (`scripts/range.mjs`), макросы `builtin:*`.

Кандидаты: из встроенных обработчиков в поля схемы, чтобы их можно было задавать данными и в «Мастерской».

| Кандидат | Откуда | Что даёт |
|---|---|---|
| `selfEffect` своими правилами (эффект на себя из RE без эффекта pf2e) | `tentacular-limbs` | заклинания и действия «на себя», которые pf2e не автоматизировал |
| `ephemeral` — off-guard / модификатор только в нужной атаке | `twin-feint`, `surprise-attack`, `fake-out` | «цель застигнута врасплох перед вами», «следующая атака» |
| `expire` — снятие эффекта по событию | `one-shot-one-kill`, `surprise-attack`, `spellshape` | конец хода, следующее сотворение, начало хода цели, первый урон оружием группы X |
| `onInitiative` — триггер по броску инициативы навыком | `one-shot-one-kill`, `surprise-attack` | черты «если бросили инициативу Скрытностью/Обманом» |
| `toggleToAction` — переключатель → эффект по нажатию | `spellshape`, `one-shot-one-kill` | все «следующее действие получает…» |
| `multiStrike` — серия Ударов с условием | `double-slice`, `blade-dance`, `twin-feint` | «два Удара; если оба попали…» |
| `prompt` — выбор у игрока (окно) | `blood-magic`, `variable-cast` | выбор варианта, числа действий, распределения |

Правило: не больше одного нового примитива на пачку. Каждый примитив сопровождается `ruleToForm` / `formToRule` (`scripts/sheet.mjs`), валидатором, тестом и описанием в README.

## 4. Приоритет

1. **Кампания:** предметы и способности персонажей (Варрис, Шен-Ли, Муссария, Лиарэль) и их следующих 2–3 уровней.
2. **NPC ближайших сцен и бестиариев кампании.**
3. **Общий контент по частоте:** базовые действия (Захват, Финт, Демонстрация и т. п.), популярные заклинания 1–5 круга, расходники (зелья, свитки, эликсиры), общие черты навыков.
4. **Остальной компендий** — под публичный релиз.

## 6. Инфраструктура (пачка 0)

1. **Инвентаризатор мира.** Скрипт для вкладки ведущего выписывает все предметы и способности актёров мира со слоем и статусом: «pf2e / модуль / выводится / вручную / не автоматизируется». Результат — `inventory-world.json` и таблица в `coverage.md`.
2. **Пакетный вывод разметки.** Прогон `deriveFromMarkup` по всем пакам (pf2e 8.6.1, тексты pf2ru для ru-описаний). Результат — `rules/drafts/*.json`, черновики с уверенностью и причиной.
3. **Очередь просмотра в «Мастерской».** Открыть черновик, пробный запуск, одобрить и записать в каталог.
4. **Регрессионный набор живых сценариев** (`tests/live/`). Повторяемые сценарии «сотворил → цель → исход» для уже сделанного: Силовой залп, Фантомная боль, лиана и Освобождение, тиски, Внезапная атака, метамагия, дальность, блок щитом, перезарядка. Запуск — из вкладки ведущего, без ручных кликов.
5. **Дашборд покрытия:** процент по типам, по кампании и по пачкам. Обновляется после каждой пачки.

## 7. Правила работы

- Решение общее, а не точечное под предмет: пользователь требует глобальных исправлений.
- Никаких кнопок для того, что модуль делает сам. Постоянные состояния не вешать ради разового эффекта.
- UI по `DESIGN.md`, тексты ru/en, термины pf2ru.
- Каждая пачка заканчивается живой проверкой и проходом Критика перед коммитом.
- Тестовые актёры и токены — только копии «AF тест: …». После проверки их удалять.
