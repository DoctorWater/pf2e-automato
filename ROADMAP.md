# ROADMAP: оптимальная автоматизация всего контента pf2e

Цель: максимум автоматизированного контента при минимуме уникального кода на одно правило. **Цель — публичный релиз**:
весь компендий pf2e, ru и en на равных, работа в любом мире. Кампания TheGreatRoute — испытательный стенд для живых проверок.

Связанные документы:
- контракт схемы правила — `plan.md` §1;
- архитектура — `architecture.md`;
- стиль UI — `DESIGN.md`;
- снимок покрытия — `coverage.md`.

## 2. Четыре слоя (от дешёвого к дорогому)

Каждый предмет относится к первому подходящему слою.

1. **Уже сделано самим pf2e.** `selfEffect`, Rule Elements, `EphemeralEffect`, тиски, `Aura`. Модуль это не дублирует. После каждого обновления pf2e реестр пересматривается: система сама дописывает автоматизацию (пример: «Жуткие удары»).
   **pf2e-automations сюда НЕ входит** (решение пользователя 2026-10-23). Модуль должен покрывать всё, что покрывает pf2e-automations, чтобы его можно было выключить. Его правила — источник для переноса (`tools/pa-port.mjs`, пачка 0.5), а не причина пропуска. Механизм `yield` уступает pf2e-automations, пока перенос не завершён, чтобы не было двойного применения. Toolbelt и Workbench остаются смежными модулями: модуль совместим с ними, но от них не зависит.
2. **Вывод из разметки.** Парсер `deriveFromMarkup` (`scripts/rules.mjs`) прогоняется пакетно по компендиям. Результат — черновики правил с уверенностью:
   - **high** — сразу в каталог;
   - **low** — в очередь просмотра в «Мастерской» с пробным запуском.
3. **Декларативные примитивы схемы.** Каталог (`rules/catalog*.json`) и правила на предметах. Новый механизм сначала появляется как встроенный обработчик. На третьем похожем случае он становится полем схемы (см. §3).
4. **Код.** Только для уникальной механики: несколько Ударов с выбором оружия, распределение снарядов, особые окна. Ожидается несколько процентов контента.

## 3. Примитивы схемы

Уже есть: виды шагов `condition` / `effect` / `note` / `visibility` / `persistent`, `challenge`, `check`, `byDegree`, `zone`, `onAttacked`, `escape`, проверка дальности (`scripts/range.mjs`), макросы `builtin:*`.

Кандидаты: из встроенных обработчиков в поля схемы, чтобы их можно было задавать данными и в «Мастерской».

| Кандидат | Откуда | Что даёт |
|---|---|---|
| `selfEffect` своими правилами (эффект на себя из RE без эффекта pf2e) | `tentacular-limbs` | заклинания и действия «на себя», которые pf2e не автоматизировал |
| `ephemeral` — off-guard / модификатор только в нужной атаке | `twin-feint`, `surprise-attack`, `fake-out` | «цель застигнута врасплох перед вами», «следующая атака» |
| `expire` — снятие эффекта по событию | `one-shot-one-kill`, `surprise-attack`, `spellshape` | конец хода, следующее сотворение, начало хода цели, первый урон оружием группы X |
| `onInitiative` — триггер по броску инициативы навыком | `one-shot-one-kill`, `surprise-attack` | черты «если бросили инициативу Скрытностью/Обманом» |
| `toggleToAction` — переключатель → эффект по нажатию | `spellshape`, `one-shot-one-kill` | все «следующее действие получает…» |
| `multiStrike` — серия Ударов с условием | `double-slice`, `blade-dance`, `twin-feint` | «два Удара; если оба попали…» |
| `prompt` — выбор у игрока (окно) | `blood-magic`, `variable-cast` | выбор варианта, числа действий, распределения |

Правило: не больше одного нового примитива на пачку. Каждый примитив сопровождается `ruleToForm` / `formToRule` (`scripts/sheet.mjs`), валидатором, тестом и описанием в README.

## 4. Приоритет (под релиз)

1. **Общий контент по частоте использования:**
   - базовые действия навыков (Захват, Финт, Демонстрация, Обезоруживание…);
   - заклинания 0–5 круга;
   - расходники (зелья, эликсиры, яды, свитки);
   - общие черты навыков и классов.
2. **Остальные заклинания, черты и снаряжение** по кругу и уровню, снизу вверх.
3. **Способности NPC бестиариев.** Много дублей одной способности: сначала дедуп по slug и тексту, потом пачка.
4. **Кампания** — не отдельный этап, а стенд. Её актёры дают живые сценарии, их предметы проверяются в первую очередь в каждой пачке.

**Перенесено в пачку 7 (решение пользователя 2026-10-24):** долг 0.5g «следующее сотворение» — Lingering Composition ×2, Fortissimo Composition ×2, Extend Boost. Механизм под всю группу «если следующее действие — сотворение…» (~210 в ядре, бросок владельца у 18). Итоги проверки плана Критиком:
- вместо эффекта-метки — предикат «предыдущее действие этого актёра — предмет X» по ленте чата (как `recentShape` в `spellshape.mjs`), правило на самом заклинании; постоянного состояния нет;

- `criticalFailure` = провал (возврат фокуса); один бросок на сообщение, а не на цель;
- цели ауры (союзники в радиусе) и таблица СЛ по уровню задаются явно;

**Решения пачки 1 (2026-10-24):**
- Вывод из разметки (`deriveFromMarkup`) по выборкам ошибочен примерно наполовину. В рантайме он `low`: бросок идёт, применение — только кнопкой ведущего. Автоматически исполняются только каталоги; правила моделей — `rules/catalog.model.json` (`tools/drafts.mjs`). Черновики разметки проходят проверку моделью: `node tools/haiku-input.mjs all --review`, промпт `tools/prompts/review-rule.md`. Haiku на проверке дал 9/50 ошибок, поэтому последняя ступень — Sonnet.
- В отчёте покрытия «готово» = pf2e + catalog + pa (закрыто переносом PA) + model; `markup-*` — черновик.
- Сюжет, решения ведущего, предметы и информация не автоматизируются — только их побочные эффекты (иммунитет). Правило из одних заметок — долг, а не готово. Реальная механика без примитива — `needs-primitive` с меткой `missing: …`, не null.

- Рейтинг примитивов по долгу пачки 1: привязка испытания к попаданию Удара (~70), триггерный спасбросок в ауре / в начале хода (~60), активация снаряжения «You cast X» с СЛ предмета (~70, у pf2e кнопки каста нет — нужна своя), принудительное перемещение (~50), состояние, привязанное к другому (~40), штраф без эффекта (~35), стадии недугов (~25), выбор режима (~25).

## 6. Инфраструктура (пачка 0)

1. **Инвентаризатор мира.** Скрипт для вкладки ведущего выписывает все предметы и способности актёров мира со слоем и статусом: «pf2e / модуль / выводится / вручную / не автоматизируется». Результат — `inventory-world.json` и таблица в `coverage.md`.

3. **Очередь просмотра в «Мастерской».** Открыть черновик, пробный запуск, одобрить и записать в каталог.
4. **Регрессионный набор живых сценариев** (`tests/live/`). Повторяемые сценарии «сотворил → цель → исход» для уже сделанного: Силовой залп, Фантомная боль, лиана и Освобождение, тиски, Внезапная атака, метамагия, дальность, блок щитом, перезарядка. Запуск — из вкладки ведущего, без ручных кликов.
5. **Дашборд покрытия:** процент по типам, по кампании и по пачкам. Обновляется после каждой пачки.

## 7. Правила работы

- Решение общее, а не точечное под предмет: пользователь требует глобальных исправлений. Если предмет — пример большой группы, механизм сразу делается под всю группу.
- Никаких кнопок для того, что модуль делает сам. Постоянные состояния не вешать ради разового эффекта.
- UI по `DESIGN.md`, тексты ru/en, термины pf2ru.
- Русский перевод (UI, тексты правил, ru-описания черновиков) использует терминологию pf2ru-translation.
- Каждая пачка заканчивается живой проверкой и проходом Критика перед коммитом.
- Тестовые актёры и токены — только копии «AF тест: …». После проверки их удалять.

## 8. Решения пользователя (2026-10-23)

- **Цель:** публичный релиз (§4).
- **Темп без лишних токенов:** конвейер с младшими агентами на Haiku (§9).
- **Проверка качества:** из каждой пачки случайная выборка 50 правил (§10).

## 9. Конвейер с экономией токенов

Главный принцип: тяжёлую работу делают скрипты, агенты получают сжатый вход и отдают только JSON.

| Шаг | Кто | Почему так |
|---|---|---|
| Сбор и сжатие входа: slug, тип, дальность, защита, область, описание без HTML, ru и en | node-скрипт | бесплатно, детерминированно |
| Сортировка по слоям §2 и вывод из разметки | node-скрипт (`deriveFromMarkup`, реестр «уже автоматизировано») | закрывает ~40% без агентов |
| Черновики правил для остатка: 30–50 предметов на вызов, вход — сжатая таблица, выход — JSON по схеме | **Джун (Haiku)** | механическое заполнение по шаблону; схема и примеры в промпте одни на всю пачку |
| Валидация каждого черновика `validateRule` + `ruleToForm` / `formToRule` туда-обратно | node-скрипт | ошибки формы ловятся без модели; невалидное уходит Джуну на повтор с текстом ошибки |
| Предметы, где Джун пишет «не уверен» или повтор снова невалиден | **Рабочий (Sonnet)** | только трудный остаток, а не вся пачка |
| Новый примитив схемы, код, миграции | **Рабочий (Sonnet)** | проектирование |
| Код и примитивы перед коммитом | **Критик (Opus)** | на швах, не на данных |
| Выборка 50 правил (§10) | **Критик (Opus)** — один вызов на пачку | дорогая модель — только на выборку |

Правила экономии:
- Агент не читает репозиторий. Схема, 5–10 эталонных правил и таблица предметов — в промпте, одинаковые для всей пачки.
- Ответ — только JSON, без пояснений.
- Ошибки формы ловит валидатор, а не модель.
- Opus тратится на код, примитивы и выборку, а не на заполнение данных.
- Если доля ошибок в выборке у Haiku выше порога (§10), следующая пачка этого вида идёт через Sonnet. Модель подбирается по фактическому качеству, а не заранее.

## 10. Проверка выборкой

Из каждой пачки — 50 случайных правил (сид фиксируется в отчёте пачки).
1. **Форма:** валидатор и сериализация «форма ↔ правило» без потерь. Это 100% пачки, скриптом, не только выборка.
2. **Смысл:** Критик сверяет правило с текстом предмета (pf2e en и pf2ru ru) — кому, по какой степени, что, СЛ, длительность, дальность.
3. **Живой прогон:** 5 из 50 на копиях в мире-стенде.
4. **Порог:** не больше 2 смысловых ошибок из 50 (≥96%). Иначе ищется общая причина (промпт, пример, примитив), исправляется, пачка переделывается целиком.
