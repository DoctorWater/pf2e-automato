# pf2e-automato — бриф

## Назначение
Модуль автоматизации для системы PF2e, по духу аналог MIDI QOL для dnd5e. Уменьшает ручную работу ГМа и игроков:
когда предмет, черта, заклинание или способность используется, нужные эффекты и состояния применяются сами
(или предлагаются кнопкой), испытания целей бросаются автоматически и результат применяется по степени успеха,
реакции и триггеры подсказываются/срабатывают, области (дым, туманы, ауры) живут как зоны.

Триггер появления: «Дымовая шашка» ставит шаблон, но не накладывает «Плохую видимость» на существ в области.

## Входит (ядро)
1. **Эффекты от предметов и черт** — при использовании предмета/черты/заклинания/способности применять эффекты
   (pf2e effect items, ссылки `@UUID[...equipment-effects/spell-effects/feat-effects/bestiary-effects...]`)
   и состояния (conditionitems) на нужные токены: себя, цели, существ в области.
2. **Испытания целей** — спасброски/проверки целей бросаются автоматически (по `@Check` предмета и выбранным
   целям или существам в шаблоне), к каждой цели применяется эффект по её степени успеха
   (крит. успех / успех / провал / крит. провал).
3. **Реакции и триггеры** — «при попадании», «в начале/конце хода», «когда по тебе атакуют» и т.п.:
   подсказка игроку/ГМу о доступной реакции, по возможности — автоматическое действие; длительности эффектов.
4. **Зоны и регионы** — области из шаблонов (@Template / регионы pf2e v14) становятся живыми зонами:
   вход/выход/начало хода накладывает и снимает эффекты (дым → «Плохая видимость»), длительность и автоудаление.

## Не входит
- Автоприменение урона после атаки (ГМ применяет кнопками системы/Toolbelt, как сейчас).
- Видимость и прятки — за модулем пользователя `pf2e-vision` (можно только вызывать его API).
- Анимации — за Automated Animations.
- Дублирование `pf2e-automations` (Reyzor), Toolbelt, Workbench: модуль **дополняет** их, не трогает то,
  что они уже автоматизируют; при пересечении — уступает или имеет переключатель.

## Источник знаний «что делает предмет»
**Разметка + свои правила.** Сначала извлекать то, что уже есть в данных pf2e: `@Check[...]`
(тип, СЛ, `basic`, `options:inflicts:...`), `@Template`, `@Damage`, ссылки на эффекты/состояния, длительность,
черты предмета, Rule Elements. Чего нет в разметке (особенно «какое состояние при какой степени успеха») —
декларативные правила на предмет по slug (и/или флаг на конкретном предмете), редактируемые в UI.
Примечание: `inflicts:` в pf2e — только roll options, не сопоставление со степенями; оно годится как подсказка.

## Система и версии
- Foundry VTT **v14.366** (API v14: регионы с behaviors, ApplicationV2, `Level` у сцен, `canvas.regions.placeRegion`).
- PF2e **8.6.1**. Перевод названий/описаний — пользовательский модуль `pf2ru-translation` (Babele):
  имена предметов русские, поэтому опираться на `system.slug`/`flags.babele.originalName`, не на `name`.
- Рядом активны: pf2e-toolbelt (Template Helper может удалять шаблон после «Target»/«Cancel»), xdy-pf2e-workbench,
  pf2e-automations, pf2e-vision, Automated Animations, Dice So Nice, lib-wrapper, socketlib.

## Пользователи и мультиплеер
ГМ **и** игроки. Игрок запускает свои предметы; изменения на чужих токенах (состояния врагам, эффекты союзникам)
применяются через ГМа — `socketlib` (executeAsGM). Режим применения **настраивается** по видам автоматизации:
«применять сразу» / «предлагать кнопкой Применить (ГМу)» / «выключено».

## UI
- Работа автоматизации видна **в чате**: к сообщению предмета/броска добавляется блок с целями,
  их результатами испытаний и кнопками «Применить/Отменить»; подсказки реакций — тоже в чате.
- Свои правила — **вкладка «Автоматизация» в листе предмета**: что модуль распознал из разметки + форма правил
  (испытание и эффект по степеням, зона, триггер).
- Внешний вид — в стиле системы pf2e.
- Локализация: **ru + en** (`lang/ru.json`, `lang/en.json`).

## Зависимости
`lib-wrapper`, `socketlib` (оба установлены). Без сборщиков и npm-зависимостей.

## Покрытие первой очереди
Предметы, черты и способности **кампании TheGreatRoute**: 4 персонажа 2-го уровня (Варрис, Лиарэль, Муссария,
Шен-Ли) и противники мира (Львиные Клинки, гоблины, звери). Тестовый набор, одинаковый для всех прототипов:
1. **Дымовая шашка (малая)** (`smoke-ball-lesser`) и действие «Дымовая завеса» агентов — зона:
   существа в шаблоне получают «Плохую видимость», при выходе/исчезновении зоны — снимается; 1 минута.
2. **Испытание по степеням** — например «Дыхание огнём» гоблина-пиромана (`breathe-fire`, область + Реакция basic)
   или Frightful Presence: бросок за каждую цель/существо в области, эффект по степени.
3. **Эффект от предмета** — «Бравая брага (малая)» (`bravos-brew-lesser`): эффект по ссылке из описания на пьющего.
4. **Реакция** — «Ловкое уклонение» (Nimble Dodge, Лиарэль): подсказка при атаке по ней, +2 к КБ на атаку.

## Прототипы
**N = 3**, ось различий — **техническая архитектура** (один и тот же тестовый набор, три способа устроить движок).
Каждый прототип — отдельный устанавливаемый модуль `pf2e-autoflow-proto-<k>` в `prototypes/proto-<k>/`.
