## 2. Особые случаи

### 2.1. W42 Cackle: есть ли путь «Cackle → Sustain конкретного якоря»

Факты по коду:
- Cackle — hex (trait `hex`) без `duration.sustained`. `events.runFamiliar` на `spell-cast` запускает способность фамильяра (ровно один раз
  на сообщение), но автоякорь создаётся ТОЛЬКО если у сотворяемого hex есть `duration.sustained` — у Cackle его нет. Сотворение Cackle никакого якоря не «поддерживает».
- `sustain.isSustainMessage` берёт только действие Sustain: карточка заклинания (`origin.type === "spell"`) исключена. Cackle в чате = карточка заклинания, `count()` не вызывается.
- Единственный засчитывающий путь — кнопка «Поддержать» в шёпоте КОНКРЕТНОГО якоря (`sustain.run` → `count` → событие `spell-sustain` → запуск способности фамильяра)
  либо действие Sustain с листа/из чата: оно засчитывается ЕДИНСТВЕННОМУ якорю автора, при нескольких якорях — шёпот «выберите» без выбора (`sustain.pick`).
- Решение «сотворение Cackle и вложенное Поддержание = два запуска» выполнимо: cast Cackle (запуск 1) + кнопка «Поддержать» на нужном якоре (запуск 2). Cackle — тоже hex: в тот же ход другой hex не сотворить (W03), поэтому cast hex + Cackle в один ход не бывает.
- Поддержание в тот же раунд, когда hex сотворён, = `again` (события нет) — это Sustain по правилам не нужен, Cackle не даёт ничего нового.

Вердикт: прямого пути «Cackle → якорь X» нет. Минимум: **(а) S** — запись `onUse` на заклинание Cackle с заметкой
«Нажмите «Поддержать» в шёпоте нужного наговора; запуск способности фамильяра уже учтён при сотворении». Автоматический выбор якоря
(`choose from:"anchors"` + `count`) — **(в) L**, потребителей ≈3–5 (Cackle, Communal Sustain, Sustain an Effect…, ручной подсчёт по `items.json`; грубая регулярка даёт 75 с шумом «заклинание, само sustained») ≪ 30 → **долг**.
Живого сценария Cackle нет (запланирован в `plan-familiar.md` п.5) — добавить в `level1-familiar.js` (S).

### 2.2. W41 Phase Familiar: есть ли pre-damage путь

Факты:
- `damage-taken` (`events.mjs`) — пост-событие: приходит по `flags.pf2e.appliedDamage` ПОСЛЕ применения урона. До урона им не вмешаться.
- Реальные pre-damage точки в модуле: (1) `builtin/apply-hook.mjs` — единственная обёртка `Actor#applyDamage` с подписчиками «до» (Shield Block, `damage-link`); (2) `builtin/shield-block.mjs` — шёпот с кнопкой «Блок» на карточке урона держателю поднятого щита; (3) `hold.mjs` — удержание ATTACK-ROLL по цели с носителем `hold` (Sanctuary), не урона.
- Подписчика «реакция фамильяра ведьмы до урона» нет; `reactions.mjs` — окна-подсказки по исходу атаки (пересчёт бонусом КБ), не про сопротивление.
- Эффект `61Hl31nyzt63vvX9` живёт 1 раунд: если выдать его ДО нанесения урона, он защитит и от всего остального урона раунда (шире текста «против ЭТОГО урона»).

Вердикт: честный ручной сценарий. ГМ придерживает кнопку урона по фамильяру, ведьма сотворяет Phase Familiar (реакция, 1 фокус система списывает сама; реакцию не считает никто),
выбрав токен фамильяра цели; затем ГМ применяет урон. **(а) S**: копия модельной записи в `campaign`/`catalog` + заметка с этим порядком и пометкой, что снимать эффект после урона — вручную
(риск: копия теряет правки `model`-слоя). Pre-damage путь на подписке `apply-hook` — **(в) L**; число документов «реакция при уроне + resistance/immunity» по грубой регулярке 75 (верхняя оценка, шум не вычищен;
`apply-hook.subscribe` уже есть, но нужны шёпот «реакция» получателю, учёт реакции и откат) — **долг**, не блокирует закрытие L1.

### 2.3. Forbidding Ward: «уже как sustain»?

Нет. В `catalog.campaign.json` у `RA7VKcen3p56rVyZ` и `forbidding-ward` шаги без `sustain:true` (в `catalog.json` и других слоях записи нет, campaign последний). Заклинание — sustained, 1 минута;
эффект pf2e `ctMxYPGEpstvhW9C` — просто 1 минута. Без Поддержания эффект висит минуту и не снимается при пропуске. Это НЕ hex, автоякоря нет.
Решение: **(а) S** — `sustain:true` на шаге с эффектом (образцы: Clinging Ice, Information Overload; нужна проверка валидатора на шаге с `who`+`mark`) + живая проверка «пропуск Поддержания снимает эффект и метку».

## 6. Честный долг и причины

| Долг | Причина |
|---|---|
| W03 «один hex за ход» не блокируется | Нет подтверждённой pre-use точки; `spell-cast` — пост-событие, ложная блокировка хуже честного предупреждения |
| Pre-damage реакция Phase Familiar (подписчик `apply-hook` + шёпот + учёт реакции) | L, один потребитель в сборке, группа не подтверждена; ручной порядок работает |
| Авто-Поддержание «выбранного якоря» при Cackle | ≈3–5 документов ≪ 30; кнопка якоря даёт то же вручную |
| WF11 Ongoing Misery (способность Горечи у Фейи) | SOURCE-BLOCKED: сверка конфликта текста, внешняя сверка — только по подтверждению пользователя |
| «Ведьма видит цель» у Evil Eye, чтение auras, +4 к Charm, отношение Charm | Сюжетное/решение ГМа: правило из одних заметок, автоматизировать нечего |
| Detect Magic, Sigil, Pet Cache, Prestidigitation | Нет автоматизируемой части (ответы ГМа, свободное применение) |
| Cat Fall, Experienced Smuggler, Trap Finder (тайное обнаружение) | Падение и скрытые броски ГМа; автоматики нет ни в pf2e, ни в модуле |
