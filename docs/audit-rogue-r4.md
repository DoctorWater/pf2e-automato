## 1. Twin Feint (`feats-srd.Item.9XALeVNcmlIxf3tJ`)

Текст 8.6.1: требование — два ближних оружия, по одному в разной руке. Два Удара (по одному каждым) по одной цели; цель автоматически off-guard против второго; MAP применяется как обычно. Системных RE нет (`rules: []`) — механика целиком наша.

Реализация. Запись только в `rules/catalog.campaign.json:11` (по source UUID; в pa/model/onhit/cat её нет, поэтому действует она): `onUse` с пустым `apply` и макросом `builtin:twin-feint`. Обработчик `scripts/builtin/twin-feint.mjs` (`player: true` в `builtin/index.mjs:38`):
- ровно одна цель (`soleTarget`), иначе предупреждение;
- кандидаты `twoWeaponCandidates` (`strikes.mjs:13`): оружие ближнего боя, `carryType: held`, `handsHeld: 1`; два экземпляра одного предмета (`quantity >= 2`) считаются двумя оружиями; диалог `askStrikes` не даёт выбрать одно и то же оружие дважды;
- первый Удар с MAP из диалога, потом урон при попадании; затем временный эффект на атакующем (`af-twin-feint-second`, `EphemeralEffect` off-guard для `strike-attack-roll` и `strike-damage`), второй Удар с `min(2, map+1)`, `finally` удаляет эффект.

Соответствие тексту: да — одна цель, off-guard только для второго Удара и его урона независимо от исхода первого, эффект убирается даже при отмене/ошибке, native Sneak Attack получает `target:condition:off-guard` через тот же механизм, что и системные «off-guard для этой атаки».

Дефекты:
- P2. Нет тестов `run()`: `tests/builtin.test.mjs:50-53` проверяет только `soleTarget` и форму `secondStrikeEffect`; живой сценарий `tests/live/strikes.js` (строки 26–58) считает только остаток `af-twin-feint-second`. Не проверены: отмена второго броска, второй Удар мимо/крит, MAP при agile, Sneak Attack ровно один раз на втором Ударе.
- P2. Обработчик не тратит 2 действия сам (расход — через карточку предмета/трекер, как у остальных builtin); при вызове макросом без карточки действия не списываются. Проверить вживую, как вызывается из листа.
- P2. Требование «в разных руках» проверяется косвенно (`handsHeld: 1` у двух разных предметов). Оружие с признаком `free-hand`/щит с клинком (shield boss и т. п.) не распознаётся как «меч» — ограничение допустимо, оговорить в README.
- P2. Эффект на актёре создаётся без `origin`/`context`; он видим игроку 1–2 сообщения подряд, побочных событий `effect-created` от модуля нет (slug не в каталоге событий) — не дефект, но проверить, что `events.mjs` не реагирует.

## 2. Tumble Behind (`feats-srd.Item.YKqMuuC8j35NFh92`, rogue; swashbuckler `fU7d5P6WrfAirgip` вне объёма)

Текст: после успешного Tumble Through враг, через чьё место прошли, off-guard против следующей атаки плута до конца хода.

Система (`rules` предмета): `RollOption tumble-behind` (toggleable), `EphemeralEffect` off-guard для `strike-attack-roll`/`strike-damage` при включённом переключателе, `Note` на успех Tumble Through. Это ручной переключатель на ВСЕ Удары без привязки к врагу и сроку, поэтому автоматизация модуля не дублирует, а добавляет: метка врага + срок + расход.

Реализация. `rules/catalog.pa.json` — три идентичные записи: bySource `YKqMuuC8j35NFh92` (строка 416), `tumble-behind-rogue` (949), `tumble-behind` (1021); других слоёв нет, действует pa. События `onEvent` (все `side: self`):
1. `skill-check`, `action:tumble-through`, успех/крит → `apply` эффекта `Compendium.pf2e-automato.effects.Item.Vh5E1Qgp34sTKfVs` с `mark: "enemy"`.
2. `damage-roll` при `self:effect:off-guard-tumble-behind` → `removeEffect`.
3. `attack-roll` при том же эффекте и `outcome:failure|criticalFailure` → `removeEffect`.

Эффект `packs/_source/effects/effect-off-guard-tumble-behind_Vh5E1Qgp34sTKfVs.json`: `duration {value:0, unit:rounds, expiry:turn-end}`; `EphemeralEffect` off-guard (селекторы `attack-roll`, `damage`, предикат `self:mark:enemy-tumble-behind`) + `TokenMark enemy-tumble-behind`. Тот же шаблон, что у Mastermind/Scoundrel Feint.

Свежая правка `apply.mjs`: `hasEffect`/`applyEffect` с `mark` — повторный успех Tumble Through через того же врага сначала удаляет прежний эффект с той же меткой (`apply.mjs:405`) и ставит новый; успех по другому врагу создаёт второй эффект с другой меткой (не считается повтором, `apply.mjs:34-38,409`). Для Tumble Behind это безвредно (срок один и тот же — до конца хода), и поскольку damage-roll/промах удаляют эффект по UUID источника, оба эффекта снимаются вместе — это даже верно для «следующей атаки».

Соответствие: основной путь (успех Tumble Through → off-guard на следующий Удар по этому врагу → снятие после урона/промаха/конца хода) соответствует тексту. Тесты есть только на разбор `when` (`tests/pa-events.test.mjs:24-26,90,222-226`); исполнения связки нет.

Дефекты:
- P1. «Следующая атака» не расходуется атакой по другой цели или попаданием без урона. Снятие только на промах (`attack-roll` failure) и на `damage-roll`. Удар по другому врагу, попавший (или Удар без броска урона из-за отмены) оставляет эффект до конца хода — следующий Удар по отмеченному врагу снова off-guard, то есть получается вторая «следующая» атака. Правка: событие `attack-roll` без условия исхода, но с `when: ["self:effect:off-guard-tumble-behind"]` — тогда снимается любой бросок атаки (проверить вживую, что порядок «бросок атаки → снятие» не лишает off-guard урона, иначе Sneak Attack потеряется на попадании: EphemeralEffect для `damage` читается при броске урона, эффект к этому времени уже удалён). Безопасная альтернатива: оставить как есть и снимать только по `attack-roll` с `target`≠метка — требует проверки опций события. Решать после живого прогона; без него не менять.
- P1. Урон не от Удара тоже снимает эффект: `damage-roll` события `side: self` срабатывает и на урон заклинанием по спасброску, и на урон от Strike. Мелкий риск, но совпадает с замечанием в `docs/level1-rogue-tasks.md:27` («не путать атаку с damage-roll»). Правка — `when` с `item:...`/`damage:strike`-опцией или `attack-roll` как единственный триггер (см. выше).
- P2. `mark: enemy` требует ровно одного вражеского токена в `use.targets` (`apply.mjs:586-589`); при нуле или двух целях — `apply.needEnemy`, метка не ставится. Tumble Through сквозь двух врагов или без выбранной цели ничего не даст — игрок должен таргетить пересечённого врага до броска. Описать в подсказке.
- P2. Эффект и системный переключатель `tumble-behind` независимы: при включённом переключателе off-guard будет у всех Ударов по всем целям весь ход. Модуль его не гасит; достаточно упомянуть в README, правок не нужно.
- P2. `duration.value: 0 + turn-end` корректно для «до конца вашего хода» только если у эффекта есть `origin.actor` = плут; `applyEffect` пишет его из `ctx.originActor` — проверить вживую, что эффект не живёт до конца хода врага.
- P2. Нет живого сценария (в `tests/live` нет ни Tumble Behind, ни Tumble Through) — это единственное доказательство предположения об `attack-roll`/`damage` как допустимых селекторах EphemeralEffect (у системы это `strike-attack-roll`/`strike-damage`).

## 3. Nimble Dodge (`feats-srd.Item.dNH8OHEvx3vI9NBQ`)

Текст: реакция; триггер — существо целится в вас атакой, и вы видите атакующего; требование — вы не нагружены; +2 circumstance к КБ против вызвавшей атаки.

Система: `RollOption nimble-dodge` (toggleable) + `FlatModifier ac circumstance +2` при включённой опции. Ручной переключатель, не привязан к одной атаке; для реакции системы автоматизации нет — модуль нужен.

Реализация. `rules/catalog.json:75` (только там; в pa/model/onhit/cat/campaign slug не встречается): `onAttacked {trigger: attack-on-self, bonus {stat: ac, type: circumstance, value: 2}, cost: reaction, notify: [owner, gm]}`. Поток `scripts/reactions.mjs`:
- `onAttackMessage` (143–173) для `attack-roll`/`spell-attack-roll` с целью-актёром, DC — КБ; подсказка шёпотом владельцу и ГМу при любой атаке (результат не раскрывается), переброс обновляет ту же подсказку;
- `nimbleDodge(item)` — по slug либо source UUID (`reactions.mjs:122`); при `encumbered` подсказка не даётся (150) и повтор в `useReaction` отклоняется (195) — это сделано в §13.7;
- `useReaction`: проверка доступности реакции (`reactionAvailable`, флаг `reactionSpent`), повтор (`h.used`) не тратит вторую, `recalcWithBonus` пересчитывает степень по `dc + 2`, пишет `flags.gate.degree` в сообщение атаки, `spendReaction`.
Покрытие: `tests/reactions.runtime.test.mjs` (encumbered по source/по slug/для другого slug, повторная проверка, нормальное использование), `tests/reactions.test.mjs:52-57`, `tests/copy-guard.test.mjs:105-109`, `tests/rules.test.mjs:39,216`, живой `tests/live/suite.js:443-455` (подсказка одна при любом исходе, дубли способности).

Соответствие: +2 circumstance, реакция, нагруженность и «только против этой атаки» — есть. Не покрыто:

- P1. Видимость атакующего не проверяется (`grep visib/hidden/blinded` в `reactions.mjs` пусто). Атака от невидимого/скрытого существа, либо когда плут ослеплён, всё равно даёт подсказку и позволяет использовать реакцию. Правка: в `onAttackMessage` перед подсказкой (и повторно в `useReaction`) проверять, что актёр видит токен атакующего (например `token.canSee`-подобная проверка pf2e / `actor.hasCondition("blinded")` + состояния `hidden/undetected/invisible` атакующего относительно цели через `game.pf2e`-API видимости), и без подтверждения не предлагать (или предлагать с предупреждением). Тестов нет — писать вместе с правкой.
- P1. Тип бонуса не учитывается при пересчёте: `recalcWithBonus` прибавляет +2 к DC целиком, не сравнивая с уже действующим circumstance-бонусом к КБ (Raise a Shield +1/+2, бонус от укрытия не circumstance, но Raise a Shield — да; также системный переключатель `nimble-dodge`, уже вшитый в DC сообщения, даст двойной счёт). Правка: брать из `ctx.dc`/модификаторов цели существующий circumstance-бонус к КБ `m`, использовать `max(0, 2 − m)` (и учитывать circumstance-штрафы по обычным правилам: бонус и штраф разных знаков складываются). Источник данных — `ctx.dc.modifiers` / `actor.armorClass.modifiers` на момент сообщения. Тест на `recalcWithBonus` с вычитанием существующего бонуса — добавить.
- P2. Подсказка предлагается при атаках союзников и по умолчанию для «целится» любой атакой, включая ауры/оружие NPC без выбора токена (`ctx.target` должен быть) — приемлемо, текст допускает любое существо. Просто зафиксировать.
- P2. Копии NPC (`bestiary-ability-glossary-srd.Item.wCnsRCHvtZkZTmO0` и другие) совпадают по slug, поэтому ограничение «не нагружен» применяется и к ним. Допустимо; текст NPC-версии без этого условия — сверить при L1-R6, если NPC с Nimble Dodge попадут в сцены.
- P2. Русское название «Проворное уклонение» в каталоге/снимке (`nameRu`) расходится с названием в `plan.md:951` («Ловкое уклонение»). Только документация.

## 4. Surprise Attack (классовая особенность плута `classfeatures.Item.w6rMqmGzhUahdnA7`; архетипная черта `feats-srd.Item.io6eJGrw701WbmYe`, 4-й уровень)

Текст: в 1-м раунде боя, если вы бросаете Обман или Скрытность на инициативу, существа, ещё не действовавшие, off-guard против вас.

Система: у классовой особенности есть `EphemeralEffect` (`ruleKeys: ['EphemeralEffect']` в снимке; тело в LevelDB системы не прочитано — не искал), но привязка «ещё не ходившие» требует боевого состояния, которое RE сам не знает; полноту системной части проверить вживую (если система уже даёт off-guard, наш эффект даёт тот же результат и дублирование безвредно — условие один раз).

Реализация. В каталогах записи нет (проверено: `rules/catalog*.json` без `surprise-attack`); целиком builtin: `scripts/builtin/surprise-attack.mjs`, хуки `builtin/index.mjs:54` (сообщения), `:80,87` (конец боя/смена хода), `:89` (подметание). Логика: `classify` — инициатива с опциями `check:statistic:base:deception|stealth`; `findFeat(actor, "surprise-attack")` по slug/оригинальному имени, любого не-effect типа (подходят и особенность, и архетипная черта); бой — тот, где актёр участвует и `round <= 1`; `pending` — сигнатуры участников, ещё не ходивших (до старта боя — все, кроме плута; после старта — после текущего хода); эффект на плуте с `EphemeralEffect` off-guard (`strike-attack-roll`, `spell-attack-roll`, `strike-damage`, `attack-spell-damage`, предикат `target:signature:<sig>` на каждое существо); метка существа снимается, когда начинается его ход; весь эффект — когда меток нет, со 2-го раунда и при конце боя; повторный бросок другой характеристикой снимает эффект. Всё делает активный ГМ.

Соответствие тексту: да, включая «только не ходившие», 1-й раунд, Обман/Скрытность, снятие при конце боя. Тесты: `tests/surprise-dread.test.mjs` (classify, rulesFor/sigsOf/dropSig, pending) и живой `tests/live/suite.js:340-362` (эффект после инициативы, две метки, off-guard по не ходившему до и после старта, снятие метки по ходу, снятие эффекта). Не покрыто тестами: `onMessage`/`onTurn` целиком без Foundry; Sneak Attack ровно один раз против такого off-guard.

Дефекты:
- P2. Существо, вошедшее в бой после броска плута (в 1-м раунде), не получает метку; существо, чей ход пропущен/отложен (Delay) или действовавшее реакцией до своего хода, считается «не ходившим» до начала своего хода. По тексту «haven't acted» это может отличаться — крайние случаи, оставить как есть, записать в README.
- P2. Метки получают и союзники плута (их off-guard плуту безвреден, `EphemeralEffect` действует только на Удары плута по ним). Не дефект, но в `target:signature` попадают токены NPC без связи — проверить при токенах-двойниках, что `signature` различает копии (живой тест с двумя одинаковыми NPC).
- P2. Предположение, что опция `target:condition:off-guard` от EphemeralEffect включает native Sneak Attack, подтверждено только живым сценарием на попадании (`suite.js:355-358` смотрит `context.options`), а не наличием `precision`-кубов в уроне; проверить в L1-R4 «Sneak Attack ровно один раз».
- P2. Системный `EphemeralEffect` классовой особенности (см. выше) не проверен на дублирование; при двойном off-guard Sneak Attack всё равно один.

## Явных однозаписных правок каталога нет

Все найденные дефекты требуют изменений кода (`reactions.mjs`) либо живой проверки порядка событий. Единственный «каталожный» кандидат — Tumble Behind, P1: заменить условие снятия на любой `attack-roll`, но без живого прогона порядка «attack-roll → damage» он может отключить off-guard на урон, поэтому JSON здесь не приводится как гарантированная правка. Черновик (применять только после живой проверки), во всех трёх идентичных записях `catalog.pa.json` (416, 949, 1021) заменить третий элемент `onEvent`:

```json
{"on":"attack-roll","side":"self","when":["self:effect:off-guard-tumble-behind",{"or":["outcome:failure","outcome:criticalFailure"]}],"apply":[{"to":"self","removeEffect":{"uuid":"Compendium.pf2e-automato.effects.Item.Vh5E1Qgp34sTKfVs"}}]}
```
на вариант с расширенным `or`, дополнительно включающим `"outcome:success","outcome:criticalSuccess"` (и убрать событие `damage-roll`), оставив снятие по концу хода как страховку. Записи pa генерируются (`tools/pa-effects*`, `tools/pa-events.mjs`) — правку вносить в генератор, а не вручную в каталог, иначе пересборка её затрёт.
