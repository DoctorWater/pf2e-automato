## Установка (разработка)

Код лежит в `D:/ClaudeFun/pf2e-automato/`; в Data подключается junction-ом (PowerShell, без прав администратора):

```powershell
New-Item -ItemType Junction -Path "$env:LOCALAPPDATA\FoundryVTT\Data\modules\pf2e-automato" -Target "D:\ClaudeFun\pf2e-automato"
```

Затем в мире включить `socketlib` и `PF2e AuTOMATO`. Модуль работает только пока в сети есть **активный ГМ**:
все изменения мира делает его клиент, остальные шлют запросы через сокет.

### Паки модуля и релиз

Свои паки — `packs/effects` (эффекты) и `packs/equipment` (временная броня и щиты, `scripts/builtin/gear.mjs`), оба LevelDB. В git лежат только источники `packs/_source/<пак>/*.json`, собранная база в `.gitignore`: Foundry переписывает её при открытии мира, а папка модуля — junction на репозиторий.
После клонирования и после правки источников: `node tools/build-packs.mjs` (нужен `classic-level` из установки Foundry, `FOUNDRY_NODE_MODULES`; без изменений источников пересборка пропускается, при открытом мире — предупреждение). Входит в `node tools/run.mjs`.
Релиз: поднять `version` и `download` в `module.json` (ссылка на тег `vX.Y.Z`), прогнать юнит-тесты локально, запушить тег `vX.Y.Z`. GitHub Actions (`.github/workflows/release.yml`) соберёт паки (`classic-level` из npm), упакует `pf2e-automato.zip` (только `scripts`, `templates`, `styles`, `lang`, `rules/*.json`, `packs/effects`, `packs/equipment`, `module.json`, `LICENSE`, `NOTICE`, `README.md`) и выложит его вместе с `module.json` в релиз. Манифест для установки: `https://github.com/StompingRhino/pf2e-automato/releases/latest/download/module.json`.

## Тесты

Чистые функции (`rules`, `util`, `compat`, `apply`, `use`, `chat`, `saves` на заглушках глобалов) и сверка i18n — `node --test`, без npm:

```
node --test
node --check scripts/*.mjs tests/af-harness.js
```

В Node 24 вариант `node --test tests/` (с каталогом) не работает — каталог трактуется как файл; используйте `node --test` или `node --test tests/*.test.mjs`.
`tests/i18n.test.mjs` сверяет наборы ключей `lang/ru` и `lang/en` и наличие всех используемых в коде/шаблонах ключей.

## Живой прогон (харнесс)

`tests/af-harness.js` — выражение-функция для консоли ГМа. Создаёт временную сцену, монстров из Monster Core и свои предметы; **персонажей игроков и их
владение не трогает** (в отчёте `playersUntouched`), уборка — только свои документы и сообщения, созданные этим клиентом за прогон.

```js
const f = <вставить содержимое af-harness.js>; const r = await f(); console.table(r.rows); r.summary
```

Порядок первого прогона: мир с активным ГМом и включённым модулем → прогон → смотреть `r.summary` (`failed`, `errors`,
`playersUntouched: true`), затем `r.cleanup` (все счётчики удалений, `worldCatalogClean: true`) и строки `rows` с `pass: false`. Сценарии: 0 вкладка,
1 зона (шашка, пути A/B), 2 конус и испытание, 3 расходник с областью, 4 переставленный регион, 5 истечение зоны, 6 yield, 7 Frightful Presence,
8 макросы, 9 low-кнопка, 10 дозапуск вне давности, 11 реакция, 12 права сокета, 13 low-зона.

## Ручной чек-лист (то, что харнесс не покрывает; §9-16)

- [ ] **Клиент игрока**: игрок ставит область из карточки заклинания (регион создаётся его клиентом, ГМ исполняет); блок виден игроку; кнопка «Бросить»
  только у своей цели; **PC-бросок** игрока принимается (`src: "saving-throw"`/маркер); чужие кнопки скрыты; попытка вызвать ГМ-обработчик из консоли
  игрока возвращает `forbidden`.
- [ ] **Переброс (hero point)** до и после применения: до — результат заменяется; после — `changedAfterApply`, шёпот ГМу, повторное «Применить» корректно.
- [ ] **Два ГМа**: мутации делает только активный (`game.users.activeGM`); у второго ГМа кнопки работают через сокет и не дублируют применение; смена
  активного ГМа (выход первого) → `reconcileZones` и `resumePending` у нового.
- [ ] **Отсутствие ГМа**: использование предмета при выключенном ГМе → после входа ГМа свежие (< `resumeMinutes`) сообщения дозапускаются,
  старые показывают «Дозапустить»; у игрока при нажатии кнопки предупреждение «нет ГМа».
- [ ] **Перезагрузка страницы (F5)** посреди зоны: блок в чате появился сразу после загрузки; зона продолжает действовать, состояния не плодятся.
- [ ] **Пауза игры**: игрок не ставит область (поведение ядра); ГМ — ставит.
- [ ] **Toolbelt Target Helper включён**: испытания ведёт он, мы не бросаем (в блоке пометка); на регионах-зонах помощник шаблонов не вмешивается.
- [ ] **`pf2e-auto-action-tracker`** + карточка реакции: «Использовать реакцию» один раз списывает реакцию, повторное нажатие/переброс не дублирует.
- [ ] Бой: `reactionSpent` ставится в бою и сбрасывается на `startTurn`; раунды зоны уменьшаются по `updateCombat`.
- [ ] Ввод СЛ кнопкой «Ввести СЛ» запускает испытание сразу (auto).

## Файлы

`scripts/` — код (`main.mjs` точка входа); `rules/` — `catalog.json`, `catalog.pa.json`, `catalog.model.json`, `catalog.onhit.json`, `labels.json`; `lang/{ru,en}/*.json` — несколько файлов на один
`lang`, Foundry их склеивает (`client/helpers/localization.mjs:331–339`); `templates/` — блок чата и вкладка листа;
`tests/` — `node --test` и живой харнесс.
