## Поля правил сверх схемы v1 (plan.md §1)

| Где | Поле | Смысл |
|---|---|---|
| шаг apply | `persistent: {formula, damageType, dc?}` | продолжительный урон вместо condition/effect/note/visibility: состояние `persistent-damage` с `system.persistent` (как `applyDamage` pf2e), `dc` по умолчанию 15; идемпотентно по `meta.key`, откат удаляет; иммунитеты/сопротивления учитывает pf2e при броске |
| шаг apply | `who: "ally" \| "enemy"` | применять только союзникам/врагам автора (по disposition; в pf2e она выводится из союза актёра) |
| шаг apply | `mark: "enemy"` | метка `TokenMark` эффекта — на единственного врага среди целей (Запрещающая защита) |
| шаг apply | `unlessEffect: uuid` | пропустить, если у получателя уже есть этот эффект (иммунитет Наставления) |
| шаг apply | `choice: value` | заранее выбранный вариант ChoiceSet эффекта (Оплетающая лоза: success / critical-success) |
| `onUse.challenge` / `onUse.check` | `immunity: {slug, label?, uuid?, duration?, degrees?}` | «после испытания (проверки) цель невосприимчива к этой способности этого автора»: эффект на цель при степенях `degrees` (нет поля — при любой; срок — `duration` или эффект `uuid`); цель с ним не бросает и ничего не получает. Ауры: иммунитет «к Пугающему присутствию этого существа». `scope: "slug"` — иммунитет к способности **любого** автора («ко всем существам вида», напр. «ко всем вонючим аурам йзобу»); без него — только к этому автору |
| шаг apply | `removeCondition: {slug}` | снять состояние целиком (Встать, Неваляшка, Стабилизация); нет состояния — шаг пропущен; откат возвращает со старым значением. Форма: вид шага «снять состояние» |
| шаг apply | `effect.badge: "increment"` | эффект уже есть у получателя — значок (counter) растёт на 1 (или на `by`, 1..10) вместо второй копии, нет — создаётся (со значком из источника или `start`, 1..10; Кража тени: `start:2, by:2`; другое число при крит. попадании шагом не выразить — такие копии low); не выше максимума значка (Кража тени, Благословение). Форма: галка «Повтор увеличивает значок» |
| шаг apply (любой) | `rank: {min?, max?}` | шаг только при круге сотворения в границах (у не-заклинания — уровень предмета): «Ускорение с 7-го круга», «Видение невидимого до 4-го». Форма: поля «круг от / до» |
| шаг apply (любой) | `when: [предикат pf2e]` | условие шага (0.5g2): шаг идёт, только если предикат верен на наборе roll options — опции броска и origin сообщения, `outcome:*`, `target:*` цели (первая цель, если шаг «себе»), опции автора (`feat:*`, `feature:*`, `self:*`; `spellcasting:*` и `spell:*` pf2e не выдаёт) и предмета (`item:*`). Как у pf2e-automations: строки, `{and|or|nor|nand|xor|not|if…}`, сравнения `{gte|lte|gt|lt|eq: ["self:level", 5]}`. Проверяет `game.pf2e.Predicate.test` (в тестах — `scripts/predicate.mjs`). `rank` остаётся отдельным шагом: круг сотворения — не опция предмета (он поднимается при повышении). Форма: поле «когда» — roll options через запятую (все сразу) либо JSON; битая строка отвергается валидатором. «Мастерская»: поле «Когда» у шага, плашка «если …» |
| шаг apply | `removeEffect: {slug \| uuid, of?: "origin"}` | снять эффект получателя (по slug или источнику); `of:"origin"` — только созданный автором шага (в форме — галочка «созданный мной»); нет эффекта — пропуск; откат создаёт снятое заново из сохранённых данных (срок начинается заново — `start` не восстанавливается). Не трогает выданное другим предметом (`grantedBy`) и эффекты ауры; если pf2e отменил удаление (`onDelete: restrict`), эффект не считается снятым. `slug` — как у предмета (`effect-rage`) или как в roll options (`rage`) |
| шаг apply | `extendEffect: {slug | cast: true, rounds}` | `cast: true` вместо `slug` — продлить эффект, выданный **этим же сотворением** (по `meta.message`; перед продлением ждём `execUse` того же сообщения, чтобы гонки с постановкой эффекта не было; эффекта нет — предупреждение ГМу, повтор — кнопка «Применить», идемпотентно по ключу шага); форма: «*» вместо slug. Продлить действующий эффект получателя на раунды (срок в минутах/часах переводится в раунды; бессрочный пропускается). Повтор того же шага не продлевает дважды (ключ шага в флаге эффекта), откат возвращает прежний срок. Раунды в форме — поле «значение» |
| шаг apply | `effect.badge: "decrement"` (или `-1`) | рядом с `"increment"`: значок существующего эффекта −1, на минимуме эффект снимается (откат возвращает); нет эффекта — шаг пропущен, копия не создаётся. Форма: галочка «значок −1» |
| шаг apply | `refundFocus: true` | вернуть владельцу очки фокуса, потраченные на это заклинание (`system.cast.focusPoints` самого предмета, не выше максимума; только `to:"self"`). Откат — дельтой (не ниже 0). Форма: вид «вернуть очко фокуса» |
| шаг apply | `rollOption: {domain, option, value?: false}` | включить (с `value:false` — выключить) переключаемую опцию `RollOption` получателя через `toggleRollOption` (Mighty Rage, Quick-Tempered); нет такого правила у актёра — пропуск с предупреждением; откат возвращает прежнее состояние |
| шаг apply | `to: "party" \| "allies"`, `range` | получатели-группы: `party` — участники групп (party) автора, `allies` — союзники автора в радиусе `range` футов (обязателен, от 5) от его токена без преграды стен (Живые щиты, Сеятель). Шаг идёт один раз, не на каждую цель; ключ — по получателю. Видимость группе нельзя |
| шаг apply | `choose: {from: "allies" \| "enemies" \| "options", options?, prompt?, range?, of?: "target"}` | (0.5g4, `prompt`) выбор игрока-автора (окно у него, нет игрока онлайн — у ведущего; тайм-аут 2 мин: закрыто — шаги с выбором пропущены). `to` у шага всегда `self`. `allies`/`enemies` — одно существо сцены (`range` — футы от токена автора, `of:"target"` — от цели броска/карточки); дальше шаги `to: "chosen"` (только после такого `choose` в том же списке). `options: [{value, label?, when?}]` (код латиницей, `label` — иначе `choose.opt.<value>` из lang; `when` — вариант виден, только если у автора верен предикат: черта даёт вариант); выбранное — опция `choice:<value>` для `when` следующих шагов. Единственный вариант выбирается без окна. Выбор запоминается в `ops` (`chose`): повтор не спрашивает. В записи `onEvent` выбор общий для всех шагов записи. Форма: вид «выбор» — JSON в поле текста |
| шаг apply | `to: "chosen"` | получатель — существо, выбранное предыдущим шагом `choose` (Охотник на чудовищ: союзник получает ту же метку; Clue In) |
| шаг apply | `damage: {formula, damageType, basic?}` | (0.5g4) урон или лечение (`damageType: "healing"`) по формуле (кубики/числа, `@actor.level`, `@item.rank`, `floor/ceil/min/max` в скобках): бросок `DamageRoll` и применение через pf2e (`applyDamage`: сопротивления, слабости, щит, временные ОЗ) без карточки с кнопками. `basic: true` — «обычное» испытание: ×2 / ×1 / ×½ / ×0 по степени (`roll.alter`); лечение применяется без сопротивлений. Откат не предусмотрен — pf2e пишет в чат карточку урона с кнопкой отмены; повтор шага (тот же `meta.key`) урон не повторяет. Форма: вид «урон / лечение» (`basic` едет в `keep`) |
| шаг apply | `move: {mode: "push"|"pull"|"choose", distance}` | принудительное перемещение цели (только `to:"target"`): `push` — по прямой от токена автора, `pull` — к нему и вплотную; `choose` — на `distance` вверх/вниз/влево/вправо по карте, сторону выбирает автор окном при применении (игрок-владелец или ГМ; окно закрыто — цель стоит, шаг отработан; `from` запрещён); `distance` — футы, кратно 5, «up to» = максимум. Шаг исполняет активный ГМ без кнопок: ровно по сетке сцены (5 фт; диагонали и гексы считает `grid.measurePath`), остановка ПЕРЕД стеной (`testCollision`) или занятой клеткой; нулевой путь — пропуск с уведомлением. Дистанция по степени — отдельным шагом в каждой степени. Размер цели — `when`: `{"lte":["target:size",3]}`. Журнал `moved {from,to,id}`; повтор после переброса степени не двигает (ключ без степени); откат (`undoOps`) возвращает позицию, если токен ещё на месте (`revertRecordedMovement` либо `update` с `isUndo`, реакции не срабатывают). Цели идут от дальних к ближним (толчок) или наоборот (притяжение): при «Применить всем», при шагах `onUse.apply` по области и в режиме auto — там применение откладывается, пока не придут спасброски ВСЕХ целей карточки (кто не бросил — кнопка «Применить всем»; шаги без `move` в той же карточке тоже ждут). По умолчанию толкает от токена автора; `from: "point"` — от центра области этого использования (круг-взрыв — центр круга, эманация — центр рамки региона; конус/линия/нет региона — откат к токену автора с уведомлением `moveSkip.noPoint`); притяжение к точке не заходит дальше клетки центра. Правило областей: при `targets:"area"` допустим только `from:"point"`, при остальных `targets` `from:"point"` запрещён, в триггерах зоны и `onEvent` `move` запрещён (`move.bad`). Форма: поле «откуда». Цель без токена, отказ `TokenDocument#move` или нулевой сдвиг — пропуск с уведомлением. Не умеет: телепорт, «выберите клетку», падение/ловушки. Форма: вид «толчок / притяжение» |
| правило | `activate: [{id?, label?, spell?, rank?, dc?, duration?, immunity?, attack?, per?, requires?, note?, onUse?, choices?}]` | (активации; в интерфейсе «Активации»; поля `onUse`/`choices`, `rank.half`, `dc.against` — см. «Ключ `activate`» ниже, их рантайм — отдельным шагом) активация снаряжения «You cast X»: на карточке предмета кнопка «Сотворить: …» на каждую запись; сотворяет **нажавший** (владелец актёра или ведущий; через ведущего не идёт), дальше работает правило самого заклинания (испытание, состояния по степеням, зона). `spell` — UUID; `rank` — круг (у кантрипа нет — половина уровня предмета вверх); `dc` — число, `{level: "high"}` (NPC: таблица Spell DC and Spell Attack, колонка High, уровни −1…24; атака = СЛ − 8) или нет (СЛ лучшей записи заклинателя владельца; нет записи — СЛ по уровню предмета, `calculateDC`, с пометкой на кнопке); `attack` — бонус атаки заклинанием (по умолчанию СЛ − 10); `per: {value, unit, uses?}` — «uses раз за value rounds/minutes/hours/days», **мягко** (исчерпано — окно «всё равно?», не запрет; «раз в день» обнуляет только отдых `pf2e.restForTheNight`, «раз в N дней» — время мира (отдых его не сбрасывает), счётчик — флаг предмета `uses`, удаление карточки возвращает использование, очистка лога — нет; у способности со своим `system.frequency` и у «в день» NPC счётчик не ведётся, только показывается); `requires` — `invested` / `equipped` / `held` / `none` (нет поля: настраиваемый предмет — `invested`, иначе `equipped`; не выполнено — кнопка отключена, `none` — не проверять; у способностей NPC проверки нет). Запись заклинателя для эфемерного заклинания — ленивая обёртка `ActorSpellcasting#get` по id `af-cast-<предмет>-<активация>` (в коллекции `spellcasting` её нет). В опциях сообщения — `origin:item:cast-by-activation`. Правило из разметки (low) — кнопки только ведущему; у расходников (палочки, свитки) из разметки активации не выводятся. `id` по умолчанию — slug метки или хвоста UUID заклинания. Из разметки: блоки «Activate … Effect: You cast @UUID[spells-srd]» с одной ссылкой (`deriveCast`; `@Check` блока уходит в `dc` записи). Частота — только из блока Frequency (у кантрипов спеллхарта её нет). `counteract` — бонус противодействия (по умолчанию как у атаки). `duration: {value, unit, expiry?}` (только при `spell`) — свой срок записи: «effects of X for N», когда он не совпадает со сроком заклинания; `immunity` (то же, что `challenge.immunity`, только при `spell`) — иммунитет после спасброска самого заклинания (Dominate: 24 часа). Оба поля кладутся в метку сообщения `activation` и в `onPreCreateMessage` накладываются на копию правила заклинания (`withActivation`): срок получают шаги с состоянием/эффектом в `onUse.apply` и `byDegree`, кроме `policy: "reduce"` и шагов с `repeat`; `immunity` заменяет иммунитет испытания, нет испытания — ничего не делает. Правило заклинания из каталога не меняется. Правила заклинаний из `rules/catalog.pa.json` (Heroism, See Invisibility, Calm) при активном pf2e-automations и `yieldToAutomations` уступаются ему целиком — наложение срока тогда не сработает. СЛ: из текста, иначе по уровню предмета; у кантрипа спеллхарта — большая из СЛ предмета и лучшей записи владельца; заклинание с испытанием/атакой без СЛ в тексте — `low`. В каталог (`tools/cast-batch.mjs`) идут только предметы, где все активации — «cast X» с одной ссылкой; прочее — долг. Прикреплённые спеллхарты (`subitems`) работают. Бонус после активации спеллхарта («+1d4 урона до конца хода») — отдельный примитив, не сделан |
| шаг apply | `condition.policy: "reduce"` | (0.5g4) снизить действующее значение состояния на `value` (по умолчанию 1), на нуле состояние снимается (Аура отваги); нет состояния, оно без значения или выдано другим предметом — пропуск; откат возвращает значение. Без `duration` |
| шаг apply | `repeat: {on, end?, statistic?, dc?, traits?, options?}` | (triggered-save T1) повторный спасбросок цели на границе её хода: `on` — `turn-start` / `turn-end`, `end` — степени, снимающие носитель (по умолчанию успех и крит. успех). Носитель — свой документ с `meta.repeat` (состояние идёт в обёртке без срока, `unlimited`); если у цели уже есть такое состояние/эффект — отказ, чужое не трогаем. Внутри `challenge.byDegree` навык, СЛ, черты берутся из испытания (СЛ снимком числа: `use.dc` / результат цели / расчёт), вне него `statistic` и `dc` обязательны. Срабатывает у активного ГМа в бою (`pf2e.startTurn/endTurn`, раз за ход), мёртвым не бросается; NPC бросают сами, PC — кнопкой в карточке; автор мог исчезнуть — повтор идёт по снимку. Только у `to: "target"`, не вместе с `escape` |
| `onUse.zone` | `follow?`, `enterBy?`, `onCarrierGone?`, `triggers: [{on, per?, challenge?, apply?}]` | (triggered-save T2) облако, стена, эманация: существо входит в область (`enter`), начинает (`turn-start`) или заканчивает (`turn-end`) в ней ход — получает карточку испытания (как `onEvent.challenge`, против СЛ автора; иммунитет, `who`, `when` — те же) и/или шаги `apply` (только `to: "target"`). Зона может состоять из одних триггеров (без состояния/эффекта). `per: "round"` / `"turn"` — не чаще раза за раунд / за ход боя на существо; ключ общий для всех записей зоны с таким `per` (вход и конец хода делят один бросок); вне боя `per` не ограничивает — каждое событие даёт карточку. Вход считается только при реальном движении (создание/включение региона поверх токена — не вход: стартовое испытание остаётся в `onUse.challenge`); пропущенные ходы и скрытая/истёкшая зона не стреляют; мёртвые не бросают; автор эманации триггеров не получает (`excludeSelf`). **Эманация заклинателя** (фигура `emanation` от токена сцены; pf2e так создаёт эманации заклинаний) следует за его токеном средствами ядра: привязка `region.attachment.token` ставится при запуске зоны, ядро двигает фигуру вместе с ходом, держит членство заклинателя (его состояния зоны не мигают) и удаляет регион при удалении токена (карточка зоны — `closed`). Скрытый ГМом токен прячет и область — триггеры молчат. Наезд области на стоящую жертву — вход (один бросок за ход заклинателя; откат хода и правка — не вход). `follow: false` — область стоит на месте; `enterBy: "path"` — вход получают и задетые по пути заклинателя (по умолчанию `"end"` — по итоговому положению); `onCarrierGone: "stay"` — при удалении токена область остаётся до конца срока (по умолчанию `"close"`); работает при удалении токена ГМом (удаление игроком закрывает область). Удаляя такой токен, ГМ видит подтверждение ядра «привязанные регионы будут удалены»; при `stay` текст неточен. Триггеры и СЛ копируются в поведение зоны при создании — карточка использования и автор могут исчезнуть. Форма: зона → «триггеры» |
| шаг apply | `effect: {mods: [...]}` + обязательный `duration: {value, unit, expiry?, of?}` | (пачка 1) inline-эффект без готового эффекта pf2e: «−2 статусный штраф к Воле на 1 раунд», «−10 фт к Скоростям», слабость 5 к огню, запрет реакций. Кубики (1–4, по одному ключу): `{bonus:{target,type,value}}` (target: `ac`, `saving-throw`, `fortitude`/`reflex`/`will`, `attack-roll`, `damage`, `perception`, `skill-check` или навык; value со знаком), `{speed:{type,value}}` (ко всем Скоростям, `all-speeds`), `{resist:{dmg,value,except?}}`, `{weak:{dmg,value}}`, `{forbid:"reactions"}`. Модуль строит Rule Elements сам (FlatModifier/Resistance/Weakness/RollOption), сырых RE из данных нет. Срок только конечный; `of:"target"` — по ходу получателя. С `mods` не сочетаются `badge`/`replace`/`mark`/`choice`/`unlessEffect`; `repeat` допустим. Имя эффекта «Эффект: <предмет>», slug `af-<slug предмета>` (`removeEffect`/`extendEffect` находят его). `forbid` ставит опцию `af:no-reactions`: реакции модуля (подсказки `onAttacked`, Блок щитом, Внеочередная атака) не предлагаются, pf2e сам реакции не запрещает |
| шаг apply | `duration: {value, unit, expiry?}` у шага `effect` | (0.5g4) срок созданного эффекта заменяет срок источника (См. невидимое с 5-го круга: 8 часов); `value` — число или кубик `"1d4"` (бросается при создании; у состояния кубик тоже допустим); `expiry` без указания — из эффекта; `of` у эффекта не бывает. Форма: поля срока у строки «эффект» |
| `onUse.check` | без `vs` | бросок только за степень, СЛ задаёт система (Прыжок в высоту: крит. провал — состояние «Распластанность» на себя; Лазание). Нужны `roll: "system"`, `targets: "self"`, шаги `to: "self"`; «цель» — токен автора. Форма: «Против: без цели (бросок системы)» |
| `onUse.check` | `oneRoll: true` | один бросок автора на все цели карточки (нужен `vs`, без `roll:"system"`): pf2e бросает против СЛ первой цели, степень каждой цели модуль считает от того же итога и СЛ этой цели (`degreeFromTotal`, натуральные 1/20 учитываются), в результате пишется СЛ цели. Иммунные цели без результата пропускаются; состав целей фиксируется при первом броске (позже испугавшаяся цель не добавляется). Ограничение: степени неглавных целей считаются по статической СЛ — `AdjustDegreeOfSuccess` автора и контекстные модификаторы СЛ цели учитываются только у цели, против которой бросал pf2e. Работает и когда игрок кликнул `@Check` с карточки (без выбранной цели или с целью вне списка): результат распределяется по всем целям; переброс пересчитывает всех. Имя не `once` — оно занято в `onEvent.once` («раз за раунд»). Пример — «Не надо пугаться» (No Cause for Alarm) в `rules/catalog.json` |
| `onUse.check` | `when: <предикат>` | условие на цель (как `challenge.when`: `target:condition:frightened`): не выполнено — цель не бросает и в карточке не показана. Условие вычисляется **в момент броска и запоминается**: цель с записанным результатом остаётся в карточке, при откате и при кнопке ГМа, даже если состояние уже снято (испуг снижен или кончился) — иммунитет всё равно ставится. То же для `challenge.when` |
| `onUse.check` | `roll: "system"` | модуль сам не бросает — исход из броска pf2e (атака заклинанием); снимок на карточке не создаётся |
| правило | `onEvent: [{on, side, when?, once?, afterUse?, aura?, range?, per?, apply?, challenge?}]` | (0.5g3) правило на предмете актёра срабатывает по событию, см. ниже «События» |
| каталог | `byName` | правило способности NPC без slug и источника — по имени предмета в мире |
| ограждение | `guardCopy` (`scripts/rules.mjs`) | копия способности NPC/ловушки (актёр `npc`/`hazard`) с правилом каталога по `source`/slug пропускает его, если текст копии не называет состояние правила («потеря») или называет другое состояние («другое»: Evil Eye у Kepgeda — frightened против Sickened источника). Карта «подразумевает» (grabbed → off-guard…), `flat-footed` = `off-guard`; эффекты, спасброски, числа и прозу не сравнивает. Вместо правила — вывод из разметки (`low`, исполняет только кнопка ГМа) с `diverged: {kind, states}`; в бейдже, на вкладке и в Мастерской — пометка «Текст копии отличается от правила каталога». Не огораживаются флаг предмета, мировой каталог, предметы персонажей, `origin` без найденного предмета (пути `use.mjs` передают `origin.uuid`, предмет подтягивается и огораживается так же), перевод без `flags.babele.originalPayload`, нераскрытый `@Localize`. Отчёт: `node tools/copy-guard-report.mjs [--check]` (отключаемые копии, правила каталога с состоянием, которого нет в тексте источника; `--check` входит в `tools/run.mjs`) |

Также: уровень эффекта = круг сотворения заклинания; цель с иммунитетом к чертам источника (напр. mental) состояний не получает;
встроенные обработчики с `player: true` бросают у автора-игрока, результат проверяется ГМом в `finish`.

## События (`onEvent`)

Правило на фите, эффекте, снаряжении или способности NPC может сработать **от события**, а не от использования предмета. Пример — «Боевое выступление»: Удар с уроном продлевает композицию на 1 раунд, но каждую — один раз:

```json
{"v":1,"onEvent":[{"on":"damage-roll","side":"self","when":["action:strike"],"once":true,
  "apply":[{"to":"self","extendEffect":{"slug":"aura-inspire-courage","rounds":1}}]}]}
```

- `on`: `attack-roll`, `skill-check`, `saving-throw`, `damage-roll`, `damage-taken`, `spell-cast`, `turn-start`, `turn-end`, `enter` (только `side:"near"`), `effect-created`, `effect-deleted`.
- `side`: `self` — владелец бросает / получает урон / ходит; `target` — владельца атакуют (`onAttacked` — его частный случай); `origin` — владелец — автор эффекта на том, кто ходит или бросает; `near` — **аура владельца** (см. ниже).
- `when` — предикат pf2e по тем же roll options, что видит pf2e-automations (`outcome:*`, `target:*`, `self:effect:*`, `domain:*`, `item:attack-effect:<slug>` у Удара…). `to:"self"` в `apply` — владелец, `to:"target"` — другой участник события.
- `challenge` — другой участник бросает испытание против СЛ владельца: `{"on":"damage-roll","when":["stunning-blows"],"challenge":{"statistic":"fortitude","dc":{"against":"class"},"byDegree":{"failure":[{"condition":{"slug":"stunned"}}]}}}`.
- **Аура владельца** (triggered-save T3): `side:"near"` с `on`: `turn-start` / `turn-end` / `enter` — «другой» участник (тот, чей ход, или тот, кто вошёл) оказался в ауре **владельца-носителя** (NPC — несвязанный токен, PC — любой токен). Зона — ровно одно из: `aura` (slug Aura RE pf2e, радиус берётся у `token.auras`; нет такой ауры у токена — запись молчит) или `range` (футы от носителя; расстояние по правилу pf2e между клетками токенов, с высотой — 3D, как measureDistanceCuboid pf2e: перекрытие по высоте расстояния не добавляет). `per: "round"|"turn"` — не чаще раза за раунд / за ход боя на пару носитель–жертва: ключ общий у записей с одной аурой и одним `per`, поэтому «входит или заканчивает ход» — две записи (`enter` и `turn-end`) с одним `per` дают одну карточку; разные ауры окон не делят; вне боя `per` не ограничивает — каждое событие даёт карточку. `when` записи — предикат на жертву (`target:trait:undead`), `challenge` — как обычно (`who` на шагах «к цели», `when`, `immunity`, `byDegree`); иммунная цель карточки не получает и окно `per` не гасит. `enter` — хук v14 `moveToken` (положения «до» и «после» — `movement.origin` / `movement.destination`): «был вне → стал внутри» по концу движения, двигаться может жертва или носитель; проход сквозь ауру (внутри побывал по клеткам пути, остановился снаружи) — тоже вход; создание токена и ручной перенос/откат (`config`, `paste`, `undo`) входом не считаются. Стена — луч центр → центр (и для `range`, и для `aura`; только на просматриваемой сцене); в начале/конце хода при `aura` на просматриваемой сцене решает сама аура pf2e (`containsToken`: тип стены по чертам ауры, высота). Жертва — только существо. Запрещено: `afterUse`; `aura`/`range`/`per` не у `near`; `near` с событиями кроме трёх. Пример: `{"on":"turn-end","side":"near","aura":"frightful-aura","per":"round","challenge":{"statistic":"will","dc":{"value":25},"immunity":{"slug":"frightful-aura","duration":{"value":1,"unit":"minutes"}},"byDegree":{"failure":[{"to":"target","who":"enemy","condition":{"slug":"frightened","value":1}}]}}}`. Форма в Мастерской: «в ауре владельца» → аура / дальность / «не чаще». Живой сценарий — `tests/live/aura-trigger.js`.
- `afterUse: true` (strike-gate, «Make a Strike. If it hits, the target must attempt a save…»; только свои броски владельца: `attack-roll`, `skill-check`, `saving-throw`, `damage-roll`) — запись срабатывает на бросок владельца **сразу после карточки этого же предмета**: идём назад по чату, смотрим сообщения этого актёра (`origin.actor`); карточка того же предмета (по slug) — связь есть, а бросок того же вида или карточка другого предмета обрывает поиск. Поэтому одна карточка = один Удар (второй Удар и Удар после промаха уже не «по этому использованию»), а Удар без карточки ничего не запускает. В бою карточка должна быть позже начала текущего хода актёра, вне боя — не старше 10 минут. Исход и «это Удар» — в `when`: `["self:action:slug:strike",{"or":["outcome:success","outcome:criticalSuccess"]}]` (опция `self:action:slug:strike` есть у Ударов и персонажей, и NPC). Цель испытания — цель этого Удара. «Если нанёс урон» приравнено к «попал»; боеприпасы и бомбы («when damaged by») этим не закрыты. Перевод готовых черновиков: `node tools/strike-gate.mjs` (список) / `--write`.
- `check` (Lingering Composition; только `on:"spell-cast"` с `afterUse:true`, не вместе с `challenge`): `{"statistic":"performance","dc":{"ofTargets":"level"},"byDegree":{…}}` — после сотворения владелец бросает проверку против СЛ уровня самого высокого существа среди целей композиции, шаги по степеням идут на владельца (`to:"self"`). Запись срабатывает **один раз на сообщение** (не по разу на цель). Цели для СЛ: у композиции с областью — союзники в эманации от токена владельца и он сам; без области — цели сотворения; никого — уровень владельца (`use.targets` у композиций каталога — выделенные игроком, обычно враг, в счёт не идут; композиции против врагов — Dirge of Doom — считаются по союзникам, СЛ правит ГМ). Карточка-хозяин проверки — как у challenge (режим «challenge» не `off`); NPC-бард бросает сам, PC — кнопкой. СЛ лежит в `use.dc`: ГМ правит её кнопкой «СЛ», пока нет результата (`checks.checkDcOf` берёт `use.dc` при фиксированной `vs.dc`). Связь «следующее действие» — `afterUse` для `spell-cast`: сама карточка Lingering связь не рвёт, любой другой бросок/карточка этого актёра между ней и композицией — рвёт. Пример: `rules/catalog.json`, `Compendium.pf2e.spells-srd.Item.irTdhxTixU9u9YUm` (`extendEffect:{cast:true,rounds:3|2}` при крит. успехе/успехе, `refundFocus` при провале и крит. провале; `when` — кантрип-композиция, кроме Song of Marching). Fortissimo не покрыта.
- Исполняет только активный ГМ; ключ `<сообщение>:<предмет>:<номер записи>` не даёт сработать дважды; переброс откатывает прежнее исполнение. Правило, которым уже занят pf2e-automations, уступается (`yield`).
- Носители (0.5g4): правило `onEvent` может лежать на **эффекте**, который заклинание или расходник ставит владельцу (`side:"target"`: напавший на владельца спасается, Маска ужаса, Репеллент от паразитов — `tools/pa-carriers.mjs`, ключ `bySource` — uuid эффекта), и на **предмете, вложенном в оружие** (Защитная статуэтка: опция `sub-item:<slug>` есть у броска оружием, `scripts/events.mjs`). Эффекты с настоящими Rule Elements вместо пустых меток PA пишутся в `tools/pa-effects.authored.mjs` (`node tools/pa-effects.mjs --authored` — без PA и Foundry) и собираются в пак `node tools/build-packs.mjs`.
- **Удержание атаки** (`hold: true`, Sanctuary; только `side:"target"`, `on:"attack-roll"` или `"skill-check"`): атака по владельцу рождается *удержанной*: на клиенте создателя `preCreateChatMessage` (`events.onPreCreate`) ставит флаг `flags[pf2e-automato].gate.hold` и гасит автоурон Workbench (`flags.xdy-pf2e-workbench.noAutoDamageRoll`), пока нападающий не пройдёт испытание записи. «Атака» — бросок атаки (в том числе заклинанием) **и** проверка с чертой `attack` (Подсечка, Захват, Толчок, Разоружение). Пока атака удержана, её не обрабатывают ГМ-диспетчеры (`events.onMessage` — только записи `hold`, `use.onCreateMessage`, встроенные обработчики Захвата/Реактивного удара…): кнопок урона нет, подсказка реакции не показана. Исход закрывают **шаги** `hold` (`{"to":"self","hold":"release"}` — атака проходит и **один раз** прогоняется заново теми же диспетчерами; `"cancel"` — атака отменена, плашка «действие потрачено», кнопок урона нет; `"end"` — как `release`, плюс снимается носитель с *защищённого* — заклинание кончается; шаг `hold` бывает только в записи с `hold`). Разрешение касается всех удержанных атак пары «нападающий → цель» (Двойной удар: одна карточка), висящая вторая карточка удаляется. Кнопка урона **на карточке заклинания** (атака заклинанием) этим не скрывается — защищает только флаг Workbench. Страховка от зависания: удержанная атака выпускается, если нет карточки и шага (нет носителя, режимы `effect`≠`auto` / `challenge`=off, нет токена нападающего), если ГМ удалил карточку, не применив её; ГМу на плашке доступны ручные «Выпустить» / «Отменить». Удержание не ставится, если нет активного ГМа или выключены `mode.effect` (нужен `auto`), `mode.challenge`, `mode.apply`, `mode.damageGate`. Переброс атаки после разрешённой Воли итог переносит: метки и снятый носитель не откатываются. Автоурон Workbench после выпуска не повторяется (урон бросают кнопкой).
- Срок эффекта `duration.of:"target"` у шага `effect` по uuid (метка «до конца хода получателя»): автор эффекта — получатель, и pf2e считает `turn-end` по **его** ходу, а не по ходу заклинателя. Вне боя `turn-end` сам не наступит — метку снимает ГМ.
- **Убежище (Sanctuary)**: заклинание (`rules/catalog.json`) ставит на цель эффект «Spell Effect: Sanctuary» из пака модуля, носитель с правилом — `rules/catalog.json` (`bySource` по uuid эффекта); метки на нападающем — эффекты «Sanctuary Passed/Stopped» (до конца хода нападающего) и «Sanctuary Barred» (до конца срока). Воля нападающего против СЛ заклинателя: крит. успех — Убежище кончается; успех — этот ход нападающий может атаковать цель без новых спасбросков; провал — атака отменена, до конца хода без бросков отменяются и следующие; крит. провал — атаки отменяются до конца срока. Атака или проверка с чертой `attack` самого защищённого снимает Убежище; враждебные действия без броска атаки (заклинание с уроном, запугивание) — вручную. Эффекты пака собираются `node tools/pa-effects.mjs --authored` + `node tools/build-packs.mjs` (**только при закрытом мире**). Метки привязаны к защищённому (`meta.by`, опция `origin-effect:<slug>`): итог Воли против A не действует на атаки по B. Ограничения: два Убежища на одной цели делят метки; выпуск удержанной атаки необратим — откат шага «Применить» возвращает только отмену и метки, повторный «Применить» второго прогона диспетчеров не даёт; нападающий-игрок (`preCreateChatMessage` на клиенте игрока) вживую не проверялся — только NPC-нападающие под ГМом.
- Правка — в «Мастерской»: вид «Когда: событие». «При попадании Удара» для пассивных способностей NPC (`tongue-grab`) раздаёт `node tools/onhit.mjs` в `rules/catalog.onhit.json`.

## Переменное число действий и «Магия крови»

- Заклинание со временем «1 to 3» / «1 or 2» / «2 or 3» pf2e 8.6 колдует без выбора числа действий (опции `item:cast:actions:N` для таких нет). Модуль сразу после сотворения спрашивает число действий у **автора сообщения** (игрок — у себя, ГМ — у себя) и пишет `origin:item:cast:actions:N` в сообщение и `flags.pf2e-automato.cast.actions`. Ячейка/очко фокуса уже потрачены системой один раз — **заклинание повторно колдовать не нужно**: закройте окно только если сотворили по ошибке. Перехватить сотворение до траты ячейки без обёртки внутренних методов pf2e нельзя.
- «Силовой залп» (`force-barrage`, `magic-missile`): снарядов = действия × (1 + по одному за каждые 2 ранга выше базового). Берутся ваши цели (таргет): одна цель — всё ей; несколько — окно распределения. На каждую цель — **один** бросок урона и одно сообщение (формула умножается на число снарядов; в памяти на время вызова, предмет не меняется). Других заклинаний «снаряды по числу действий» в системе не искали (сжатые паки) — добавить слаг в `MISSILE_SLUGS` (`scripts/builtin/variable-cast.mjs`).
- «Магия крови» (аберрантное наследие): ровно один раз за сообщение сотворения; окно у игрока-заклинателя, если он в сети и владеет актёром, иначе (или при сбое) у ГМа.

## Освобождение, Внезапная атака, Жуткие удары

- **Освобождение** (`escape` у шага `apply` с состоянием или эффектом, напр. Захват, Опутывающая лиана): после наложения жертве и ведущему уходит шёпот с кнопками Атлетика / Акробатика (`stats`, плюс «Безоружная атака») — бросает действие `escape` pf2e против СЛ. Успех и критический успех снимают созданный шагом документ и всё, что он выдал; кнопка не одноразовая (каждая попытка — действие жертвы). `dcStat`: `spell` — СЛ заклинаний автора, иначе навык автора (`athletics`…); не вычислилась — в шёпоте поле ввода СЛ. СЛ источника (`use.dc`) берётся только у испытаний. Если метаигра pf2e скрывает СЛ (`metagame.dcs`), владельцам шёпот приходит без СЛ, ведущему — с ней. Не отслеживается: окончание захвата при перемещении захватчика — снимать вручную.
- **Внезапная атака** (`surprise-attack`): после инициативы Обманом или Скрытностью в 1-м раунде на плуте появляется эффект: существа, ещё не ходившие, застигнуты врасплох для его Ударов и заклинаний-атак (`EphemeralEffect`, как у тисков). Метка снимается, когда у существа начинается ход; эффект — со 2-го раунда, по концу боя и когда плут вышел из боя (id боя во флаге эффекта; висящие подметаются при запуске, `deleteCombat`, `deleteCombatant`). Так же подметается эффект «Один выстрел, один труп».
- **Двойной финт** (`twin-feint`, встроенный): нужна ровно одна цель и два ближних оружия в руках (признак «в разных руках» проверяется косвенно — `handsHeld: 1` у двух разных предметов; щит с клинком и оружие со `free-hand` как «меч» не распознаются). Окно: какое оружие каким Ударом и MAP первого; второй Удар — на ступень MAP выше. Off-guard — временный эффект на плуте только на второй Удар и его урон (Sneak Attack срабатывает один раз, на втором); снимается сразу после второго броска или при его ошибке. Отмена первого броска — второго нет. Модуль сам не списывает 2 действия — их тратит карточка/трекер.
- **Перекат за спину** (`tumble-behind`): успех Акробатического прохода (`tumble-through`) вешает на плута эффект «до конца хода» и метку на **выбранную в таргете** врага — таргетьте пересечённого врага до броска (при нуле или двух целях метка не ставится). Off-guard — только Удары по помеченному; урон по нему или промах Удара снимает эффект. Системный переключатель `tumble-behind` от эффекта не зависит: если он включён, off-guard будет у всех Ударов по всем целям весь ход — модуль его не гасит.
- **Жуткие удары** (`dread-striker`): модуль ничего не делает — родной `EphemeralEffect` с `target:condition:frightened` уже в черте pf2e 8.6.1.

## Недуги со стадиями (шаг `affliction`)

pf2e стадий недугов не ведёт (предмет `affliction` в сборке не создаётся), поэтому счёт ведёт модуль. Шаг `{to: "target", affliction: {stage, def}}` кладёт определение (`def`: название, вид яд/болезнь/проклятие, спасбросок, `maxDuration`, `onset`, `virulent`, `stages[]` с сроком, уроном, продолжительным уроном, состояниями, штрафами `mods` и текстом) прямо в шаг; на цели создаётся эффект без срока, стадия — счётчик на его значке. Определение из текста «Saving Throw … Stage N …» собирает код (`tools/affliction.mjs`): провал — стадия 1, крит. провал — стадия 2; нераспознанное остаётся текстом стадии. Вывод из разметки такие правила не вешает (low).
- Спасбросок — в конце интервала стадии: в бою на конце хода цели (раунд = 6 с мирового времени, время в бою идёт по раундам), вне боя и у не-участников — по смене времени и при смене ведущей вкладки. Успех −1, крит. успех −2, провал +1, крит. провал +2; провал после последней стадии повторяет её урон. Время прошло скачком (8 часов) — одна карточка и новый интервал от «сейчас», пропущенные интервалы не догоняем; `maxDuration` вышел — недуг снят.
- Повторное воздействие: яд — стадия +1 (крит. провал +2), срок не меняется (и в onset); болезнь и проклятие не действуют. Onset: стадия записана сразу, эффекты ждут срока.
- **Virulent:** страница правил не говорит, обнуляется ли счётчик успехов. Толкование модуля: любая степень, кроме успеха и крит. успеха, обнуляет счётчик; два успеха подряд снижают стадию на 1, крит. успех сам снижает на 1 и счётчик не копит.
- Состояния стадии: frightened, sickened, drained, doomed, stunned, unconscious поднимаются по максимуму и при смене стадии не снимаются (как у pf2e); остальные живут в обёртке и заменяются вместе со стадией. Чужое состояние не трогается. Штрафы стадии (`mods`) — в правилах эффекта-носителя.
- **Расхождение с pf2e:** урон стадии при клике ГМа по значку носителя наносится только при росте стадии; путь спасброска наносит урон при любой смене стадии (как pf2e). Урон стадии на одном сообщении и цели после отката и повторного «Применить» второй раз не наносится (журнал `state.damaged`).
- Лечение вручную — клик ГМа по значку носителя вниз (урона при снижении нет); снятие носителя убирает всё созданное им. Откат шага (`undoOps`) возвращает стадию и часы без повторного урона. Не сделано: лечение внешним эффектом (Neutralize Poison), распространение болезни, нанесение яда на оружие, кумулятивное снижение СЛ.
- **Заметка недуга `def.note`** (строка ≤ 1200, обрезка с «…»; Мастерская — поле «Заметка» в шапке недуга): то, что модуль не автоматизирует (нельзя снять, смерть, превращение). Показывается в описании эффекта-носителя и на первой карточке стадии; настройка мира «Заметка недуга» — публично (по умолчанию) или шёпотом ведущему (тогда в описание не идёт). Настройка читается в момент показа; описание носителя пишется при наложении, поэтому на уже наложенные недуги смена настройки не действует. Смерть не автоматизируется: стадия без срока (`duration: null`) — конечная, бросков нет; без `maxDuration` носитель не снимается.
- **`@Check[...|basic]` у недугов игнорируется сознательно:** спасбросок недуга всегда не-basic (провал → стадия 1, крит. провал → стадия 2); модификатор `basic` в тексте не меняет шаги.
- **Мастерская правит недуг целиком** (режим «Автоматизация», шаг вида «недуг» — он есть в списке видов и в «+ Добавить»): шапка (название, вид, спасбросок и СЛ, макс. срок, начало действия, вирулентный, начальная стадия шага), стадии строками-сводками (раскрыта одна: срок, урон, продолжительный урон, состояния плашками −/+, штрафы тем же редактором свойств, что у «своего» эффекта, текст), добавить/удалить стадию. Допустимое то же, что у валидатора `vAffliction`. Логика — `scripts/workshop/affliction-edit.mjs`.
- **Определение общее для шагов группы.** Копия лежит в каждом шаге-недуге (Провал — стадия 1, Крит. провал — стадия 2); правка в одном шаге переписывает все шаги его группы, своя у шага только начальная стадия (`affliction.stage`), она не выходит за число стадий. Группа — сессионная (в правило и на вкладку листа не попадает): при открытии окна шаги с равными определениями образуют группу, переименование группу не меняет, поэтому разные недуги с одним именем не сливаются. Новый шаг-недуг в правиле с недугом присоединяется к его группе; кнопка «Отделить» даёт шагу независимую копию. Вкладка листа правит тот же шаг JSON-строкой, без синхронизации.

## Нанесение яда на оружие (шаг `coat`)

Injury-яд (расходник или действие) наносится на оружие и действует на цель **первого Удара** этим оружием. Шаг `{to: "self", coat: {weapon: "choose", challenge, duration?}}` стоит в `onUse.apply` (один, не в событиях и не в степенях испытания); `challenge` — обычное испытание цели (спасбросок, СЛ, степени с шагом `affliction` или состоянием), его запускает не использование, а Удар. Для готового правила с `onUse.challenge` есть конвертер `coatOf` (`tools/affliction.mjs`).

- **Носитель** — эффект владельца со slug `coat-<яд>-<id оружия>`, бессрочный (у Envenom срок задаёт `coat.duration`: до конца следующего хода владельца). В флагах — `coat` (оружие, признак боеприпасов, СЛ числом, определение недуга) и собственное onEvent-правило (`flags.pf2e-automato.rule`); пак-эффекта нет. СЛ в любой форме (`value`, `against`, `expr: "markup"`) превращается в число при нанесении (`coatDc`): расходник к Удару может исчезнуть.
- **Выбор оружия** — окно у игрока-автора (иначе у ведущего), единственное годное берётся без вопроса; у персонажа это `weapon`, у NPC только `melee` (Удар NPC идёт от `melee`; оружие инвентаря даёт свой связанный `melee`, боеприпасы берутся по `flags.pf2e.linkedWeapon`), без брошенных и убранных в рюкзак. Колющее/рубящее проверяется по опциям предмета (`item:damage:type:*`); дробящее помечается в окне, а ведущему уходит заметка (и при единственном оружии): яд на нём тратится без действия.
- **Замена.** Второй яд на то же оружие заменяет первый, ведущему уходит шёпот. Повтор кнопки той же карточки носителя не дублирует (`meta.key`).
- **Ход яда.** Не взведён: Удар попал (успех/крит. успех) — яд *взводится* на цель, у носителя меняется правило; промах — ничего, яд остаётся; крит. провал — яд потрачен без испытания. Взведён (попавший Удар «забрал» яд: следующие Удары этим оружием его не несут и не тратят): сообщение «урон получен» по этой цели — яд потрачен, и испытание бросается, только если ОЗ или временные ОЗ цели убыли и оружие колющее/рубящее; иначе яд потрачен без испытания. Урон не применили или он сведён к 0 (pf2e такого сообщения не пишет) — яд пропадает без испытания в конце хода владельца; вне боя конца хода нет, и его тратит следующий Удар этим оружием. Урон другой цели (область) взведённый яд не трогает. Связь с оружием — опция `item:id:<id оружия>` у броска и урона.
- **Боеприпасы.** Признак — как у pf2e (`WeaponPF2e`, расход боеприпаса): `system.expend > 0` и не `system.ammo.builtIn`; он не зависит от выбранного боеприпаса. На таком оружии яд тратится первым Ударом любого исхода, испытания нет (снаряд улетел).
- **Режимы.** События носителя идут только при настройке эффектов «Автоматически»: иначе шаг показывает шёпот и носитель не создаёт. При режиме испытаний «Выключено» яд тратится без карточки.
- **Откат.** Нанесение, взвод и трата пишут журнал: откат карточки яда ищет носитель по ключу шага (а не по uuid: после отката траты он пересоздан с новым id), откат взвода (переброс Удара) возвращает правило и цель, откат траты возвращает носитель вместе со взводом.
- **Внутренние поля.** В правиле носителя запись `onEvent` может нести `gate` (`target` — урон по взведённой цели; `removed` — испытание только если шаг снятия реально снял носитель, это защищает от гонки двух быстрых Ударов), `idle` — только вне боя (запись «следующий Удар тратит яд»), а шаг — `coatArm: true`. Они нужны только носителю; в каталог правил не идут (семантическая проверка отвергает).
- **Ограничения v1.** Сообщение «урон получен» несёт убыль ОЗ, но не разбивку по типам: колющее/рубящее берётся из оружия, а не из экземпляров броска; ложное испытание возможно, если s/p свели к нулю, а другой тип (огонь, свойство оружия) нанёс урон. Не сделано: модификаторы черт (Deadly/Sticky/Double Poison, Blowgun), яд на боеприпас, 8 injury-действий NPC, оружие с активацией. Подробности и список проверок вживую — `plan-weapon-poison.md`.

### Ключ `activate` (прежде `cast`)

Список активаций предмета хранится под ключом `activate`; старый `cast` читается по-прежнему (при обоих ключах побеждает `activate`, `tools/validate` и Мастерская считают это ошибкой `activate.dup`). При запуске мира **активный ГМ автоматически переписывает** мировой каталог и флаги `rule` предметов (на актёрах и вложенные, например спеллхарты) на новый ключ; счётчики `uses` и `id` записей не меняются. **Обновите модуль у всех клиентов:** клиент со старой версией после перезаписи не увидит кнопок активаций, а откат модуля теряет их. Не мигрируются предметы в компендиумах мира, неразвёрнутые токены и чужие модули — они продолжают работать за счёт чтения `cast`. Снимки в уже созданных сообщениях со старым `cast` тоже читаются.

**Форма записи (схема и валидатор).** Запись — ровно одно из `spell` | `choices` | `onUse` либо пара `spell` + `onUse` («каст + добавка»); без `spell` и `choices` обязательна `label`. `onUse` — грамматика `rule.onUse`; СЛ испытания внутри — только `{value: N}` или не задана (при нажатии: `value` → `dc` записи → СЛ по уровню предмета), формы `against`/`source`/`level`/`from` отвергаются (`activate.dcForm`). `choices` — 2–6 вариантов `{id?, label?, spell?, onUse?, rank?, dc?}` (у варианта без `spell` нужна `label`, вложенных `choices` нет). `rank` — целое 1–10 или `{half: "actor"|"item", min?}` (`max(min, ⌊уровень/2⌋)` от уровня актёра или предмета; `min` по умолчанию 1; только вместе со `spell`). `dc` записи — число, `{level: "high"}` или `{against: "class-spell"}` (СЛ лучшей записи заклинателя актёра). `id` записей и вариантов уникальны. Ключи ошибок: прежний `rules.err.cast.bad`, новые `activate.kind`/`label`/`choices`/`choice`/`dcForm`.

## Вычисляемые опции броска

Если условие вычисляется из положения на сцене, переключателя нет (CLAUDE.md §1.5). Реестр — `REGISTRY` в `scripts/builtin/neutralize-rules.mjs`: опция -> вид режима (`mode.computed`). Новая опция — одна строка.

- **Нейтрализация переключателя** (`neutralize-rules.mjs`): обёртка статической `game.pf2e.RuleElements.fromOwnedItem` (libWrapper, без него — прямая подмена) ставит `ignored = true` переключаемому `RollOption` с опцией из реестра. Строки нет ни на листе, ни в Token Action HUD, а `RollOption.beforeRoll` не снимает нашу опцию. `BaseSpeed`/`DamageDice` не трогаем. Данные мира не пишутся: при `mode.computed = off`, уступке pf2e-automations (`yieldToAutomations`) или без модуля pf2e возвращает переключатель; смена настройки пересобирает актёров.
- **«Стайный»** (`computed-options.mjs`, опция `pack-attack`; 73 NPC бестиариев и черта): в бросок урона Удара (`strike.damage`/`critical`, в том числе альтернативные применения) добавляется опция `pack-attack`, если у цели не менее двух живых видимых союзников бросавшего (кроме него самого), держащих её в досягаемости; цель — как у pf2e (цель карточки, иначе первая цель пользователя). Кубы, критудвоение и precision считает `DamageDice` pf2e. Порог один — у `superior-pack-attack`, `coordinated-assault` и у Phantom Wolf (по источнику актёра); только отрисованная сцена; на гексе и без сетки расстояние даёт `distanceTo` pf2e между углами токенов — приближённо. Нейтрализация не встала — опция не подставляется, ГМу одно предупреждение.
- Не вычисляется (в долг): `war-formation`, `subduing-attack` (по 2 документа, опция не проверена), Convergent Tactics, Tag Team, Gang Up (по 1–3).
