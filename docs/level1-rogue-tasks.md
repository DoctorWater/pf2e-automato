## Пакеты реализации, зависимости и владение

Владельцы следующей волны: исполнитель L1-R получает только собственные новые `scripts/builtin/level1-rogue.mjs`
или более узкие новые обработчики (если они нужны после ревью), профильные новые тесты и `tests/live/level1-rogue.js`.
Существующие каталоги, пак эффектов, actions/events/reactions/saves/main, builtin/index и ru/en изменяет только интегратор.
Исполнитель описывает необходимые врезки и определения эффектов в результате задачи; одновременного редактирования общих файлов нет.
Новые файлы не создавать ради пустого каркаса. Проверку сборки делать fixtures/инвентаризацией, без нового actor-build pipeline.

## Общие действия и переменные сборки

Плут получает классовую и навыковую черту на первом уровне; фон и родословная дают дополнительные варианты.
Не объявлять весь справочник навыковых черт обязательным списком одного персонажа. Для выбранных items составить
инвентаризацию с UUID/предпосылками/автоматизацией; неизвестное помечать явно. Проверить базовые Feint, Demoralize,
Tumble Through, Recall Knowledge, Create a Diversion, Hide/Sneak и Shove там, где они используются перечисленными
способностями. Результаты восприятия/отношений относительны, тайная информация остаётся ведущему.

## Проверки следующей волны

- Валидатор каталога и round-trip формы при изменении схемы, `node --check` затронутых `.mjs`, профильные тесты, `node --test`, ключи ru/en.
- Живой прогон на временных копиях «AF тест»: два плута, две цели, разные ходы, промах/крит/отказ, реакция уже потрачена,
  перезагрузка и активный ведущий; уборка собственных документов. Без живого прогона статус `implemented-needs-test` сохраняется.
- Независимый Критик по смыслу и диффу; после исправлений повторная проверка. Коммиты только по явному указанию пользователя.
- Сейчас меняется только документация: проверки игрового поведения не запускались и не считаются пройденными.
