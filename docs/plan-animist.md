## 2. Ключевой факт про Поддержание

- `sustain.mjs`: якорь создаётся шагом `sustain:true` (`attach`), `last` якоря = позиция раунда при сотворении. `count()` отдаёт `"fresh"` только если `last` ≠ текущий раунд; сотворение и Поддержание в одном раунде дают `"again"`. Значит «при сотворении и **первом** Поддержании в каждом последующем раунде» уже даётся самим якорём — отдельного `once`/дедупа не нужно. Вне боя (раунда нет) дедуп — окно 6 с (`events.onSustain`).
- **Но**: `spell-sustain` сегодня доходит только до способностей фамильяра. `onSustain` вызывает `runEvent(…, {familiar:[actor]})`, а валидатор (`rules.mjs:637`) отклоняет `spell-sustain` у записи не с `side:"familiar"` (`ev.familiar`). Записи сосудов «импульс при Поддержании» поэтому не выразить даже на готовых полях: у события нет сообщения-карточки и целей.
- Следствие: все пульсирующие сосуды (A23, A25, A20, A26, A27, A28, A29, A30, A31, A22) упираются в один примитив P1 (раздел 5). Без него полезно только то, что делает сотворение (`spell-cast`) и сам эффект.

## 9. Эскиз P1 и риски

- Валидатор: разрешить `spell-sustain` при `side:"self"`; `ev.familiar` оставить для ветки `familiar`. Запись живёт на заклинании-источнике якоря (`anchor.flags.sustain.src`), событие запускается под `queue("events:<anchor>:<combat>:<round>")` — дедуп раунда остаётся прежним (`count()` → `fresh`).
- События без карточки: `ev.message` пуст, цели — `anchor.flags.sustain.actors` либо область якоря (эманация/зона автора); шаги `choose from:"options"` работают как при сотворении.
- Риск 1: вне боя нет раунда — действует окно 6 с, импульсы не дублировать вручную.
- Риск 2: два сосуда одновременно у одного героя — Sustain из чата pf2e засчитывается единственному якорю, при двух якорях только подсказка; для пары A23+A27 у Само нужна проверка (раздел 7, п. 5).
- Риск 3: `last` якоря при сотворении = позиция раунда, поэтому cast-пульс и первое Sustain в тот же раунд не должны оба сработать; проверить сценарием «cast и Sustain в одном раунде».
- Порог: P1 = 66 документов по регулярке (верхняя оценка); перед кодом пересчитать по `tools/coverage.mjs`/словарю `rules/mechanisms.json`, а не по регулярке.

Приёмка партии: `node --check` затронутых `.mjs`, `node --test`, валидатор правил; один живой сценарий `tests/live/level1-animist.js` по образцу `level1-sustain.js` (22/22) с временными копиями «AF тест» и уборкой.
