# План: урон по итогам обычного спасброска (basic save → damage)

Статус: **проект v1, код не писан.** Решение пользователя 2026-11-06 «делай».
Опора:
- `scripts/saves.mjs` — результаты испытания в `use.state.challenge.results[key] = {degree, total, dc}`, цели — `challengeTargets`;
- `scripts/chat.mjs:~225` — множитель `mult(degree, basic)`, подпись «урон ×½»;
- `scripts/events.mjs` — `strikeCardFor`: поиск карточки предмета для броска по ленте чата, граница хода, `AFTER_USE_MS`;
- `scripts/apply.mjs` — `undoLog` и откат;
- pf2e `applyDamageFromMessage` (`pf2e.mjs:54152`) — образец нанесения: `roll.alter(m, 0)`, `getContextualClone`, `actor.applyDamage({damage, token, item, rollOptions, outcome, shieldBlockRequest})`.

## Проблема

Модуль бросает обычные (basic) спасброски целей и показывает множитель, но основной урон бросает игрок отдельной карточкой урона pf2e (заклинание, импульс, `@Damage`). Эту карточку модуль с итогами не связывает: ГМ наносит урон руками, выделяя токены по одному. Toolbelt-путь не лучше: спасброски NPC не бросаются, цели области до Toolbelt не доходят, а `basic` теряется (живая проверка 2026-11-06, Пылающая колонна).

**Группа** — все предметы с обычным спасброском и уроном системы: заклинания с `defense.save.basic`, импульсы с `@Check[...|basic]`, бомбы и прочие с `basic` в правиле. Это сотни документов, порог пройден.

## Механизм

1. **Связь.** Сообщение `damage-roll` (`flags.pf2e.context.type`) от актёра A по предмету I (`flags.pf2e.origin.uuid`, для `@Damage` — `itemId` в опциях или `message.item`) ищет назад по ленте карточку использования модуля (`flags.<MOD>.use`) того же актёра и того же предмета. Условия:
   - у карточки `challenge.basic === true`;
   - есть хотя бы один результат;
   - соблюдены граница хода и `AFTER_USE_MS`, как в `strikeCardFor`; можно переиспользовать его с поиском по item uuid.

   Не нашли — ничего не делаем.
2. **Множитель** по степени цели: крит. успех ×0, успех ×½, провал ×1, крит. провал ×2 (тот же `mult`, что на карточке). Цели без результата (ещё не бросили, иммунитет) пропускаются; когда результат появится позже, урон наносится досрочно (см. п. 4).
3. **Нанесение** — по образцу pf2e `applyDamageFromMessage`, но по токенам целей карточки, а не по выделенным:
   - `roll.alter(m, 0)`, при ×0 не вызываем;
   - `actor.getContextualClone` с опциями сообщения;
   - `applyDamage({damage, token, item, rollOptions, outcome})`.

   Так сопротивления, щит и откат кнопкой pf2e на карточке «damage-taken» работают штатно. Каждое нанесение — один раз на пару (сообщение урона × цель): ключ в `flags.<MOD>` сообщения урона.
4. **Режимы** (`mode.apply`):
   - `auto` — сразу, у активного ГМа;
   - `button` — на карточке урона кнопка «Нанести по итогам спасбросков», ГМу;
   - `off` — ничего.

   Результат, пришедший после броска урона (цель бросила позже), в `auto` наносится сразу, в `button` — повторным нажатием (уже нанесённые пропускаются).
5. **Не трогаем:**
   - не-basic испытания (урон по степеням в шагах правила, как Earth's Bile — уже наносится шагами);
   - атаки;
   - урон с карточки, у которой правило само наносит урон шагами `damage` (иначе урон удвоится): если в `byDegree` есть шаги `damage`, механизм молчит;
   - Toolbelt-путь (`useToolbeltTargetHelper` + `targetHelper.checks`): результаты держит Toolbelt — молчим.
6. **Где:** новый `scripts/builtin/basic-damage.mjs` по образцу соседних обработчиков (`MESSAGE_HOOKS`), кнопка — через `renderChatMessageHTML`. Строки — в существующих lang-файлах. Чистая функция `planBasicDamage(results, targets) -> [{key, mult}]` с тестом.

## Риски для Критика

- Повторный бросок урона (переброс, второй клик по `@Damage`) не должен наносить урон второй раз — или должен? Решение: связывается только **первый** бросок урона после карточки; следующие — без автоматики (так безопаснее, ГМ видит обычные кнопки pf2e).
- Карточка с двумя бросками урона (основной и продолжительный в одном сообщении): берём `rollIndex 0`, продолжительный pf2e кладёт сам.
- Игрок бросил урон до спасбросков (цели ещё не бросили) — п. 4.
- Права: `applyDamage` по чужим токенам — только ГМ.

## Проверка

- Юнит: `planBasicDamage`, поиск карточки.
- Живой прогон в RustySpirit: Пылающая колонна по Гоблину (успех → ½) и Скелету (провал → ×1); заклинание Марены с обычным спасброском по области; переброс урона не наносит второй раз; `button` — кнопка наносит один раз.

## v2 — правки по Критику (2026-11-06), перебивают текст выше

1. **Связь без требования результатов.** Связываем при создании урона, даже если результатов ещё нет:
   - на карточке — `use.state.basicDamage = {msg}`;
   - на сообщении урона — `flags.<MOD>.basicDamage = {card, done:{key:{degree, mult}}}`.

   Поздние результаты наносит хук в `saves.afterRecord` (`saves.mjs:~328`). Обе ветки идут в одну очередь `queue("basic:"+dmgId)`.
2. **Без двойного урона по соседним путям.**
   - Цель пропускается, если `shield-block.alreadyApplied()` вернул истину (это ловит и ручные кнопки pf2e).
   - После нанесения ставить `flags.<MOD>.shieldBlock.done.<tokenId>` и `flags.pf2e-toolbelt.targetHelper.applied.<tokenId>.0`, как `useBlock`.
   - В режиме `auto` на карточке урона — строка «нанесено: имя ×½».
3. **Переброс спасброска после нанесения.** Степень хранится в `done[key]`. Если новая степень расходится со старой — шёпот ГМу (`saves.changedAfterApply` или новый ключ) и кнопка «пересчитать» на карточке урона. Пересчёт откатывает старое нанесение и наносит заново.
4. **Откат pf2e.**
   - В `rollOptions` нанесения кладём маркер `pf2e-automato:basic:<dmgId>:<key>`.
   - Если у сообщения `damage-taken` стоит `appliedDamage.isReverted`, снимаем `done[key]` (образец — `events.mjs:~717`).
5. **Нанесение.**
   - Эфемерные эффекты — через `origin.synthetics.ephemeralEffects["damage-received"]`; функция `extractEphemeralEffects` не экспортируется.
   - Опции собираются заново для каждой цели: `self:` → `origin:`, `origin:ally/enemy`, собственные опции цели.
   - `shieldBlockRequest` не передаём: Блок — реакция, идёт своим путём.
   - Отряды схлопываем по `troop.id`.
6. **Поиск карточки — по снимку модуля** (`flags.<MOD>.use.actor` и `use.item.uuid`, запасной ключ — slug), а не по `origin` pf2e. Так находятся и карточки Поддержания, и карточки активаций (`use.item` — заклинание, если оно есть в снимке). Окно поиска шире 50 сообщений или по ходу.
   - **Долг:** расходник, который исчез после траты (у инлайн `@Damage` нет origin), остаётся без связи.
7. **Гейтировка.**
   - Свой хук `createChatMessage`, как у `shieldBlock` (`builtin/index.mjs:~75`), под `mode.apply`, а не `mode.macro`.
   - При `use.confidence === "low"` режим `auto` понижается до `button`.
8. **Молчим также, если:**
   - в правиле есть шаги `damage` в `onUse.apply` или в `pulse`;
   - `context.sourceType === "attack"`;
   - в `rolls[0].kinds` нет `"damage"` (лечение).
9. **Признак `basic`.**
   - Если в правиле нет `basic:true`, для заклинаний берём `item.system.defense?.save?.basic`.
   - Исправить `basic:false` в `catalog.model.json` у Incarnate Skeletal Giant, Sage's Curse и Stumbling Curse.
   - Правила без `challenge` при обычном спасброске — долг с перечнем (Living Thunderbolt и др., расходники PA).
10. **Тесты связи:**
    - Удар между карточкой и уроном;
    - урон другого предмета;
    - второй бросок урона (связывается только первый);
    - карточка импульса Поддержания;
    - поздний результат;
    - переброс спасброска;
    - откат.

## Долг

Механизм не видит предметы, у которых нет `challenge` в правиле, хотя спасбросок обычный — для них связывать урон не с чем:
- заклинания и способности: Living Thunderbolt, Interstellar Void, Ibex's Harvest, Call the Ten, Draconic Barrage, Glass Shield, Draw the Lightning, Crown of Prophets;
- расходники PA: Silver Crescent, Poison Fizz, Frost Breath, Phoenix Flask, Energy Mutagen.

Чтобы они заработали, нужно добавить им правило с `challenge` и `basic: true` (механизм группы, а не частный случай).

Расходник, исчезнувший после траты, остаётся без связи: у инлайн `@Damage` нет origin, а предмета в снимке карточки уже не найти по uuid.
