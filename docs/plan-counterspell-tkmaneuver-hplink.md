## M4. Реакция-контрзаклинание

### M4.1 Признак и группа
Признак: `Trigger ... Casts a Spell` + `counteract` в тексте. Разбор 66 уникальных (76 док.):
- простые, без траты слота — 24 уник. / 28 док. (+2 / 2 с иным триггером): модификатор в тексте `[[/r 1d20+N #Counteract]]` (14), «spell attack modifier» + ранг 2 (Denounce/Chastise/Ravage Heretic), навык (Devour Ambient Magic, Absorb into the Aegis, Shred Spell);
- «потратить подготовленное/ячейку» — 32 уник. / 38 док.: Counterspell (PC prepared/spontaneous, ~21 PC-черт), Dueling Counter, Troop Counterspell и т.п.;
- добавки: временные ПЗ (Confiscate Spell, Shred Spell — 2), «сохранить в книгу / отразить / подчинить призванного» (Spellstealing Counter, Reflect Spell, Bloodstone Doll, Mimic Spell — 6 док.);
- иной триггер (спасбросок по области, Recognize the Spell, аура Spellsurge) — 3 уник.: вне механизма, остаются ручными.

Окупаемость: готового примитива нет (в коде `counteract` — только модификатор в `cast.mjs:170` и `rules.mjs:855` для активаций; сравнения рангов и отмены заклинания нигде нет). Записью каталога из существующих шагов не выразить: нужна отмена чужой карточки. 76 док. > порога 30 — механизм оправдан.

### M4.2 Правила (из источника, не по памяти)
- СЛ — СЛ заклинания-триггера (`PF2E.Item.Spell.Counteract.Hint`: «if it's a spell, use the caster's DC»; `spellDcOf` в `events.mjs`). Правится ГМом кнопкой «СЛ» карточки проверки (`checkDcOf`).
- Таблица результата — из `PF2E.Item.Spell.Counteract.*` и `rollCounteract` (`pf2e.mjs:53798`): крит. провал — не сорвано; провал — рангом ниже контр-ранга; успех — ранг не выше контр-ранга +1; крит. успех — +3. Чистая функция `counteractOutcome({degree, counterRank, targetRank}) -> {counteracted, maxRank}`; числа сверить с `rollCounteract` при реализации (в плане не закрепляю по памяти).
- Ранг заклинания-триггера: `flags.pf2e.origin.castRank ?? item.rank`. Контр-ранг: из записи — число, `{half:"actor"}` (уровень/2 вверх, как `vRank` в `rules.mjs`), либо ранг потраченной ячейки (фаза 2).
- Модификатор: (а) из текста — плоский, как `buildEntry` в `cast.mjs:170` (вынести общий `flatStatistic(actor, mod)`); (б) `getStatistic("counteract")` — pf2e сам берёт лучший `counteraction` записей колдовства (`pf2e.mjs:34446`); (в) навык (`arcana`/`religion`…).
- Бросок не копируем: карточка проверки уже есть (`hostChallenge`), игрок/ГМ бросает кнопкой.

### M4.3 Места в коде и хуки
1. **Поле записи.** `onEvent {on:"spell-cast", side:"near", range:N|aura, cost:"reaction", when:[…], counter:{mod:N | statistic:"counteract"|"spell-attack"|навык, rank:N | {half:"actor"}, expend?:"same-spell"|"same-rank"}}`.
   - `rules.mjs`: `NEAR_ON` (`:689`) + `"spell-cast"`; валидатор `vEvent` — `counter` только при `side:"near"`, `on:"spell-cast"`, `cost:"reaction"` (как `check`/`cost` из youre-next). `EVENT_TARGETED` уже включает `spell-cast`.
   - Условия, которые модуль **вычисляет** (правило 1.1, без вопросов): расстояние и стены (`aura.mjs insideAura/wallBlocked`, как `fireNear`); черты заклинания (`origin:item:trait:summon|divine|mental|teleportation` — уже в `messageOptions` из `pf.origin.rollOptions`); «единственная цель — вы» / «цель — вы или союзник в 15 фт» (по `messageTargets(message)`, новая опция `spell-cast:targets-self-only`, `spell-cast:targets-me-or-ally:15` в `messageOptions`); «заклинание, которое вы подготовили / есть в репертуаре» (поиск в записях колдовства владельца, фаза 2); враг/союзник — пара `alliance`, как для `damage-taken` в `messageOptions`. Не вычисляется («видите проявления», «не поклоняется Урготе», «вы в дуэли») — текст условия показывается в окне владельца и ГМу, решение за ГМом/игроком (вопрос 2).
2. **Удержание карточки заклинания** — единственное, что даёт честную «отмену». Сейчас `hold.mjs` держит только атаки (`isAttackContext` в `events.onPreCreate`, `events.mjs:765`). Добавить причину `"counter"` рядом с `REROLL`:
   - `events.onPreCreate`: для карточки `spell-cast` (origin.type === "spell", без context.type), если на сцене есть токен с записью `counter`, в радиусе, реакция доступна и `holdEnabled()` — `message.updateSource({flags:{[MOD]:{gate:{hold:"counter"}}}})`. Нет кандидатов — карточку не трогаем (нулевая цена для столов без таких существ);
   - потребители карточки сотворения, которые должны молчать, пока висит `counter` (группа, проверить ВСЕХ, правило 4.4): `events.onMessage` (ранний выход как `isRerollHold`, иначе он решит, что это Святилище), `use.onCreateMessage` (`use.mjs:236`, уже `isHeld`), `builtin/index.mjs:70` (уже `isHeld`), `sustain.mjs:299` (`onMessage` **не проверяет** — якорь Поддержания поставился бы на сорванное заклинание), `builtin/variable-cast.mjs:143` (клиентский хук), `builtin/animations.mjs` (не проверяет, только косметика), `damage-button.mjs refreshCard`/`damage-gate.mjs` (плашка ожидания, строка `hold.waiting` — для `counter` свои строки);
   - `hold.pairOf` строит ключ «актёр>цель» — для `counter` ключ = `message.id` (иначе два заклинания одного мага слипнутся).
3. **Диспетчер** — новый маленький модуль `scripts/counterspell.mjs`, подписка `createChatMessage` (активный ГМ), если `gate.hold === "counter"`:
   - кандидаты = токены сцены с записью `counter` (`eventItems(actor)`), фильтр геометрией/`when`; порядок — по расстоянию; очередь `queue("counter:"+message.id)`;
   - на каждого: `runEntry` (уже даёт гейт реакции, очередь владельца, дедуп) -> ветка `entry.counter` в `execEntry`: подтверждение окном `apply.askChoice` (кому — `chooserOf`/`ownerPlayer`), `spend()` (+ слот в фазе 2), `hostChallenge` с `check:{statistic|flat, vs:{dc}}`, `castMessage`, `state.counter = {cast: message.id, counterRank, targetRank}`;
   - результат броска -> `saves.recordResult` видит `state.counter` -> `counteractOutcome` -> `hold.resolve(cast, "cancel")` либо следующий кандидат; кандидаты кончились -> `hold.resolve(cast, "release")` (`replay` прогонит все диспетчеры, `events.onMessage` стороны `near` не исполняет — повторного окна нет);
   - один успех завершает цепочку (заклинание срывается один раз).
4. **Что реально происходит при «сорвано»** (честно): карточка pf2e остаётся в чате (след для ГМа), слот уже потрачен (правильно: контрзаклинание слот не возвращает). Модуль **не** исполняет: шаги `onUse.apply`, события `spell-cast` (Lingering и т.п.), якорь Поддержания, встроенные обработчики (damage-link, hex, spellshape), кнопки «Урон»/спасброска на карточке модуля. Модуль **не может** остановить то, что делает сам pf2e/другие модули по кнопкам внутри HTML карточки pf2e (бросок урона, шаблон области, спасбросок) и анимации Automated Animations: при `cancel` переписываем `content` карточки, убирая `section.card-buttons`, и добавляем плашку «Сорвано: …». Проверить живьём, что pf2e не рисует кнопки заново при `updateChatMessage`.
5. **Фаза 2 — трата ячейки** (38 док.): `counter.expend`. Подготовленное — слот с тем же заклинанием и `expended:false` -> `entry.setSlotExpendedState`/`update system.slots.slotN.prepared.i.expended`; спонтанное — `slots.slotN.value-1` ранга ≥ триггера (Counterspell: тот же ранг для PC; «такого же или выше» у NPC). Нет подходящей ячейки — действия нет, предупреждение «что не так и что сделать» (правило 1.1), обход Alt. Откат — op журнала `slotExpended{entry, slot, prev}` в `undoOps`/`undoLog` (рядом с `reactionSpent`).
6. **Добавки.** Временные ПЗ (2 док.) — не окупаются: `note` в `byDegree`/шаге; сохранить/отразить/подчинить (6 док.) — только `note`, нарратив не автоматизируем.

### M4.4 Что видит ГМ/игрок (строки в существующем `lang/ru|en/events.json`, ключи `events.counter.*`)

## M5. Манёвр атакой заклинания вместо Атлетики

**Решения Руководителя и Критика (перекрывают текст ниже; реализовано `scripts/builtin/maneuver.mjs`):** поля `onUse.maneuver` в грамматике правил нет — таблица по slug во встроенном обработчике (Telekinetic Maneuver, Magnetic Attraction), список манёвров — по тексту копии (ссылки-uuid или английские названия; старые копии — три, без Reposition; текста не нашли — весь список таблицы). Бросок — `game.pf2e.actions.get(slug).use({statistic:"spell-attack", target: Actor|TokenPF2e, multipleAttackPenalty})` (TokenDocument pf2e молча заменяет целями игрока). Степени применяет существующий `actions.onRollMessage` (тип `attack-roll` уже в `ROLL_TYPES`). Кнопку pf2e «Spell Attack» прячет гейт в `damage-button.attackOrder`; после первого манёвра остальные кнопки скрываются (флаг карточки `flags[MOD].maneuver`: у броска из `use()` нет origin). Риск «руна мощи»: Разоружение, Толчок и Сбивание берут модификатор мощи лучшего экипированного оружия с чертой манёвра независимо от statistic (`pf2e.mjs` disarmCheckContext/shoveCheckContext/tripCheckContext) — ограничение pf2e, не обходим. Vanish Weapon, Mage Hand (Amped), Distant Grasp, Gift of the Anemos — вне группы (не кнопка карточки: `[[/act]]` в тексте, условный вариант).

### M5.1 Признак и группа
Текст «Disarm/Reposition/Shove/Trip … using a spell attack roll instead of an Athletics check» у заклинаний. Настоящая группа ~115 док.: Telekinetic Maneuver (core 1 + NPC-копии 50 с текстом «Disarm, Shove, or Trip» без Reposition + 48), Magnetic Attraction (1+10; только Разоружение, при чужих/закреплённых предметах), Mage Hand (Amped) 2 и Distant Grasp 1 (Толчок, СЛ Стойкости), Vanish Weapon (реакция, Разоружение ближней атакой заклинанием), Gift of the Anemos (Толчок по желанию). Ложные: Graceful Leaper, Determined Dash (Акробатика/Атлетика в другую сторону), Sand Snatcher (бросок импульса — Захват), Disarming Shot (атака оружием), Desperate Surge (в тексте уже `[[/act … statistic=spell-attack]]` — pf2e делает сам, механизм не нужен).

### M5.2 Что умеет pf2e (правило 1.3)
- `game.pf2e.actions.get("disarm"|"reposition"|"shove"|"trip").use({actors, target, statistic, multipleAttackPenalty})` принимает **строку-slug статистики** (`SingleCheckActionVariant.use`, `pf2e.mjs:112634`: `e.statistic?.trim() || …`). Сам pf2e пишет `[[/act grapple statistic=spell-attack]]` в Desperate Surge — значит `spell-attack` поддержан; `Actor.getStatistic("spell-attack")` берёт лучшую запись колдовства (`:34445`), `getStatistic(<slug записи>)` — конкретную.
- Защита выбирается самим действием: Разоружение/Сбивание — Рефлекс, Толчок/Перестановка — Стойкость (`DisarmAction` и др.: `difficultyClass ?? reflex`); степени/заметки pf2e выводит сам.
- Каталог модуля уже имеет правила `disarm|trip|shove|reposition` (`rules/catalog.json:185-189`, степени: Сбивание — лежит, Разоружение — эффект, Толчок/Перестановка — заметки). `actions.mjs onRollMessage` берёт бросок системы с `action:<slug>` и применяет эти `byDegree`. Значит нужен только **запуск** броска, а не новая математика.

### M5.3 Предложение (малый примитив)
Поле `onUse.maneuver: {of:["disarm","reposition","shove","trip"], statistic:"spell-attack"|"<slug записи>"}` на правиле заклинания (по slug `telekinetic-maneuver@spell`, `magnetic-attraction@spell`…, без uuid — у NPC-копий свои uuid; ограждение копий `plan-copy-guard`).
- Карточка заклинания (`use.mjs`/`chat.mjs`, образец — кнопка «Бросок» `checks.rollCheck`): после сотворения — по кнопке на каждый манёвр в списке `of` (одно действие — одна кнопка, надписи — `PF2E.Actions.<X>.Title`, правило 2.3 и 3.1). Кнопка появляется, только когда шаг наступил (после сотворения, цель выбрана; правило 3.2). pf2e-кнопка «Spell Attack» на той же карточке (если pf2e её рисует по трейту `attack`) даёт бросок против КБ — это второй, **неверный** путь: скрыть штатно (проверить живьём, как скрыт у других заклинаний с rule).
- Клик: `game.pf2e.actions.get(slug).use({actors:[caster], target: цель, statistic, multipleAttackPenalty: map})`, MAP спрашивается как `checks.askMap`; цель — единственная цель карточки (`messageTargets`), иначе окно выбора цели.
- Результат: бросок системы подхватывает `actions.onRollMessage`. **Проверить**: `ROLL_TYPES` в `actions.mjs:11` содержит `attack-roll`, но не `spell-attack-roll`; если pf2e ставит `spell-attack-roll` для `statistic=spell-attack`, добавить его туда (иначе степени манёвра модуль не применит). `ruleFor` с `origin.type === "spell"` ищет правило по спеллу (`check.roll:"system"`) и падает на slug манёвра — сохранить.
- Ограничения pf2e-манёвров («нужна свободная рука», «Разоружение: цель держит предмет») — действие `disarm` pf2e проверяет само; для заклинания требования не нужны (текст: «без руки» у Vanish Weapon, Telekinetic Maneuver) — проверить, что `disarmCheckContext` не блокирует без свободной руки; если блокирует — `rollOptions` обхода или предупреждение (правило 1.1, обход Alt).
- Расстояние: дальность заклинания (60 фт у TK) — `melee-reach.mjs`-образец, `range.mjs`; вне дальности — действия нет, предупреждение.

### M5.4 Что видит ГМ
Кнопки манёвров на карточке заклинания (названия pf2e), штатная карточка броска pf2e, итог — карточка проверки модуля по каталогу (Сбивание: «Лежит»). Новые строки: максимум подпись блока «Манёвр атакой заклинания» и предупреждение «цель вне дальности» — в `lang/ru|en/use.json` (существующий).

### M5.5 Откат
Как у любого броска/эффекта модуля: удаление карточки броска откатывает применённое (`undoOps`), перебросы — штатный механизм `actions.mjs` (`stash`). Нового состояния нет.

### M5.6 Тесты

## M7. Перенос ПЗ (Spirit Link)

**Решения Руководителя и Критика (перекрывают текст ниже; реализовано `scripts/builtin/spirit-link.mjs`):** НЕ строкой `LINKS` в `damage-link.mjs` — `BY_EFFECT`/`linksOf` подхватили бы эффект и `reduction` поделил бы урон пополам; отдельный обработчик со своим slug эффекта `effect-spirit-link`, тест на `intercept` (null при таком эффекте). ПЗ заклинателя ≤ 0 проверяются ДО переноса (связь кончается), мёртвая цель пропускается. Запись ПЗ прямая; заклинатель, дошедший до 0, не получает состояний от pf2e — шёпот ГМу (связь снята, состояние вручную). Исполнитель — активный ГМ-лидер, хук `pf2e.startTurn`. Solidarity не делаем; кнопки отката нет.

### M7.1 Группа и вывод
Из 50 док. только Spirit Link (47) подходит под «в начале хода автора»: «When you Cast this Spell and at the start of each of your turns, if the target is below maximum Hit Points, it regains 2 HP … You lose as many. … ignores temporary Hit Points … no effects increase the HP regained or decrease the HP lost … if you're ever at 0 HP, spirit link ends automatically» (+2 за ранг выше). Расчёт: уникальный текст один, но 47 документов (46 — копии в актёрах Blood Lords). **Общий примитив `hp-transfer` в `rules.mjs` не нужен** (порог «группа от ~30 уникальных предметов» не набирается, остальные 3 текста — другие механики). Правильное место — таблица группы «связь жизни» в `scripts/builtin/damage-link.mjs` (`LINKS`: Life Link, Share Life, Shield Other): ещё одна строка `spirit-link` с `mode:"transfer"`. Solidarity (1 док., касание объекта, разово) — тот же код передачи как отдельная строка, если захочется (вопрос 4); Defend Life (1 док., перехват урона) и Arazni — отдельные долги, не здесь.

### M7.2 Места в коде
- `damage-link.mjs onMessage` (сотворение): эффект-метка на цели (`effectSource/addEffect`, `origin = заклинатель`, срок из `spellDuration`), как у Life Link; **передача сразу при сотворении** (первый перенос по тексту).
- Начало хода автора: хук `pf2e.startTurn` (как `events.mjs:781`) — для автора ищем метки со slug `effect-spirit-link` на актёрах боя/сцены с `origin.actor === автор` (сканирование токенов сцены, не `damage-taken`). Передача: `n = min(2·ранг, maxHP цели − ПЗ цели)`; цель +n, автор −n **прямой записью** `system.attributes.hp.value` (так выполняется условие «без сопротивлений, без модификаторов лечения, мимо временных ПЗ»; `applyDamage` pf2e это нарушил бы). Правило «не поднять выше максимума» — в `n`. 
- «Автор на 0 ПЗ — заклинание кончается»: после списания, если ПЗ автора ≤ 0 — удалить метку. «Dismiss» — удаление метки (уже работает через эффект).
- Регенерация/быстрое лечение автора на время действия отключены: шёпот-напоминание ГМу (pf2e это без RE не выразить, `ruleKeys` у копии пуст; проверить core-заклинание grep по `ruleKeys`).
- Поддержание не нужно (срок 10 минут, не sustained) — `sustain.mjs` не трогаем.
- Дубли двойного эффекта: у цели нет `RollOption`/RE на лечение — pf2e ничего не добавляет; `paHas("spirit-link")` — уступить pf2e-automations, как у остальных строк таблицы.

### M7.3 Что видит ГМ
Шёпот ГМу через `whisper()`: «Spirit Link: {цель} +{n} ПЗ, {автор} −{n} ПЗ» (строки `builtin.link.spiritLink*` в существующем `lang/ru|en/builtin.json`, названия — `item.name`); при `n = 0` — тишина; при окончании — «связь кончилась (ПЗ ≤ 0)». Нет цели при сотворении — предупреждение `builtin.link.needTarget` (уже есть).

### M7.4 Откат
Долг, как и у Life Link (в шапке `damage-link.mjs`): откат кнопкой pf2e не применим — это не урон-карточка. Предлагаю в шёпоте кнопку «Откатить перенос» (возвращает обе записи ПЗ по журналу `flags[MOD]` шёпота) — минимум; без неё — ГМ правит ПЗ руками (вопрос 5).

### M7.5 Тесты
Юнит: чистая `transferAmount(rank, targetHp, targetMax)` (2/4/6…, потолок по максимуму, цель на максимуме -> 0, автор не ниже 0), `linksOf` с новой строкой, конец связи при ПЗ автора ≤ 0, `paHas` — уступка. Живой: Spirit Link на копии — перенос при сотворении и на ходу автора; цель на полном ПЗ; временные ПЗ не затрагиваются; автор доходит до 0 -> связь снята; Dismiss; NPC-копия Blood Lords.

### M7.6 Риски
Сканирование носителей меток на каждый ход автора (цена: токены сцены); автор вне боя (ходов нет — только перенос при сотворении, как есть); цели на другой сцене.
