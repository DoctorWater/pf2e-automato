## M3. Удар NPC запускает способность из `attackEffects`

### Признак и группа
- Признак: у `melee`-предмета `system.attackEffects.value` содержит slug способности **того же актёра** (`action`/`feat`).
- Пары «Удар–способность» (всего 1218 по компендию; по `descEn` melee = список attackEffects):
  | группа | док. | уник. | что делать |
  |---|---|---|---|
  | у способности есть `onUse` | 500 | 292 (216 slug) | **M3: запускать** |
  | уже `onEvent` (Tongue Grab и др., `catalog.onhit.json`) | 60 | 18 | не трогать |
  | способность есть, правила нет | 1482 | 891 | вне плана: контент, посчитано |
  | способности нет в актёре (яд из снаряжения) | 36 | 17 | вне плана (`coat.mjs`) |
- Внутри 216 slug с `onUse`: 213 пассивные (`actionType` passive), 3 — действия (`disarm`, `feed-on-blood`, `predatory-grab`); 212 с аффликшеном (яд/болезнь/проклятие), 215 с испытанием; у 214 правило модельное (`catalog.model.json`: `onUse.challenge` + `onAttacked` + `macros`, без `onEvent`). Частоты (`frequency`) у способностей группы нет (0). Условий «on a critical hit» в тексте нет (0 из 216): крит ничем не отличается от попадания.
- Эталон: Rust Creep в `catalog.rusthenge.json` — `onEvent {on:"damage-roll", side:"self", when:["target","item:attack-effect:<slug>"], challenge:{...}}`. Форма `challenge` у `onEvent` и `onUse.challenge` одна и та же (`byDegree`, `immunity`, `affliction`), отличается `rollerRole`/`targets`.

### Решения
1. **Механизм — вывод `onEvent` из `onUse` во время чтения, без перезаписи каталога** (не 216 копий правил). В `eventRuleOf` (`scripts/events.mjs`) после `resolveRule(item)`: если правила `onEvent` нет, предмет `action`/`feat` пассивный, без `frequency`, `rule.onUse.challenge` или `.apply` есть, и у актёра есть `melee` с `attackEffects` ⊇ slug (`carrierSlug`) — собрать запись `{on, side:"self", when:["target", "item:attack-effect:<slug>"], challenge/apply из onUse}`. Ключ кэша `ruleCache` уже включает версию предмета; добавить сюда версию Ударов актёра (modifiedTime melee) или не кэшировать выведенное.
   Чистая функция `strikeLinkEntry(rule, item, strikes)` отдельно: её и тестируем.
2. **Попадание или урон: по умолчанию урон (`on:"damage-roll"`)**, как у Rust Creep. Основание: эффекты «plus» у яда/болезни действуют, когда Удар попал и нанёс урон; бросок урона делается только после попадания, цель берётся из `ctx.target`. Исключение — «при попадании» без урона: slug из текста с `hit` (по скрипту 5: `ghoul-fever`, `ghast-ghast-fever`, `ghoul-ghoul-fever`, `feed-on-blood`, `tetanus` — «takes damage») проверить глазами и, если нужно, дать признак `trigger:"hit"` (`on:"attack-roll"`, `outcome:success|criticalSuccess`, как в `catalog.onhit.json`). Решение по каждому из 5 — на этапе 1; 211 остальных — урон.
3. **Крит = попадание**: одна запись на сообщение урона (крит — то же сообщение с `outcome:criticalSuccess`), СЛ не меняется. Если появится способность с «critical hit» в тексте — запись с `when` по `outcome:criticalSuccess` (в 216 таких нет).
4. **Без дублей с `onEvent`**: вывод только при `!rule.onEvent?.length`. У 18 уникальных с `onEvent` (Tongue Grab…) и у `rusthenge` вывода нет. Юнит-тест: пересечение «выведено» ∩ «есть `onEvent`» = ∅.
5. **Без дублей со `strike-effects.mjs`**: он действует по base-slug (grab/knockdown/push/trip) и по `[[/act …]]` в тексте своей способности. Тест: для выведенных slug `effectInfo(slug, own)` = null; если пересечение найдётся (свой `tongue-grab` с `/act grapple`) — выведенную запись не строить (там уже `onEvent`, см. п.4).
6. **Одна способность — один путь (§3.3, §3.5)**:
   - Если вывод активен, карточка ГМа для этой способности (`use.mjs`, `onCreateMessage` по сообщению предмета) собирается без кнопок испытания и применения, с подсказкой «Применяется автоматически Ударом «<Удар>»» (ключ `events.strike.linked` в `lang/{ru,en}/events.json`). Обход — Alt при отправке в чат (решение ГМа), по образцу `melee-reach.mjs`.
   - Идемпотентность: ключ `entryKey(message.id, item.uuid, i)` и журнал `flags.automato.events` уже защищают от повторного исполнения; перебросы — через `rerollKey`/`undoLog`. Кнопки pf2e «Применить урон», Блок щитом, Toolbelt эту ветку не затрагивают (мы не наносим урон).
   - Три способности-действия (`disarm`, `feed-on-blood`, `predatory-grab`) вывод не получают: у них своя активность, их запуск остаётся ручным.
7. **Уступание pf2e-automations**: вывод строится из результата `resolveRule(item)`, значит, уступка по `yield`/`shouldYield` наследуется (поведение как у обычного `onEvent`). Добавить тест: slug в PA-группе -> вывода нет. Параллельно `paHas(slug)` как у `strike-effects.mjs`.
8. **Своя частота у способности**: `system.frequency` есть -> вывод не строим (расход частоты — решение ГМа через карточку, модуль частоту не тратит). В группе таких 0, но защита нужна для 891 «без правила», когда те получат правила.
9. **Режимы**: `modeOf("challenge")==="off"` — тишина (как у всех `onEvent` с `challenge`); эффекты без испытания — `modeOf("effect")`.
10. **Привязка по актёру, не по slug глобально**: в подсчёте выше был запасной поиск «любой актёр с таким slug» (`*|slug`). В рантайме связываем только по `actor.items` самого владельца Удара; число уникальных, у кого связь реально сработает, пересчитать скриптом на этапе 1 (может быть меньше 292).

### Места в коде
`scripts/events.mjs`: `eventRuleOf`, `eventItems`, `messageOptions` (опция `item:attack-effect:*` уже кладётся), `runEntry`/`execEntry`, `hostChallenge`; `scripts/use.mjs` (`onCreateMessage` — подсказка вместо кнопок); `scripts/rules.mjs` (валидатор `ev.*` — прогнать выведенные записи); `scripts/saves.mjs`, `scripts/affliction.mjs` — без правок (получают готовую запись).

### Что видит ГМ
Бой и вне боя одинаково (бросок урона не зависит от боя): после броска урона Удара с целью — обычная карточка испытания «<название способности>» с кнопками спасброска цели и наложения аффликшена (существующие). Без цели в бросок — шёпот ГМу «нет цели у Удара «X»» (существующий механизм hostChallenge; если его нет для этого случая — ключ в `events.json`). Подсказка на карточке ручной отправки — см. п.6.

### Откат
Выведенное правило ничего не хранит: выключили режим или обновили модуль без вывода — всё как было. Применённые эффекты — через журнал сообщения (удаление/переброс урона откатывает).

### Тесты
- Юнит (`tests/events.strike-link.test.mjs`): `strikeLinkEntry` — пассивная+onUse+связь -> запись; нет связи -> null; есть `onEvent` -> null; `frequency` -> null; `actionType:"action"` -> null; прогон по всем 216 slug из `items.json`+каталогов: каждая выведенная запись проходит валидатор `rules.mjs`; ∩ с `onEvent` и со `strike-effects` пусто; число выведенных = числу из скрипта.
- Живые (`tests/live/strike-link.js`, на копиях в «Тестовые копии (автоматизация)»): Ghoul (Claw + Ghoul Fever), существо с Bog Rot у Fist, Rust Creep (регрессия: одна карточка, не две); попадание+урон -> одна карточка; промах -> нет; крит -> одна; переброс урона -> прежняя откатилась, новая одна; два Удара подряд -> два независимых; ручная отправка способности -> подсказка без кнопок, с Alt -> кнопки; PA включён -> модуль молчит; несвязанный токен и связанный актёр.

### Риски
- Урон попал в иммунитет/сопротивление «весь урон»: событие `damage-roll` сработает (урон «брошен»), а по правилу эффект не должен. Решить на этапе 1: ограничиться `damage-roll` (принято у Rust Creep) либо перейти на `damage-taken` с опцией Удара — проверить, несёт ли сообщение применения `item:attack-effect`.
- Модельные правила (`catalog.model.json`) с ошибками — вывод размножит ошибку на ~290 уникальных; выборка 20 живых карточек по разным видам (яд/болезнь/проклятие) до включения по умолчанию.
- Кэш `eventRuleOf` и добавление Удара актёру: версия по melee.

## M6. Постоянное состояние без Rule Element

### Признак и группа
- Признак: текст самого существа «is permanently X / X at all times / always X», **на самом существе** (не эффект на цели), и нет `GrantItem` в правилах предмета. Широкий поиск по NPC-действиям: 121 уник. / 182 док., но почти всё — «petrified/blinded permanently» на проваливших цели (критпровал), это не про владельца.
- Группа «своё постоянное состояние» (`gap-groups.json`): **24 уник. / 65 док.** без RE: `Slow` 22 (зомби и пр., Slowed 1 + «can't use reactions»; ещё 7 уник./11 док. `Slow` уже с `GrantItem` — их не трогаем), `Natural Invisibility` 1 (Invisible; при враждебном действии Hidden — частично), `Foster Fear` 1 (это условное «Off-Guard против Frightened», вычисляемое, сюда не входит).
- Смежное, **не входит**: «когда не касается воды/земли — Slowed 1» (Water-Bound/Earthbound, ~7 уник./10 док.) — вычисляемое условие, отдельный механизм; `Perpetual Hangover` (Sickened, 1) — ниже порога (§ порог примитива ~30 док.).
- Порог: Slow 22 уник. (≈62 док.) проходит; остальное — строка таблицы данных, когда понадобится.

### Решения
1. **Таблица `slug -> {condition, value, noReactions}`** в `scripts/builtin/permanent.mjs` (данные, не код: `slow -> slowed 1 + noReactions`, `natural-invisibility`/`naturally-invisible -> invisible`). Признак по slug и по типу (`action`/`feat` на `npc`), а не по имени существа — работает для всех 22+.
2. **Состояние — через эффект модуля**, а не правку предмета: эффект «<название способности>» (имя берём из `item.name`, §2.1), правила: `GrantItem` на состояние (форма — как у 7 уник. `Slow` с `GrantItem`, снять образец из пака) и `RollOption` `NO_REACTIONS` (как «forbid» из `inline-effect.mjs`; `reactionAvailable` уже его читает). Флаг `flags.automato.meta {key:"perm:<slug>", source:"builtin"}`, `origin` — предмет. Создание через `addEffect(actor, effectSource(...), key)` из `builtin/lib.mjs` — идемпотентно по ключу. Запасной вариант: `addCondition` (политика max) + отдельный эффект запрета реакций, если GrantItem с `badge-value` не сработает.
   Почему не правка `system.rules` предмета: `GrantItem` у pf2e срабатывает только при создании предмета, правка существующего ничего не выдаст.
3. **Когда**:
   - `ready` (активный ГМ): проход по `game.actors` и несвязанным токенам всех сцен (как `spellshape.syncAll`) — уже стоящие в мире;
   - `createItem` на актёре (feat/action с slug из таблицы) — новый актёр, добавленная способность;
   - `createToken` — новый несвязанный токен (его актёр — копия дельты; эффект кладём на актёра токена);
   - `combatStart` — страховка для тех, кого не прошёл проход.
   `deleteItem` способности — снять наш эффект. Компендии и актёры вне мира не трогаем.
4. **Несвязанные и связанные**: связанный актёр — эффект на актёре (виден всем токенам), несвязанный — на актёре токена. Повторный проход пропускает актёра, у которого уже есть эффект с ключом.
5. **Решение ГМа удалить эффект вручную** уважается: после снятия модуль не навязывает его заново на этом актёре (флаг `perm.off:<slug>` на актёре; новый токен — свежий актёр, получит снова).
6. Видимость: эффект без иконки в HUD токена не обязателен — условие вычисляемое/постоянное, переключателя нет (§1.5); иконку состояния даёт pf2e.
7. Бой и вне боя: одинаково (состояние постоянное). В бою pf2e сам учтёт Slowed при количестве действий; запрет реакций — через существующий `reactionAvailable`.

### Что видит ГМ
Состояние на токене как обычное; эффект в листе — под названием способности («Медлительность» и т. п. — перевод предмета). Одна строка в чат один раз при первом применении на `ready` не нужна (шум); лог в консоль. Настройка: существующий режим эффектов (`modeOf("effect")`), новой настройки нет. Ключи при необходимости — `lang/{ru,en}/builtin.json` (`builtin.permanent.*`).

### Откат
Режим эффектов `off` -> проход снимает все эффекты `meta.key` с префиксом `perm:` (`source:"builtin"`); `GrantItem` снимает выданное состояние каскадом (`onDeleteActions.granter` в pf2e). Без модуля pf2e возвращается к тексту без состояния — как было.

### Тесты
- Юнит (`tests/builtin.permanent.test.mjs`): таблица по всей группе из `items.json` (22 slug `slow` + invisible), `needs(item)` — нет при наличии `GrantItem`; построение `effectSource` (правила GrantItem+NO_REACTIONS); идемпотентность по ключу; очистка по префиксу.
- Живые (`tests/live/permanent.js`): зомби-копия связанная и несвязанная (Slowed 1 и запрет реакций видны, реакция Удара не открывается); токен до включения модуля (проход на `ready`); новый токен; удалить эффект руками -> не возвращается; выключить режим -> всё чисто; существо с готовым `GrantItem` — без двойного Slowed.

### Риски
- `GrantItem` без владельца-предмета и значение бейджа (`alterations`) — проверить на образце pf2e до реализации.
- Проход на `ready` на больших мирах: ограничить актёрами, у кого есть предмет из таблицы (O(items) один раз).
- «can't use reactions» для не-NPC (редкий случай) — тот же эффект.

## M8. «Следующее сотворение» у NPC: Reach Spell и родня

### Признак и группа
- NPC-действия/черты с трейтом `spellshape`/`metamagic`: **70 уник. / 104 док., 32 slug**; из них RollOption-правило (переключатель pf2e) только у 13 уник.
- Текст «если следующее действие — Cast a Spell…» (NPC `action`/`feat`): 53 уник. / 72 док.; более широкое «next action …» (включая Strike, прыжок) — 91 уник. / 122 док. (не берём).
- По потребителю в коде:
  | подгруппа | уник./док. | есть потребитель |
  |---|---|---|
  | Reach Spell (+30 фт дальности) | 21 / 30 (+1 PC-черта) | да: `range.mjs` `hasReachSpell`, `use.mjs` `casterOptions` |
  | Quickened Casting (−1 действие) | 17 / 30 | нет (цена действия) |
  | Widen Spell (область) | 2 / 5 | нет (`use.mjs:539` — шёпот ГМу) |
  | Conceal Spell, Director's Magic, Quiet Confidence (subtle) | ~4 / ~6 | нет |
  | Overwhelming Energy (игнор сопротивления 20) | 2 / 2 | нет |
  | Energy Shift, прочие единичные | ~25 / ~30 | нет |
- Пересечение с PC-метамагией: 11 slug NPC совпадают с PC-slug (75 док.), 21 — только NPC.
- У PC-метамагии механизм есть (`spellshape.mjs`: переключатель -> эффект с `RollOption`, «потрачен сообщением», снятие следующим сотворением и концом хода), а `next-cast` в долге (22 уник., `rules/mechanisms.json`, `coverage.md`) — это про эффекты, **накладываемые модулем на цели** (`afterUse` + `spell-cast`, Lingering Composition), не про опции заклинания.

### Решения
1. **Не делать общий примитив «следующее сотворение» для всей группы.** Из 53 уник. потребитель есть только у Reach (30 док.); у остальных нужен свой движок (цена действия, область, сопротивления) — каждый подгруппа < порога ~30 док. и отдельное изобретение. Они остаются долгом, число — выше.
2. **Reach у NPC — расширить источник опции в `spellshape.mjs`**: сейчас опция берётся только из флага `flags.automato.spellshape` (его ставит `migrateItem` из переключателя). Добавить вывод по требованию: `optionOf(item) = флаг ?? derive(item)`, где `derive` — для `feat`/`action` с трейтом `spellshape|metamagic` без переключателя и slug из набора `{reach-spell}` -> `reach-spell` (подопция pf2e = slug). Набор из одной строки; следующий потребитель (widen, когда появится движок области) — добавить slug.
   Ничего не пишем в предмет (никакой миграции) — флаг не нужен, откат нулевой.
3. **Дальность через `range.mjs`**: без правок — `hasReachSpell` уже читает `spellshape:reach-spell`; `itemRange(spell, opts)` даст +30. `rules/ranges.json` для Reach не нужна (там дальность способностей-предметов, а не модификатор заклинания); проверить, что NPC-заклинание не имеет записи в `ranges.json`, перекрывающей `range`.
4. **Работа в бою и вне боя**: как у PC — в бою эффект до конца хода, вне боя до следующего сотворения. Используется то же `combatOf`/`UNTIL_TURN_END`.
5. **Несвязанные токены/уже стоящие в мире**: ничего не мигрируем, так что проход не нужен; работает на первое использование.
6. Режим: тот же `mode.macro` (при `off` — ничего не выводится, как у `syncItem`).
7. Дубли: если у NPC-версии Reach есть pf2e-переключатель (2 из 21 уник.), работает прежний путь (`stripToggle` -> флаг) — `derive` вторым не включается (приоритет флага).

### Что видит ГМ
Как у PC: нажал «Дальнее заклинание» у NPC -> эффект «Дальнее заклинание» на токене + шёпот-подсказка (`builtin.spellshape.hint`, `builtin.spellshape.effect`, `builtin.spellshape.spent` — существующие ключи, ничего нового). Заклинание дальше обычной дальности, но в +30 — не помечается «вне дальности».

### Откат
Состояния нет, только эффект с `meta.key=spellshape` — снимается существующей логикой (следующее сотворение / конец хода / режим `off` -> `syncAll(off)`).

### Тесты
- Юнит (`tests/builtin.spellshape.test.mjs`, расширить): `derive` по всем 21 уник. NPC Reach из `items.json` даёт `reach-spell`; предмет с переключателем — флаг приоритетен; `quickened-casting`, `widen-spell` — null; `effectRules("reach-spell")`; `maxRange(range, false, ["spellshape:reach-spell"])` = +30; `recentShape` с выведенной опцией (гонка «нажал и сразу сотворил»).
- Живые (`tests/live/spellshape-npc.js`): копия NPC с Reach Spell (без переключателя) — нажать, заклинание с дальностью 30/60 по цели на дальности 30+Δ и 60+30 проходит, на 60+31 — `far`; второе сотворение уже без бонуса (эффект «потрачен», затем снят); конец хода в бою; вне боя до следующего сотворения; несвязанный токен.

### Риски
- Имя опции у pf2e для NPC-версии может отличаться от slug (`reach-spell` у PC): сверить на образце NPC (если `Reach Spell` NPC без RE — наша опция единственная; если есть чужая — не двоить).
- `casterOptions` читает `rollOptions.all` актёра — для несвязанного токена нужен актёр токена; проверить в живом прогоне.
- Quickened Casting (30 док.) остаётся без автоматизации: цена действия не управляется модулем.
