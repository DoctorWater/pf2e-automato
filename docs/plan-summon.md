# План: призыв существ (черта summon)

Статус: **проект v1, код не писан.** Запрос пользователя 2026-11-06: «Призыв нежити» — механизм под группу; выбор бестиариев — настройка мира (по умолчанию все бестиарии, можно выбрать другие компендиумы).

## Группа

Черта `summon` / текст «You summon a creature…»: ~150 документов — 42 заклинания `spells-srd` (Summon Undead/Animal/Fey/Fiend/Dragon/Elemental/Construct/Plant or Fungus/Entity/Celestial/Giant/Monitor/Lesser Servitor, Phantasmal Minion…), 19 черт, предметы, способности NPC. Механизм — общий; данные (признак существа, базовый уровень) — генератором по `descEn`, как `rules/ranges.json`.

## Правила (pf2e, описание черты summon)

- Существо с признаком X и уровнем ≤ L, где L — по рангу заклинания по таблице черты `summon`: ранг 1 → −1, 2 → 1, 3 → 2, 4 → 3, 5 → 5, 6 → 7, 7 → 9, 8 → 11, 9 → 13, 10 → 15 (у заклинаний с иным базовым уровнем — сдвиг по тексту, «whose level is 5 or lower» на 5 ранге).
- Существо получает признаки `summoned` и `minion`; приспешник действует, только когда призыватель тратит на него действие (Поддержание): **2 действия** в ход призывателя, без реакций, если не указано иное.
- Срок — длительность заклинания (обычно «sustained up to 1 minute»): кончилось Поддержание / «Прекратить» / истекло — существо исчезает.
- Дальность — дальность заклинания (обычно 30 фт) до места появления.

## Механизм

1. **Настройка мира `summon.packs`** — список компендиумов-источников (Actor). Значение по умолчанию `[]` = «все бестиарии»: Actor-компендиумы системы pf2e, чьё имя содержит `bestiary`/`monster-core`/`npc-core` (вычисляется в рантайме, новые бестиарии подхватываются сами). Меню настройки (`game.settings.registerMenu`) — список всех Actor-компендиумов мира (система, модули, мир) с флажками; бестиарии отмечены по умолчанию; кнопка «Все бестиарии» возвращает `[]`. Строки — `lang/{ru,en}/settings.json`.
2. **Данные правила** — поле `onUse.summon: { trait, level }` (`level` — базовый для минимального ранга; рост — таблица черты). Генератор `tools/summons.mjs` → `rules/summons.json` (по uuid источника/slug), вливается в `resolveRule` нижним слоем, как `ranges.json` (пак W3). Валидатор поля.
3. **Карточка** — кнопка «Призвать» (одна кнопка в один момент: после сотворения; после призыва скрыта). Окно выбора: существа из выбранных компендиумов (`pack.getIndex({fields: ["system.traits.value", "system.details.level.value"]})`, кэш на сессию), фильтр по признаку и уровню ≤ L, поиск по имени, сортировка по уровню.
4. **Размещение** — щелчок по сцене (как превью шаблона), в пределах дальности от токена автора (обход Alt, как у областей). Актёр импортируется из компендиума в папку мира «Призванные (автоматизация)» один раз (повторно — тот же), токен несвязанный, disposition автора, владение — владельцам автора. Эффект «Призванное существо» (признаки `summoned`, `minion`, ссылка на заклинание).
5. **Бой** — если автор в бою: участник добавляется с инициативой сразу после автора.
6. **Срок** — токен привязан к якорю Поддержания сотворения (`sustain.attach`, список призванных во флаге якоря); конец якоря (пропуск, «Прекратить», истечение) — токен и участник боя удаляются у активного ГМа. Не-поддерживаемые сроки (раунды/минуты) — по эффекту «Призванное существо» с длительностью: истёк — удалить токен.
7. **Права/исполнение** — выбор и размещение на клиенте игрока, создание токена и актёра — у активного ГМа (`callGM`, проверка владельца автора).

## Дополнения v1 (запрос пользователя 2026-11-06)

8. **Два действия приспешника.** Поддержание заклинания призыва (кнопка якоря или действие «Поддержание» с листа) даёт призванному 2 действия в этот ход: шёпот владельцу с напоминанием и, если включён `pf2e-auto-action-tracker`, отметка 2 доступных действий у участника-приспешника (или эффект «Приспешник: 2 действия до конца хода»). Без Поддержания в этом ходу приспешник не действует (напоминание в начале его хода в бою: «ждёт команды»).
9. **Несколько существ.** Заклинания/способности с «summon up to N» / «two creatures» / повышением на число существ — окно выбора разрешает N существ (по одному или повторы), размещение по очереди; все привязаны к одному якорю; Поддержание командует всеми (у каждого 2 действия? — по тексту правил; проверить у Критика).
10. **Токены из FA Nexus** (модуль `fa-nexus`, если включён). Поиск токена в каталоге Nexus по имени существа (английское `flags.babele.originalName`/slug), лучший кандидат по совпадению имени; файл — через сервис Nexus (`scripts/content/nexus-content-service.js`: `list("tokens")`, `getFullURL`) с загрузкой в мир по правилам Nexus; премиум без подписки — пропуск. Нет совпадения / Nexus выключен / ошибка — штатный токен актёра из компендиума. Настройка мира: «Токены из FA Nexus» вкл/выкл.

## Вне объёма v1 (долг)

Черты и способности NPC с нестандартным текстом (генератор помечает «не распознано»).

## Проверка

Юнит: генератор (признак/уровень по тексту), таблица уровней по рангу, фильтр индекса, значение настройки по умолчанию. Живой: Призыв нежити у «Тест: Марена» — окно (только нежить ур. ≤ −1 из бестиариев), размещение в 30 фт, признаки, инициатива после Марены, «Прекратить» → токен исчез; настройка без бестиариев → список пуст с подсказкой.

## v2 — правки по Критику (2026-11-06), перебивают текст выше

**Группа и данные.**
- Заклинаний с чертой summon в `spells-srd` — 14 (не 42); summon-anarch/axiom (легаси, chaotic/lawful) — в исключения; incarnate (healing-servitor, irii, stampede, elemental-herald, warden-of-the-wild, ancient-fleshforged, oliphaunt) — не приспешники, долг.
- Поле правила `onUse.summon`: `{ traits: [..] }` (ИЛИ: plant/fungus; lesser-servitor — celestial/fiend/monitor/animal) | `{ uuid }` (конкретное существо: phantasmal-minion, gray-shadow); необязательные `levels` (таблица ранг→уровень, у lesser-servitor своя, потолок 3 с 4 ранга), `count`. Уровень по умолчанию — таблица черты summon (1→−1, 2→1, 3→2, 4→3, 5→5, 6→7, 7→9, 8→11, 9→13, 10→15), из текста не разбирается (в items.json минус испорчен). Генератор `tools/summons.mjs` — явный список с исключениями → `rules/summons.json`, оверлей в `resolveRule` (как `ranges.json`).

**Ограничения черты summon (§1.1).** Только `common` (rarity в индексе); только `npc` (не hazard/loot); место свободно и вмещает существо (`findSpot`/`hit` из `builtin/onyx-dog.mjs`); призванное не призывает; у призывателя не больше 4 приспешников; дальность — `itemRange`.

**Источники существ.** Мировая настройка `summon.packs`: пусто = по умолчанию — бестиарии pf2e из настроек браузера компендиумов pf2e (`game.pf2e.compendiumBrowser` вкладка bestiary, `compendiumBrowserPacks`), без дублей легаси/ремастер не трогаем (решает ГМ флажками); меню — флажки по всем Actor-компендиумам. Индекс (npc, common, traits, level) строит ГМ (у игроков паки LIMITED), кэш на сессию.

**Существо.** Мировой актёр-источник импортируется один раз в папку «Призванные (автоматизация)», владелец — только ГМ; права игрока — через `delta.ownership` токена (несвязанный токен). Эффект «Призванное существо» с RE `ActorTraits add [summoned, minion]` (без minion pf2e считает его в бюджете встречи). Ключ флага — `flags[MOD].summoned` (не `summon` Ониксовой собаки: её `expire/dismiss` смотрят тот ключ).

**Жизненный цикл.** Якорь Поддержания хранит список призванных (uuid токенов). Конец якоря → удалить токены и участников боя. Токен: 0 ОЗ → изгнан (удалить, якорь подрезать `prune`); удалён вручную/вместе со сценой → подрезать якорь. На `ready` у активного ГМа — уборка призванных без живого якоря. Повтор: ключ идемпотентности (сообщение + номер существа) во флаге якоря до создания (callGM без автоповтора).

**Бой и действия приспешника.** Сразу по сотворении призванное тратит 2 действия (шёпот владельцу). Дальше — только когда призыватель Поддерживает (кнопка/действие): 2 действия у каждого приспешника этого заклинания, реакций нет; повторное Поддержание в ход — ничего. Участник боя есть (ОЗ, эффекты), инициатива сразу после призывателя с явным приоритетом (`setInitiative` + priority), пометка «ходит только по Поддержанию». Трекер действий не трогаем (своего API нет) — шёпот/эффект «Приспешник: 2 действия».

**Несколько существ** (запрос пользователя, хоть и ниже порога): `count` из правила/повышения → окно позволяет выбрать N, размещение по очереди, общий якорь, предел 4 приспешника.

**FA Nexus** (необязательно, у ГМа, после создания токена — подмена `texture.src`, сбой → штатный токен): ступень 1 — уже скачанные файлы Nexus в `cloudDownloadDirTokens` (`FilePicker.browse`), подбор по имени существа; ступень 2 (настройка «Скачивать из каталога FA Nexus», выкл. по умолчанию) — сервис Nexus из его модуля (`list("tokens")` → скачать в ту же папку), только если каталог Nexus синхронизирован у ГМа; версию Nexus сверять в `compat.EXTERNAL`.

## Паки реализации (параллельно, файлы не пересекаются; интерфейсы ниже)

- **S1 данные и источники:** `tools/summons.mjs`, `rules/summons.json`, `scripts/rules.mjs` (оверлей + валидатор `onUse.summon`), новый `scripts/summon-index.mjs` (`summonPacks()`, `buildIndex()`, `candidates({traits, uuid, maxLevel})` — npc, common, сортировка), настройка и меню в `scripts/settings.mjs` + `lang/{ru,en}/settings.json`, тесты.
- **S2 призыв:** новый `scripts/summon.mjs` (кнопка на карточке, окно выбора, размещение, `callGM` создание, эффект, права, бой, жизненный цикл, действия приспешника, лимиты), подключение в `scripts/main.mjs` (`init` + обработчик `gm()`), хук в `scripts/sustain.mjs` (конец якоря → призванные), `lang/{ru,en}/use.json`, тесты. Использует S1 (`candidates`) и S3 (`nexusToken`) по интерфейсу.
- **S3 токены Nexus:** новый `scripts/nexus-tokens.mjs` (`nexusToken(actor) -> Promise<src|null>`), запись в `compat.EXTERNAL`, настройка (через S1? — нет: своя регистрация в своём файле на `init`), тесты чистого подбора имени.

## v3 — по живой проверке (2026-11-06)

- **В бой призванное не добавляется.** С признаком `minion` участник боя не создаётся (проверено вживую: тот же токен без `minion` встаёт в бой, с `minion` — `createEmbeddedDocuments("Combatant")` возвращает пусто). По правилам приспешник и не ходит сам — действует в ход хозяина по Поддержанию. ОЗ/эффекты живут на токене; 2 действия — шёпот при сотворении и при каждом засчитанном Поддержании.
- Отношение (disposition) токена — как у токена призывателя (у копии «Тест: Марена» прототип враждебный — это данные копии).
