## 4. Решение: минимальный набор изменений

### 4.1. Схема (публичная часть)

1. `sustain: true` на шаге `condition|effect` = «выданное этим шагом привязано к поддержанию: снимается, когда поддержание кончилось». `sustain: false` = явно «переживает конец заклинания» (Сад исцеления: +1 против эмоций после конца). Отсутствие = прежнее поведение (без регрессий каталога). Валидатор менять не нужно, кроме запрета `sustain:true` вне шагов заклинания (`rule.onUse`/`onEvent` предмета-заклинания) — опционально.
2. `EVENT_ON` (`rules.mjs:589`) += `"spell-sustain"`, `"spell-end"`. Только `side:"self"`, без цели (`EVENT_TARGETED` не меняем). Остальные поля записи (`when`, `apply`, `challenge`, `once`) — как есть. Не новый примитив, а два значения перечисления; i18n: подписи в `lang/*/rules.json`, форма `sheet.mjs`, Мастерская — по циклу §1/§2/§6.
3. Предикаты `when`: опции события `sustain:first` (самое первое Поддержание), `sustain:count:N`, `spell:rank:N`, `spell:end:<dismiss|missed|expired>` (для `spell-end`) + опции самого заклинания `item:*` (там `item:trait:hex` — нужно для L1-W02). Мельче — не вводить.

### 4.2. Рантайм (внутренняя часть, новый файл `scripts/sustain.mjs`)

**Якорь поддержания** — один эффект-носитель на авторе: «Поддержание: <заклинание>» (`duration.sustained:true`, срок = `itemDuration` заклинания, `expiry:"turn-end"` от автора; без правил). Создаётся через `applyInlineEffect` (`apply.mjs:54`; проверить, что допустим пустой `mods` — спайк). `flags[MOD].meta = { key:"<castMsgId>:sustain", source:"sustain", sustain:{ msg, src, slug, rank, castRound, doneRound, count, combat, bound:[{actor,key}], affected:[uuid] } }`.
Якорь создаётся лениво и идемпотентно по `key`: (а) на первом выполненном шаге `sustain:true` (`applyOps`, `scope:"apply"|"challenge"`), (б) на `spell-cast`, если правило заклинания содержит запись `spell-sustain`/`spell-end` (Желчь земли без эффектов на цели). Условие — только по правилу, поэтому ни один из 460 документов не получает якорь без явного opt-in каталога.
Выбор «конкретного поддерживаемого использования» = выбор якоря; два использования одного заклинания = два якоря.

**Привязка выданного.** Шаг с `sustain:true` пишет `meta.sustainOf = anchorKey`; `{actor,key}` добавляется в `anchor.bound`. Дедуп уже обеспечивают `findByKey`/`hasEffect` (`apply.mjs:26-39`): cast и Поддержание того же раунда не удваивают эффект.

**Конец якоря** (`deleteItem` с `meta.source==="sustain"`, подписка рядом с `events.mjs:672`, `options?.[MOD]?.undo` игнорируем):
1. причина: флаг `endReason` (ставим сами при пропуске/кнопке) иначе `item.isExpired` -> `expired`, иначе `dismiss`;
2. снять все `bound` (`removeCarrier` -> каскад на GrantItem-состояния, `apply.mjs:273`); недоступный актёр -> предупреждение ГМу, не молчаливый пропуск;
3. запустить `spell-end` (опции `spell:end:*`), по одному запуску на каждого из `anchor.affected` как `other` (как цели сотворения, `events.mjs:569-574`) — этим выдаётся «после конца» (Сад исцеления).

**Поддержание** (`sustain.run(anchorKey, by)`, только активный ГМ, очередь `queue("sustain:"+key)`, `fired` по `key:round`):
- раунд боя = `game.combat.round`; если `doneRound === round` (сотворено в этом раунде или уже поддержано) — ничего, мягкая подсказка. Это и есть «первое Поддержание за раунд» и «cast+sustain в одном раунде без дубля»: событие не больше одного за раунд на якорь;
- иначе `doneRound = round`, `count++`, запуск `spell-sustain` через `runEvent`/`actorEvent` (`events.mjs:476,618`), записи берутся из снимка правила в сообщении сотворения (`flags[MOD].use.rule`), при удалённом сообщении — `rules.resolveRule` по `src`; фильтр: запись принадлежит именно этому заклинанию, а не любым `onEvent` актёра;
- фокус/ячейку НЕ трогаем: путь не вызывает `SpellcastingEntry.cast/consume`; на сообщение Sustain расход не навешан и у pf2e (`pf2e:111695`). `refundFocus` не затрагивается;
- вне боя (нет раунда): Поддержание срабатывает по клику без учёта `doneRound` (идемпотентность — окно 6 с по ключу), пропуск не определяем (ручной, п. 7).

**Откуда приходит «поддержано»** (источники безвредно дублируют друг друга благодаря `doneRound`):
1. кнопки «Поддержать / Прекратить» на шёпот-карточке `card()` автору при создании якоря (стиль — `ui-style-guide`); карточка обновляется после каждого Поддержания; игрок нажимает — клик идёт к активному ГМу тем же путём, что кнопки карточек use (`scripts/chat.mjs`, `main.mjs:108` socketlib);
2. (этап 1б, опция) разбор сообщения pf2e «Sustain»: `createChatMessage` без `flags.pf2e.origin`, `h4.action` = `game.i18n.localize("PF2E.Actions.Sustain.Title")`, автор = speaker; срабатывает только при ровно одном якоре у актёра, иначе подсказка выбрать карточкой. Включаемая настройка (`scripts/settings.mjs`), по умолчанию выключена: язык/шаблон pf2e могут измениться;
3. `Прекратить` = `endReason:"dismiss"` + удаление якоря; удаление эффекта вручную равнозначно.

**Пропуск.** `pf2e.endTurn` (расширить `events.mjs:669`): для якорей автора `doneRound < encounter.round` -> `endReason:"missed"`, удалить якорь. Страховка пропущенного хода: `pf2e.startTurn` (`events.mjs:668`) -> `doneRound < round-1` -> то же (на `skipped` pf2e `endTurn` не вызывает, `pf2e:26634`). Конец боя (`deleteCombat`) не снимает якоря (срок — по часам); вопрос 3 п. 8.

**Лишнее не делаем:** ни счётчика «зеркал» (Trickster's Mirrors — на `sustain:count:N` в своём правиле), ни автопарсинга текста Sustain из HTML (`derive` ненадёжен, `markup-derive-unreliable`).

### 4.3. Пульс (повторное действие заклинания при Поддержании)

Для заклинаний с областью/выбором (Желчь земли, Сад исцеления) `onEvent`-запись не подходит: у события нет области (`rules.mjs`, проверка `move.bad`: «у события нет области»). Решение этапа 3 — запись `spell-sustain` содержит `apply`/`challenge` без области там, где это возможно (лечение эманации автора, `to:"allies"`+`range`), а для настоящей области — **повторный запуск `onUse` исходного правила** как шёпот-карточка use с готовым снимком (путь `buildSnapshot`, `state.awaitingRegion`, как у расходников и активаций, `use.mjs` ~50-60; хост-карточки уже создаёт `hostChallenge`, `events.mjs:257`). Это спайк: если `awaitingRegion` не подходит без новой схемы — Желчь земли остаётся «ГМ ставит шаблон вручную по подсказке-карточке», без нового поля. Выбор принимается по итогам спайка; публичное поле для этого не вводим без группы ≥30 (по `items.json` area+Sustain-повтор — единицы: Earth's Bile, Wildfire и т.п.).

## 7. Риски и ручное ГМу

- Сообщение Sustain pf2e не структурировано; без кнопки/настройки Поддержание модулю неизвестно -> «кнопка — основной путь» (п. 4.2).
- Вне боя пропуск не определить; `pf2e.endTurn` не вызывается при skipped/delay; игрок без активного ГМ — всё стоит (как и прочий `onEvent`, `guardActiveGM`).
- Повторный cast того же заклинания тем же автором: по умолчанию создаётся второй якорь; одинаковые эффекты дедупятся `hasEffect`. Автоматического «второй cast прекращает первый» нет — ГМ.
- Удаление якоря при нескольких клиентах/зависшем Foundry: возможны привязанные эффекты без якоря -> безопасная проверка «осиротел» при `ready` (спайк, не обязательна).
- Размер: якорь — предмет-эффект, виден игроку; иконка/имя по `ui-style-guide`.
- Остаётся вручную: сюжетные условия поддержания (концентрация, дальность, «пока цель видима»), условия «не может Поддержать» (оглушён, без действия), выбор цели в нестандартных Sustain-эффектах, 8-часовой режим Workshop.

## 8. Открытые вопросы пользователю

1. Принимаем кнопку на шёпот-карточке как основной «Поддержать» (pf2e этого события не даёт), а разбор чата — необязательной настройкой?
2. Якорь как видимый эффект на авторе («Поддержание: X») — приемлем, или хранить состояние в флагах актёра без предмета (тогда нет иконки/автоистечения pf2e)?
3. Конец боя: снимать ли якоря с `sustained` при завершении боя (правила неоднозначны; по умолчанию — нет)?
4. Повторный cast того же заклинания тем же автором: оставлять оба якоря (по умолчанию) или заменять прежний?
5. Допустим ли спайк пульса с областью (п. 4.3) с запасным «ручным» вариантом?

3. Пропуск: `endTurn(R+1)` при `doneRound=R` -> `missed`; при `doneRound=R+1` — нет; `startTurn(R+2)` при `doneRound=R` -> `missed` (пропущенный ход); у чужого автора — нет.
4. `endReason`: явная > `isExpired` > `dismiss`.
5. Привязка: ключ `meta.key` уникален на шаг и якорь; повторное применение (cast+sustain, переброс) — `skipped`; `sustain:false` не пишет `sustainOf`.
6. Конец якоря: список `bound` снимается; недоступный актёр -> предупреждение, остальные сняты; `spell-end` по `affected` — один запуск на цель.
7. Фокус: путь Поддержания не вызывает расход (макет `consume` не вызван).
8. Opt-in: правило без `sustain:true` и без `spell-*` записей якоря не создаёт.
9. Каталожный тест (в `tests/level1-catalog.test.mjs`): каждая запись с `sustain:true` относится к заклинанию с `duration` sustained; Information Overload не имеет `duration` без привязки (регрессия C01).

## 10. Живые сценарии (по одному, вкладка ГМа; «AF тест»)

1. Information Overload: cast -> провал Will -> Поддержание R+1 -> пропуск R+2 -> stupefied снят, якорь удалён; затем «Прекратить»; затем истечение минуты (`game.time.advance`).
2. Cast и Поддержание в одном раунде: нет второго пульса/дубля эффекта; фокус сверен до/после.
3. Игрок-владелец жмёт «Поддержать» без ГМ-вкладки игрока (через сокет) и с двумя якорями (две карточки).
4. Garden of Healing: cast -> пульс; Поддержание R+1 -> пульс; конец -> бонус только исцелённым; новый cast во время бонуса не лечит.
5. Earth's Bile (после спайка): область на cast и на Поддержание.
6. Пропущенный ход (skip/delay) и вне боя: поведение по п. 7.
7. Повторный запуск карточки описания и перебросок Will не создают событий и не дублируют привязку.

## 11. Статус реализации

### Волна 1 (сделано) — `scripts/sustain.mjs`, точечно `apply.mjs`, `rules.mjs`, `main.mjs`
- **Якорь** — эффект «Поддержание: <заклинание>» на авторе, свой slug `sustain-<slug>` (не `af-…`), `meta.source:"sustain"`, `meta.message:"ev:sustain"` (onEvent его не гоняет), `duration.sustained:true`, срок = `itemDuration` или 10 минут; данные в `flags[MOD].sustain` = `{msg, src, actors[], last:{combat,round}}`. Создаётся на первом выполненном шаге `sustain:true` (ключ `<msg>:sustain`, идемпотентно); второе сотворение = второй якорь. Системный эффект заклинания якорем НЕ делается (Workshop: вторая модель срока и режим 8 ч) — ponytail, волна 2.
- **Привязка**: шаг `sustain:true` пишет `meta.sustainOf`; создание якоря — отдельная операция журнала `{op:"anchor"}`. Откат (`undoOps`) удаляет привязку, а когда живых привязок не осталось — якорь с `{[MOD]:{undo:true}}` (без «конца заклинания»).
- **Валидатор**: `condition` с `sustain:true` требует `duration` (`apply.sustainDur`); `sustain:false` = отсутствие поля (маркер сохраняется в правиле, рантайм его не читает).
- **Конец** (кнопка «Прекратить», пропуск, срок, ручное удаление): `deleteItem` якоря → `apply.removeBound` (по `meta.sustainOf`, через `dropEffects`, не `removeCarrier`); недоступный актёр — предупреждение ГМу. Конец боя якорь не снимает.
- **Шёпот** автору и ГМу (`whisper()`/`card()`, тег `sustain`) с «Поддержать / Прекратить»; клик — `callGM("sustainRun")`, проверка владельца как у `applyRetch`. «Поддержать» сама выкладывает pf2e Sustain (`game.pf2e.actions.get("sustain")`), записывает `last`; повтор в том же раунде срок не продлевает и не блокируется.
- **Разбор чата** (настройка `sustain.parse`, по умолчанию вкл.): SimpleAction (h4.action) и действие с листа (`origin.slug === "sustain"`); засчитывается единственному якорю автора, при нескольких — шёпот ГМу; идемпотентно по флагу `sustainSeen` на сообщении.
- **Пропуск**: `pf2e.endTurn` автора (раунд хода — `combatant.flags.pf2e.roundOfLastTurnEnd`: хук приходит уже после перехода хода; не тот `{combat, round}` = пропуск), страховка — `pf2e.startTurn` активного ГМа и `leader.onLead`; бой берётся тот, где автор участник, а не `game.combat`; `last` при создании якоря — момент сотворения (`use.at`); `isExpired` проверяется при Поддержании и в конце хода; ГМу — шёпот со списком снятого. Вне боя пропуск не определяется (ponytail: срок якоря ограничивает).
- **Потребители**: Information Overload (`PesUKf0lIt5zRofj`, stupefied 1/2 на 1 мин, `sustain:true`), Clinging Ice (`MraZBLJ4Be3ogmWL`, эффект `2sMXAGZfdqiy10kk`, ChoiceSet -5/-10 фут., `sustain:true`) — `rules/catalog.json`.
- Тесты: `tests/sustain.test.mjs` (якорь/привязка/конец/пропуск/другой бой/повтор/откат/разбор чата), `tests/sustain-rule.test.mjs` (валидатор), `tests/level1-catalog.test.mjs`.

### Не сделано (долг)
- События `spell-sustain` / `spell-end` в `EVENT_ON`, предикаты `sustain:first|count:N`, `spell:end:*` (этапы 2–3 §5).
- `sustain:count` (Trickster’s Mirrors), пульс с областью (§4.3: Earth’s Bile), Garden of Healing (бонус «после конца» по `affected`), Cackle.
- Перевод действующих sustained-записей каталога на `sustain`: Calm, Shroud of Night, Forbidding Ward, Figment (и остальные из ≈460 по `duration`).
- Traveling Workshop: якорь = его системный эффект; режим 8 ч.
- Страховка пропущенного хода — `pf2e.startTurn` активного ГМа и `onLead`; осиротевшие привязки при `ready` не чистятся; карточка-шёпот после Поддержаний не обновляется.
- Живые сценарии §10 не прогонялись (Foundry недоступен).
