## 2. Что уже делают pf2e и Foundry

- **pf2e знает Take Wing сам.** Правила: `RollOption take-wing` (toggleable, `not feat:into-the-sky`) + `BaseSpeed fly 15` под `predicate:[take-wing]`. Zip! Zoom! = `BaseSpeed fly 25` под тем же `take-wing` (pf2e берёт максимум кандидатов, `selectCandidate`, `pf2e.mjs:34656`) — поэтому «15 → 25» и «если уже есть полёт — не давать» pf2e решает сам. Into the Sky = постоянный `BaseSpeed fly 25` (в паке selector записан как `fly-speed`, не `fly` — проверить, не опечатка pf2e; наша забота, только если живой прогон покажет скорость 0).
- **Нет авто-включения.** Переключатель на листе игрок ставит вручную и сам снимает; фит не выключается после перемещения. `selfEffect` у всех девяти пусто (`items.json`) → при клике pf2e шлёт лишь карточку и списывает частоту (`createUseActionMessage`, `pf2e.mjs:54100`).
- **Foundry v14 / pf2e и скорости.** Тип движения токена (`walk/fly/swim/climb/burrow/crawl/step`) → `system.movement.speeds[тип].value` (`pf2e.mjs:120700-120709`; `walk`→`land`). Линейка pf2e сама считает действия по выбранному типу; тип без скорости не выбирается. Значит, как только на актёре есть скорость `fly` — игрок выбирает «Полёт» в HUD токена, ничего больше не нужно.
- **Падение pf2e не автоматизирует** (grep: только текст описаний; урона от падения и проверки опоры нет).
- **Модуль.** `effect.mods` имеет вид `speed` (только бонус к скоростям, `FlatModifier all-speeds`), вида «новая скорость» (`BaseSpeed`) **нет**. Срок эффекта с `{value:0, unit:"rounds", expiry:"turn-end"}` уже допустим (`rules.mjs:101`, `apply.mjs:468-471`) = «до конца хода». Хук `moveToken` уже слушает `events.mjs:803` (входы в ауры). `height.mjs` — только высота токена по региону при входе; полёта, падения и «твёрдой земли» в нём нет. `move.mjs` — принудительное перемещение, к теме не относится.

## 3. Можно ли собрать Take Wing правилом каталога уже сейчас

Нет, не полностью. Эффект на себя `BaseSpeed fly 15` до конца хода не соберётся: вида `BaseSpeed` в `mods` нет. Чего не хватает:

1. Вид `BaseSpeed` (тип движения + значение/формула) в `inline-effect.mjs` + блок в Мастерской.
2. Срок «до конца хода» — **есть**.
3. «На одно перемещение»: снять после первого перемещения токена — **нет**.
4. «Если уже есть скорость полёта — не давать» — **не нужно**: `BaseSpeed` pf2e берёт максимум.
5. Усиление Zip! Zoom! — **бесплатно при условии, что эффект включает тот же `RollOption take-wing`** (иначе предикат Zip! Zoom! не сработает, а наш `BaseSpeed 15` его не заменит). См. §5.1: эффект модуля несёт и `BaseSpeed`, и опцию фита; родной переключатель не щёлкаем, скрываем общим механизмом (§5.2).
6. Само действие уже блокируется «раз за раунд» — см. §4.

## 4. Ограничение «once per round»

`impulse-gate.mjs`: строка `frequency` (`LIMITS`) применима, если у предмета есть `system.frequency`, в бою (`c.inCombat`) для `per: round|turn`; вне боя не блокирует (идёт доработка). У девяти предметов `frequency: 1/round` (кроме `benefactors-wings` — частоты в данных нет, в тексте её тоже нет: проверить по `descEn`, блок не нужен). Точка (2) `preCreateChatMessage` ловит карточку использования любого `feat/action` с `USE_TYPES` (`undefined`/`self-effect`) → **Take Wing под блок попадает**, дополнительный код не нужен. Проверить в живом прогоне: pf2e списывает частоту *до* карточки (`justSpent`), второй клик в том же раунде в бою — блок с предупреждением; Alt — обход. Перед сдачей перепроверить после коммита доработки `impulse-gate.mjs` (сейчас в рабочем дереве изменён).

## 5. Решение для группы (редакция 2, CLAUDE.md §1.4 и §1.5)

Путь «щёлкнуть родной переключатель шагом `rollOption`» отклонён (§1.5, HUD не засорять). Единый механизм для A и B:

**5.1. Вид `move` в `effect.mods`.** `{ "move": { "type": "fly|swim|climb|burrow", "value": 15 | {"land": true, "min": 20}, "option": "take-wing" } }` -> RE `BaseSpeed {selector:type, value}` (формула `max(@actor.system.movement.speeds.land.value, N)`; `force` не ставим) и, если задан `option`, ещё нередактируемый `RollOption {domain:"all", option}`. Эффект накладывается шагом `apply` на себя при использовании; срок и снятие — 5.3.
- **Усиления без переключателя.** `option` = имя опции родного переключателя фита (у восьми фитов оно равно slug: `take-wing`, `take-flight`…). Эффект сам ставит эту опцию, и родные правила pf2e срабатывают сами: Zip! Zoom! (`BaseSpeed fly 25` под `take-wing`), Fully Flighted (35), Benefactor's Wings (30 при драконе). Усиления в каталоге не перечисляем: механизм для всей семьи, `option` берётся из `RollOption` в `rules` фита (разметка по `ruleKeys`).
- **Двойного полёта нет.** `BaseSpeed` фита и `BaseSpeed` эффекта — кандидаты одного выбора, берётся максимум (`pf2e.mjs:34656`, сортировка по `value desc`, `force` не ставим). Если переключатель всё же включён (нейтрализация не сработала), опция та же и максимум тот же. Подтвердить живым прогоном (сценарий, п. 1).
- **Into the Sky:** постоянный `BaseSpeed fly 25`; эффект с 15 его не перекроет (максимум). **Селектор `fly-speed` невалиден:** допустимы `Gr = land, burrow, climb, fly, swim` (`pf2e.mjs:9577`), иначе правило получает `failValidation` и не применяется. В данных 8.4.1 это так; данные 8.6.1 (LevelDB) прочитать не удалось (`classic-level` недоступен из node), нужна проверка на живом листе: есть ли у актёра с фитом `speeds.fly`. Если нет, это баг данных pf2e; обход модулем не пишем, сообщить в pf2e.
- Для B и winged-leap (правил нет) `option` не задаётся, работает только `BaseSpeed`.

**5.2. Родную автоматику pf2e нейтрализуем (решение пользователя: встроенную автоматизацию при необходимости отключаем).** Способ — **рантайм, без записи в данные мира**: при подготовке правил предмета (обёртка/хук на `ItemPF2e#prepareRuleElements`, точное место проверить пробой на живом pf2e) у предмета, чья запись каталога содержит `move`, выставляем `ignored = true` только двум собственным правилам фита: `RollOption` с `toggleable` (из-за него появляется переключатель в HUD и на листе) и `BaseSpeed` под предикатом этой опции. Правила *других* фитов (Zip! Zoom!, Fully Flighted, Benefactor's Wings) не трогаем: они срабатывают по опции, которую ставит наш эффект (5.1).
- **Почему так.** Альтернатива «переписать `system.rules` у предмета в мире» необратима и разъезжается с обновлениями pf2e и копиями; CSS не годится (§1.5). Рантайм-правка живёт только пока модуль активен.
- **Выключение модуля / откат.** Нейтрализация исчезает вместе с модулем: при перезагрузке правила снова рабочие, переключатель возвращается, поведение pf2e прежнее. Наложенные эффекты `af-*` остаются на актёрах как обычные эффекты со сроком (гаснут сами по `turn-end`); при необходимости их снимает «Откатить» в карточке. Настройка/запись каталога снимается удалением записи — нейтрализация пропадает со следующей подготовкой актёра.
- **Без двойного нанесения (§3.5).** Нейтрализованы только правила, которые заменяет эффект: скорость даёт один источник. Если нейтрализация не сработала (другая версия pf2e), срабатывает защита максимума: `BaseSpeed` фита и эффекта — кандидаты одного выбора, берётся большее, не сумма. Предупреждение в консоль при отсутствии точки подключения; без падения.
- **Общий механизм** с «Стайным» (`docs/plan-pack-attack-no-toggle.md`, на момент правки файла ещё нет): «модуль нейтрализует правила, которые автоматизирует» — один код, один список (записи каталога с `move.option` и записи без-переключательных правил Стайного). Не дублирую: свожу к этому плану, когда он появится. Наш план от механизма зависит и стартует после него.
- Проверка в сценарии: (а) Take Wing: переключателя нет в `synthetics.toggles` и на листе; (б) `speeds.fly` без эффекта = нет; с эффектом = 15; (в) отключить модуль (или флаг) и перезагрузить: переключатель вернулся.

**5.3. Срок.** Эффект снимается после первого завершённого перемещения токена или в конце хода, что раньше; вне боя — до первого перемещения. Реализация: срок шага `{value:0, unit:"rounds", expiry:"turn-end"}` (есть) плюс признак `endOnMove: true` в `apply`. Рантайм: хук `moveToken` (`events.mjs:803`) удаляет эффекты с меткой `endOnMove` у этого актёра, если перемещение завершено, его `movement.action` совпадает с типом эффекта (`fly`), и оно не принудительное (`displace`, `[MOD].forced`). Чистая функция «закончить ли по этому перемещению» + тест. `pf2e.endTurn` не нужен: в конце хода эффект гаснет сроком.

**5.4. Мастерская.** Блок «Скорость» режима «Эффект»: переключатель «Бонус / Вид движения»; для вида — список типа (подписи pf2e), число либо флажок «равна наземной, но не менее N», «опция фита» (список из `RollOption` предмета, подставляется сама); срок — вариант «до конца перемещения» (ставит `endOnMove` и срок `turn-end`). Без ручного JSON, строки в `lang/ru|en`. Поля «Включить переключатель предмета» нет.

**5.5. Падение.** Только строка-напоминание в карточке использования (по признаку «fall» в `descEn`: A, umbral-wings, jump-jets, propulsive-leap), без урона и без кнопки. `height.mjs` не трогаем.

**Не берём:** C (обычный проход `speed`), D (линейка), долгие выдачи вида скорости (1–10 мин; тот же `move` закроет их позже), «удвоить fly» (sky-master-mask) и выдачу союзникам — долг.

## 7. Живой сценарий (RustySpirit, копии)

`tests/live/turn-movement.js`; актёр — копия «Тест: Дракончик» из «Тестовые копии (автоматизация)». У оригинала способностей нет: в копию положить из компендиума Take Wing, Zip! Zoom! (`zip-zoom`), Into the Sky (`into-the-sky`). Сцену «Тест» не трогать, свои сообщения убирать точечно.
1. Бой, ход: Take Wing -> эффект на актёре, `speeds.fly.value === 15`, переключателя в HUD и на листе нет (§5.2). Если нейтрализацию снять (модуль выкл.), родной переключатель возвращается и даёт 15, не 30.
2. Полёт токеном -> эффект снят, `fly` исчез. Принудительное перемещение эффект не снимает.
3. Второй клик в том же раунде -> блок `builtin.limit.frequency`; Alt обходит; вне боя не блокирует.
4. С Zip! Zoom! -> 25.
5. Копия с Into the Sky: `speeds.fly.value` (проверка `fly-speed`).
6. Конец хода без перемещения -> эффект снят сроком. Вне боя: висит до первого перемещения.
7. B: копия liberating-dive / umbral-wings -> эффект до конца хода, в карточке строка про падение.
8. Уборка копий, эффектов, сообщений; чужое состояние мира не менять.
