# План: механизмы без правила видны в Мастерской (M1, M2, M3, M5, M6, M7, M8) и выведенный источник

Только план, кода нет. Правила — `CLAUDE.md` (§1.4 механизм для группы, §1.5 переключатель только для решения игрока, §2 тексты, §3.1 единообразие, §4.4 группа); UI — `DESIGN.md` (стиль «Мастерской»). Планы механизмов: `plan-recharge-requirements.md`, `plan-strike-ability-const-cond-nextcast.md`, `plan-counterspell-tkmaneuver-hplink.md`.

## 0. Что есть сейчас (прочитано в коде)

- Режим «Автоматизация» (`scripts/workshop/app.mjs` `#autoCtx`, шаблоны `workshop-auto*.hbs`): шапка (`head.src` — откуда правило, бейджи «Низкая уверенность» / «Текст копии отличается», `head.covered` — «Выполняет pf2e-automations»), конвейер строк `ws-prow` (чип `ws-pchip` + сводка `ws-psum`, раскрывается в `ws-pfields`), справа «Что произойдёт» (`story`) и «Пробный запуск», внизу подвал (`Сбросить`, `Снять правило`, меню «В мир», основная «Сохранить в предмет»).
- Всё показанное — это **правило** (`resolveRule`). Механизмы M1, M2, M3, M5–M8 живут в рантайме по тексту/slug и в `resolveRule` не попадают: у предмета без правила Мастерская пишет «правила ещё нет» и показывает пустой конвейер.
- Уступание pf2e-automations уже видно: `automationsGroups` → бейдж + красная плашка `doubleWarn`. Встроенные обработчики видны только как строка «Макросы» (`builtin:<id>`), и только когда они записаны в правило.
- Чистое ядро Мастерской (`workshop/automation.mjs`) не импортирует Foundry и тестируется в node; строки сводок — `au.evLine` / `au.story` / `au.plate`.

## 1. Решение в одном абзаце

Новый раздел «Работает само» (в Мастерской, на вкладке листа — только чтение) строится из **тех же чистых функций, которые решают в рантайме** (`rechargeOf`, `limitEntry`, `strikeLinkEntry`, `maneuverList`, `permanentOf`, `optionOf`, слаг Spirit Link): второго признака нет, значит расхождения «показано одно, делает другое» быть не может. Правка — один необязательный флаг предмета `flags.pf2e-automato.mech`, отдельный от `rule`. Схема правила (`validateRule`) не меняется.

Почему не поле в `rule`: правило-флаг имеет высший приоритет в `resolveRule` (флаг → мир → каталог → разметка). Сохранить пустое правило ради переключателя значит выключить вывод из разметки у предмета, у которого правила не было. Отдельный флаг этого не делает.

## 2. Что ведущий видит

Решения (после ревью): раздел — над конвейером; переопределения только на предмете (`flags.pf2e-automato.mech`), схема правила не меняется; переключатели M1, M2, M3, M5 (только если манёвров больше одного), M6; M7, M8 — только показ; живое состояние не показываем; вкладка листа — только чтение; новые строки — «ведущий». **Объём: показ — только строки раздела над конвейером и на вкладке листа; правая панель (§2.2) и строка в шапке (§2.3) не делаются (дубли).**

### 2.1 Раздел «Работает само» (`workshop-auto.hbs`)
Над конвейером, заголовок `h2.ws-h`, **только если механизм нашёлся** (у большинства предметов раздела нет). Строки — те же `ws-prow`: слева чип вида (`ws-pchip`), справа сводка одной фразой (`ws-psum-static`, у переопределяемых — `ws-psum` с шевроном и раскрытием в `ws-pfields`, как у «Дополнительно»). Порядок причин: переопределение предмета → режим (`modeOf`) → `shouldYield` — только там, где рантайм это проверяет (у M6 «уступки» нет: `addPermanent` её не смотрит). Пилюля неинтерактивная (`ws-pill-static`: без `cursor:pointer` и hover). ## 3. Что ведущий может изменить (§1.5)

Правка — только там, где решение за человеком, а не вычислимо: признак получен разбором текста или таблицы, и ГМ может с ним не согласиться. Состояния, которые модуль вычисляет сам (бой/не бой, рука свободна, держит ли существо), переключателей не получают.

| | что правится | значение в флаге | поле в окне |
|---|---|---|---|
| M1 | срок или «не ограничивать» | `mech.recharge`: `false` или `"1d6"`/`"1d4+1"` (`parseDice`, ≤10 кубов) | текст «Срок перезарядки (кубики)» с подсказкой-значением из текста + флажок «Не ограничивать перезарядкой». Только раунды (как у разбора) |
| M2 | ложное требование | `mech.req: false` | флажок «Не проверять требование». Править сами клаузы нельзя: оверлей — данные `rules/use-limits.json`, ошибку разбора чинят там (`tools/use-limits.mjs`) |
| M3 | отвязать от Удара | `mech.strike: false` (в `strikeLinkEntry` → null; карточка способности снова с кнопками) | флажок «Не запускать Ударом» |
| M5 | какие манёвры | `mech.maneuvers: ["disarm","trip"]` (подмножество таблицы `SPELLS`, не пусто) | плашки-переключатели `ws-pill` (как «Дополнительно»: `aria-pressed`); по умолчанию нажаты вычисленные; «Авто» (`ws-btn-g`) снимает переопределение. Выбор манёвров — решение ГМа, вычислить его нельзя |
| M6 | не накладывать | `mech.permanent: false` (читает обёртка `fromOwnedItem`) | флажок «Не накладывать постоянное состояние». Причина: ручного снятия у синтетического правила нет |
| M7, M8 | — | — | только показ (переключатель не нужен: связь — часть заклинания; метамагия включается самим использованием) |

Где хранится: **флаг предмета** (у NPC — на предмете актёра/дельте токена). Мировой каталог и схема правила не трогаются. Отклонение от «для всей группы» (§1.4) здесь допустимо: группа уже обслужена механизмом, флаг — исключение для одного предмета. Мирового уровня у `mech` нет.

Читают флаг шесть точек, по одной на механизм, через общий `mechOf(item)` (новый `scripts/mech.mjs`, без Foundry):
`ctxOf.rc` в `impulse-gate.mjs` (M1), геттер `req` там же (M2), `strikeLinkEntry` (M3), `maneuversOf` (M5), `permanentOf` (M6). Неизвестные/невалидные ключи отбрасываются молча (как `itemFlagRule` отбрасывает невалидное правило), значит старый/чужой флаг ничего не ломает.

- `workshop/app.mjs`: **черновик `mech` (`#mech`) грузится отдельно от `#loadAu`** и сбрасывается только в `resetDraft`, после `#saveItem` и при смене предмета (не трогают «В мир», «Снять правило», «Принять», `refresh`); `#dirty()` = `#ruleDirty()` ИЛИ `#mechDirty()`; `mechErrors` входят в `errors` (блокируют «Сохранить»); в `#autoCtx` — `mechs` (кэш разбора на `#loadAu`, состояния режимов — на каждый рендер: набор текста не должен каждый раз резолвить правила всех предметов актёра, `claimedBy` у M3 дорог); `#saveItem` пишет **каждую часть, только если она менялась** (`mech` → `forcedReplace(flagPath("mech"))` либо удаление при пустом; правило — как сейчас). **Существующий дефект:** «Сохранить» без правки правила писал пустое `kind:onUse` в флаг — оно перекрывало мир, каталог и разметку, а разметка становилась доверенным `flag`. Теперь правило пишется только при `ruleDirty` (`savePatch` в `scripts/mech.mjs`, юнит-тест); без правки правила и `mech` «Сохранить» недоступна, «В мир → правило» недоступно у предмета без правила и без правки. Поведение изменилось: «Сохранить» без правки больше не закрепляет каталог — для этого «Принять». `resetDraft` сбрасывает и `mech`. `#setAuto`: пути `mech.*` идут в `#setMech` (`setProperty` в черновик; переход `maneuvers.auto` → ручной подставляет вычисленный список).

## 6. Выведенный источник (`lookupSourceOf`)

Проблема: у предмета NPC своего источника нет (`sourceOf` пуст), правило найдено по `lookupKey` = «источник актёра».Item.«id». Шапка листа показывает `source: —`, а «В мир → по источнику» отключено (`noSource`, `sheet.mjs:537,553,621`, `app.mjs:518,609,810`).

- Единый ключ: `const key = res?.lookupKey ?? res?.sourceUuid ?? lookupSourceOf(item)`. `noSource = !key`; `#world`/`worldKey` пишут `{source: key}`. `resolveBase` ищет мировое правило именно по этому `key` (`w.bySource.get(key)`), значит сохранённое найдётся без правок `rules.mjs`. Вынести в чистую `worldKeyOf(item, res, scope)` (общая для листа и Мастерской, тест).
- Подпись: у выведенного ключа пункт меню «Для всех копий этого существа» вместо «Для всех с этим источником» (ключ = существо из компендия + id предмета, не предмет); `delWorldSource` — зеркально. Строка листа `source:` показывает ключ с пометкой «выведен от существа».
- Защиты тёзок/копий (`guardCopy`, `byName`) мировое правило не проходит (оно возвращается раньше), как и сейчас при собственном источнике: ключ точный, тёзок нет. Если ГМ правил текст копии, мировое правило всё равно применится — как у любого мирового правила.
- Нет ни источника предмета, ни источника актёра (NPC, созданный вручную) — `noSource` остаётся, подсказка «у существа нет источника в компендиуме; используйте slug».

## 8. Риски

- **Дрейф признака**: если дублировать разбор в строке Мастерской, он разойдётся с рантаймом. Защита — реестр вызывает те же функции + тест паритета по корпусу (п. 7.2).
- **Стоимость рендера**: `strikeLinked`/`claimedBy` резолвят правила всех предметов актёра; Мастерская перерисовывает панель на каждый символ. Кэш на `#loadAu`, пересчёт после сохранения и при `updateItem` открытого предмета.
- **Показываем возможность, а не состояние**: строка «Перезарядка 1d4» — не «сейчас осталось 2 раунда». Не смешивать с рантаймом.
- **M1: ложные срабатывания текста** (вспомогательные броски pf2ru) уже отсечены разбором; переопределение — запасной выход, но «добавить перезарядку там, где не нашли» не делаем (нет строки — нет переключателя).
- **M3**: `claimedBy` и вывод зависят от проверенного правила; у способности только с разметкой строка показывает причину, а не пустоту — иначе ГМ не поймёт, почему карточка не автоматическая.
- **`mech` + неподходящий предмет**: ключ для предмета, на котором механизм не нашёлся, игнорируется, но остаётся во флаге (его не видно). Чистить при сохранении (оставлять только ключи найденных механизмов).
- **Мир по выведенному ключу**: правило шире, чем «этот предмет» (все копии существа); подпись в меню обязательна.
- Правка предмета NPC в компендии заблокирована — те же `lockedFlag`, что и у правила.
