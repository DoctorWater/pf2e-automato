# Roadmap тестового релиза PF2e AuTOMATO

Снимок: 2026-11-09. Foundry 14.370, pf2e 8.7.0, модуль 0.1.0 (`6623164`) → 0.2.0.

## Подача

Релиз подаём как **тестовый (public beta)** и сразу задаём ожидания: что уже работает, чего ещё нет и куда писать об ошибках.

- **Перенос pf2e-automations почти полный: 97,5%.** Модуль заменяет его, поэтому они объявлены несовместимыми (`module.json`, `conflicts`).
- **Остальной компендий pf2e закрыт на 13,6%:** 2 756 из 20 206 документов, которым нужна автоматизация (`coverage.md`, снимок 8.6.1).

Позиционирование: «замена pf2e-automations плюс Мастерская, чтобы ведущий сам дописывал недостающее без JSON».

## Этап 2. Подача

1. **README для ведущего на русском** (первая волна русскоязычная; английская версия — к открытому запуску). Структура:
   - одна фраза «что это»;
   - бейдж Beta;
   - GIF на 20–30 секунд: карточка → испытания целей → состояния по степеням;
   - три скриншота Мастерской;
   - «Что работает» с цифрами покрытия;
   - «Чего пока нет»;
   - установка;
   - быстрый старт в три шага;
   - «Несовместим с pf2e-automations — отключите его»;
   - «Известные проблемы»;
   - как сообщить об ошибке.

   Нынешний README — справочник разработчика. Его переносим в `docs/`.
2. **Первый запуск в игре.** Ведущий получает одну карточку в стиле модуля:
   - «Это тестовая версия — сделайте копию мира»;
   - кнопки «Открыть Мастерскую», «Настройки», «Сообщить об ошибке».
3. **Кнопка «Скопировать диагностику»** в настройках: версии Foundry, pf2e и модулей, итог самопроверки внешних точек. Для бета-теста это главный инструмент: без неё половина отчётов бесполезна.
4. **Шаблоны GitHub Issues:** ошибка (версии, предмет, шаги, консоль) и «нет автоматизации для X». Второй превращает пробелы покрытия в очередь работ.
5. **`CHANGELOG.md`**, теги `vX.Y.Z` и GitHub Releases (сборка уже в GitHub Actions, этап 1).

## Этап 3. Запуск

1. **Мягкий старт:** 3–5 знакомых ведущих, лучше из русскоязычного сообщества pf2ru. Только ссылка на манифест, без каталога Foundry. Две недели и еженедельные патчи.
2. **Открытый запуск:**
   - листинг на foundryvtt.com;
   - анонс в Discord pf2e Foundry (канал модулей), r/FoundryVTT, r/Pathfinder2e;
   - в анонсе — GIF и честная фраза о покрытии.
3. **Ритм после запуска:** патч раз в неделю, метки в issues (`bug`, `coverage`, `workshop`). Конвейер покрытия из `ROADMAP.md` продолжается между патчами.

## Критерии «можно выпускать»

- Юнит-тесты зелёные. Живые наборы зелёные в **чистом** мире, на английском и без необязательных модулей.
- В сборке нет кампанийных и служебных файлов.
- README, карточка первого запуска, диагностика и шаблоны issues готовы.
- P1 Мастерской закрыты.

## Решения (2026-11-09)

1. **Аудитория первой волны:** русскоязычные ведущие.
2. **Канал:** ссылка на манифест, без листинга на foundryvtt.com.
3. **Название и версия:** «PF2e AuTOMATO», первый публичный релиз — `0.2.0`.

## Открытые решения

1. **Настройки по умолчанию для чужих миров:** применение результатов сейчас по кнопке (`mode.apply = button`), остальное автоматически. Оставить так?

## Долг, не блокирующий тестовый релиз

- Меню «Создать… ▾» вместо вкладок «Эффект» и «Предмет» в Мастерской (макеты на выбор).
- Вид «движение» в эффектах, Winged Leap и способности «скорость до конца хода» (`docs/plan-turn-movement.md`).
- Переключатели War Formation и Subduing Attack — вычисляемые опции (`docs/plan-pack-attack-no-toggle.md`).
- Удалить логику уступки pf2e-automations (`yieldToAutomations`, `shouldYield`): при несовместимых модулях она не нужна.
