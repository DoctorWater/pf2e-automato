# activate: активация предмета — одна модель (план v2, кода нет)

Сводит `plan-mode-choice.md` и `plan-cast-multi.md` (оба удалены) с учётом разбора Критика (круг 1) и решений пользователя 2026-10-25. База: `feat/workshop-editors` (редактор Мастерской закоммичен, `46aa52a`). Продолжение `plan-cast-activation.md` (v2, в коде: `scripts/cast.mjs`, `deriveCast` `rules.mjs:1204`, `tools/cast-batch.mjs`). Живые допущения — **[J]**. pf2e 8.6.1 локально; новых обращений к API pf2e нет.

## 1. Правило игры

У предмета (снаряжение, оружие, броня, расходник) одна или несколько «Activate»: у каждой свои действия, частота, требования и эффект. Эффект бывает: сотворить заклинание; сотворить и добавить своё (бонус, состояние, второй бросок); только своё (испытание цели, зона, состояние); выбрать один из нескольких вариантов (грани куба, «X или Y» заклинаний). Использующий выбирает активацию (кнопка), затем вариант (диалог), и от выбора зависит механика. Сюжетные выборы и решения ведущего не автоматизируются — только побочные эффекты с механикой.

## 2. Что уже есть

- Модуль: `cast[]` (`cast.mjs`) — кнопка «Сотворить: …» на модульной карточке предмета (`chat.mjs:287` читает `use.rule.cast`, действие `cast-item` `chat.mjs:417`), `per` (`uses.<id>`, `usesLeft`, `withUse`, сброс `pf2e.restForTheNight`), `requires`, `giveBack` (возврат при удалении карточки). Валидатор — `rules.mjs:608-632` (`vCast`). Мастерская — секция «Активации» (`workshop/app.mjs`, `automation.mjs`, `sheet.mjs`). Живой тест `tests/live/cast-activation.js`, юнит `tests/cast.test.mjs`.
- `choose {from:"options", options, prompt?}` — шаг `onUse.apply`/`onEvent.apply`; выбранное = `choice:<value>` для `when` следующих шагов.
- `variable-cast.mjs`: окно «сколько действий» для заклинаний «1 to 3», пишет `origin:item:cast:actions:N` и `flags.pf2e-automato.cast.actions` **после** создания сообщения.
- Путь использования `use.mjs`: `buildSnapshot`, `execUse` на `createChatMessage` (`onCreateMessage`, `guardActiveGM`), `wantsSnapshot` (`use.mjs:64`; при `rule.cast?.length` снимок пишется всегда — из него рисуются кнопки, `use.mjs:69`), `useKindOf` (`use.mjs:28`), `isResumable` (`use.mjs:86`, учитывает `awaitingRegion`), `meta.key = <msgId>:self:<i>`. `askHere` (`builtin/lib.mjs:58`) — локальный диалог у владельца.
- Данные правил приходят из четырёх мест: каталоги `rules/*.json` (`buildCatalog` → `validateRule`), мировой каталог (`S.get("catalog")`), флаг предмета `flags.pf2e-automato.rule` (`itemFlagRule`), правка в Мастерской. Версия правила `RULE_VERSION = 1` (`rules.mjs:6`, поле `v`).

## 3. Решения пользователя (2026-10-25)

1. **Одна модель.** Активация = запись списка активаций: `spell` необязателен; свои шаги `onUse`; или `choices` — выбор 2–6 вариантов. Одна кнопка, один счётчик частоты, один диалог. Отдельных `modes` нет.
2. **Ключ `cast` → `activate`** с миграцией (каталог 137, флаги предметов мира, Мастерская, README, конвертер, тесты, живой тест, промпт). **Счётчика версии нет: `v` остаётся 1.** Старый ключ в чужом мире/флаге — §6.
3. **«Каст + добавка» — две карточки в чате** (заклинание + активация со своими шагами).
4. **Корневые режимы у заклинаний и умений — отложены.** В v1 вместо них: починка `choose` (общий `picks`) и отдельный фикс гонки `variable-cast`. Curse of Lost Time и Song of the Fallen — долг «испытание по типу цели».
5. «Каст + ручные активации» (37) — `partial` отдельной строкой в coverage.
6. «gain/replicates the effects of X» — каст только при чистом тексте (5).
7. Вспомогательный текст → `note`, `low`, после выборки Критика.
8. Ранг `{half, min}` — да; **расширено: Harrow ×5 — `rank:{half:"actor"|"item", min}` и `dc:{against:"class-spell"}` в записи** (шаг схемы).
9. Посохи/списки ≥4 с зарядами — позже, отдельный примитив.
10. Кнопка-счётчик для чисто текстовых активаций — нет.
11. Частота списывается после выбора и создания сообщения; отмена диалога не списывает.
12. **Массовая перезапись мировых данных `cast`→`activate` — сразу, в первом релизе**, при `ready` у активного ГМа («работаем на будущее»). Откат на старый модуль теряет активации — принято. Чтение обоих ключей остаётся (несвязанные токены, компендиумы, старые снимки).

## 5. Модель данных и рантайм

### 5.1 Форма (поле `activate`, заменяет `cast`)
```json
"activate": [
  {"id":"cast-x","spell":"Compendium.pf2e.spells-srd.Item.…","rank":4,"per":{"value":1,"unit":"days"}},
  {"id":"tattoo","spell":"…","dc":38,"onUse":{"targets":"self","apply":[{"to":"self","effect":{"uuid":"…"}}]}},
  {"id":"cut-fear","label":"Cut Fear","dc":27,"onUse":{…},"per":{…},"requires":"invested"},
  {"id":"cube","label":"Куб","choices":[{"id":"face1","label":"Грань 1","onUse":{…}},{"id":"face2","spell":"…","rank":2}]},
  {"id":"harrow","spell":"…","rank":{"half":"actor","min":1},"dc":{"against":"class-spell"}}
]
```
- Прежние поля записи без изменений: `id?, spell?, rank?, dc?, attack?, counteract?, per?, requires?, label?, note?`. `dc` записи: число, `{level:"high"}` (NPC), `{against:"class-spell"}` (новое: СЛ лучшей записи заклинателя **актёра**) или нет.
- `onUse` — грамматика `rule.onUse`. **СЛ шагов активации** (`onUse.challenge.dc`): в обработчике нажатия, **явно**: `challenge.dc.value` (число) → иначе `dc` записи через `pickDc`/`castInfo` (`cast.mjs:71/144`) → иначе `levelDc(item.level)`. Результат пишется в `dc` снимка: `onPreCreateMessage` для сообщения активации пропускается (`hasSnapshot`), там СЛ не досчитается. Формы `{level}` и `{from:"cast"}` внутри `activate[].onUse.challenge.dc` **не поддерживаются** (валидатор отвергает, §7); `{against}` без владельца запрещено.
- `choices` — 2–6 вариантов; вариант = `{id?, label?, spell?, rank?, dc?, onUse?}`, вложенных `choices` нет. Общие `per`/`requires`/`id` — на записи: один выбор = одно использование.
- Fearcutter и Staff of Sun Wukong — **один список кнопок** с раздельными `id`.

### 5.2 Нажатие (карточка предмета, `chat.mjs`)
1. Проверка `requires`, `usesLeft` (мягкое окно «всё равно?», как сейчас).
2. Есть `choices` → **локальный диалог у нажавшего** (`askHere`) **до создания сообщения**; отмена — выход, ничего не списано. Правило собирается синхронно с выбором: гонок `preCreate`/`pickMode`, пересчёта СЛ/зоны нет. Число действий у заклинания «1 to 3» на пути активации спрашивается **до** `ChatMessage.create` (§5.4), не после.
3. Есть `spell` → `castItem` как сейчас: карточка заклинания pf2e (сотворяет нажавший; отказ — выход без счётчика, шагов нет).
4. Есть `onUse` (записи или варианта) → **отдельное сообщение использования** `kind:"use"` со снимком производного правила: `buildSnapshot({kind:"use", rule:{v, onUse}, dc, targets})`, `dc` посчитан по §5.1. **`flags.pf2e.origin` в него не копируется как есть:** его подхватили бы `castOrigin` (`builtin/lib.mjs:93`), `shield-ward`, `prey-share`, `apparition-sense` и чужие модули как «сотворение заклинания». Вместо этого — метка `flags.pf2e-automato.activation = {item, id, choice, useId}`, а нужные опции кладутся в `rollOptions` снимка; `castOrigin` **не правится**: у сообщения активации нет `flags.pf2e.origin`, и `castOrigin` (`builtin/lib.mjs:93`) и так вернёт `null`; а метка `activation` с `useId` стоит и на настоящей карточке заклинания от активации (§5.2.6) — пропуск по метке выбил бы её у `shield-ward`/`prey-share`/`apparition-sense`/`variable-cast`. Юнит: «сообщение активации без origin → `castOrigin` = null». `item` — uuid предмета для `execUse`/`giveBack`.
5. **Исполняет активный ГМ** через `onCreateMessage` → `execUse` (`guardActiveGM`). **НЕ исполнять шаги из `castItem` у игрока и НЕ на карточке предмета.** Каждое нажатие = **своё** сообщение использования; два нажатия = два использования (два счётчика), `meta.key = <msgId>:self:<i>` лишь не даёт **одному** сообщению исполниться дважды.
6. **Счётчик и откат.** `withUse` — после создания сообщения. «Каст + добавка» — **один `useId`** (общий для карточки заклинания и сообщения активации; пишется в оба флага): счётчик возвращается ровно один раз, как бы ни удалили карточки (`giveBack` смотрит оба флага и сверяет `useId`). Удаление сообщения возвращает **только счётчик**; эффекты снимает кнопка отмены (`undoApplied`, `main.mjs:64`), а не удаление.
7. **Снимок на карточке предмета остаётся** (`wantsSnapshot` `use.mjs:64`: правило с `activate.length` — снимок есть всегда, как у `cast`): из него рисуются кнопки (`use.mjs:69`, `chat.mjs:287` → `use.rule.activate ?? use.rule.cast`, §6). Шаги исполняются **не из него**, а из сообщения активации. **[J]** — `kind:"use"` без `useKindOf`, цели нажавшего, `undoApplied`, откат; `hasSnapshot` не даёт `onPreCreateMessage` перезаписать снимок.
8. **Область (Horn of Blasting, Drum of Upheaval).** Проблема: регион из `@Template` карточки предмета достаётся карточке, а `runRegion` выходит на `!onUse` (`use.mjs:344`), у корневого правила предмета `onUse` нет. **Решение: класть обогащённый текст Effect активации (с `@Template`) в содержимое сообщения активации** и ставить `state.awaitingRegion` (как у расходника с `targets:"area"`, `use.mjs:56`) — игрок бросает шаблон из этого сообщения, регион получает `origin` сообщения активации и находит `onUse` в его снимке (`runRegion` идёт по ветке `first`, не по `resolveRule`). Обоснование против привязки региона «по `item` + `awaitingRegion`»: чужой шаблон с карточки предмета или соседней активации не должен подхватываться, а привязка по `item` неоднозначна при двух активациях с областью (Staff of Sun Wukong). `isResumable` уже учитывает `awaitingRegion`. Подтвердить вживую **[J]**: шаблон из сообщения активации → `runRegion` исполняет зону/испытание; `apply`-шаги — только в сообщении активации.
9. `rule.onUse` предмета (действие «использовать предмет» на карточке pf2e) и `activate[i].onUse` не конфликтуют; предмет, у которого модель вывела `onUse` на всё описание, **переразнести** — в долг, не в авто (риск дубля шага, §13).

### 5.3 Чистый общий код
`usesLeft`/`withUse`/`requirementOf`/`rankOf` — чистые функции в `cast.mjs`; файл и обработчик чата `cast-item` **не переименовываем** (внутреннее имя, ужимает дифф). `rankOf` получает `half:"actor"|"item"`.

### 5.4 Две починки v1 вместо режимов у заклинаний/умений (независимы, шаг 1)
- **`choose`: `picks` — общий на использование.** `picks` создаётся в каждом `applyOps` заново; общий он только в `events.mjs:208`. Не передаётся в `use.mjs:216/221` (self-шаги и шаги по цели — разными вызовами) и `saves.mjs:375` (шаги по степеням). **Не вводить новый `use.state.picks`:** `picks` восстанавливаются из сохранённых операций `chose` в `state.apply.self` (они там уже лежат для отката) в начале `applyUseSteps`/`saves` и подмешиваются в `whenOptions`. Это же чинит `applyUse(only)` (`use.mjs:248`), где при повторном запуске выбор терялся. Тест: `{choose}` + шаг `to:"target" when:["choice:a"]` в одном `onUse`; повтор через `only`.
- **Гонка `variable-cast`.** `execUse` стартует на `createChatMessage` у активного ГМа до записи числа действий. Фикс: **автор** в `onPreCreateMessage` ставит `state.awaitingActions`, только если `actionChoices(spell)` непусто и `macro≠off`; `variable-cast` снимает его **в том же `update`**, что пишет число (при отмене окна — снимает без опции); ГМ продолжает по `updateChatMessage`, `isResumable` (`use.mjs:86`) учитывает `awaitingActions` так же, как `awaitingRegion` (и второй цикл `resumePending`, `use.mjs:420`, — иначе `resumeRegion` возьмёт сообщение, ждущее число действий); `variable-cast` проверяет `cast?.actions` (уже записанное не спрашивает повторно). **Без таймаута.** На пути активации (§5.2.2) число действий спрашивается до `ChatMessage.create`, и флаг не нужен.
- **Развести флаги:** `flags.pf2e-automato.cast` остаётся **только** у `variable-cast` (`{actions}`), флаг активации — **`activation`** (§5.2.4, §6). Старое чтение прежнего флага карточки заклинания активации `cast` (`giveBack`) — оба, один релиз.
- **Долг «испытание по типу цели»** (Curse of Lost Time, Song of the Fallen): `choice:` гейтит только шаги, а СЛ/статистика/`basic`/область — поля `onUse`; в v1 не решается.

## 6. Переименование `cast` → `activate` и миграция (шаг 3, до новых полей)

Принцип: **читать оба ключа, писать новый; файлы данных переписать один раз; `v` остаётся 1.**
- **Чтение (рантайм).** `validateRule`: `rule.activate = raw.activate ?? raw.cast`. Если заданы оба — **в рантайме побеждает `activate` с предупреждением** (`warn`), не ошибка. Ошибка `activate.dup` — только в `tools/validate.mjs` и при сохранении в Мастерской. Покрывает все четыре источника: каталоги, мировой каталог, флаг предмета, форма.
- **Снимки в уже созданных сообщениях** содержат `use.rule.cast`: `buildViewModel` (`chat.mjs:287`) и все прочие читатели снимка идут через **одну функцию** `activateOf(rule) = rule.activate ?? rule.cast`; юнит на старый снимок (`rule.cast`) и новый.
- **Каталог:** одноразовый скрипт в `tools/` переименовывает ключ в `rules/catalog.model.json` (137 записей) и `rules/drafts*/` (где `cast:` в черновиках); ответы `tools/out/` не трогать. Сверка `tests/tools.test.mjs` (строка ~58 — промпт vs схема).
- **Мировые данные (мировой каталог, флаги `rule` предметов и вложенных предметов) — перезапись сразу, в первом релизе** (решение 12): при `ready` у активного ГМа всё переписывается новым ключом. Откат на старый модуль теряет активации — принято. Чтение обоих ключей остаётся для несвязанных токенов, компендиумов и старых снимков. Правило пишется **целиком** через `forcedReplace(flags.<MOD>.rule, rule)` (как `sheet.mjs:560`), где `rule` — **сырой флаг с переименованным ключом**, а не результат `validateRule` (нормализация потеряла бы непрошедшие/неизвестные поля); `id` записей и ключи счётчиков `uses.<id>` не меняются (юнит: запись без явного `id` сохраняет счётчик после переименования). Всем клиентам обновить модуль (строка в README): старый клиент после перезаписи мира кнопок не увидит, вложенные предметы (спеллхарты, `item.parentItem`) — **через родителя** (`cast.mjs:179`: у вложенного pf2e сливает `mergeObject` без performDeletions — ключ «-=» не сработает, старый `cast` остался бы). **Образец `builtin/index.mjs:93` (`macro≠off`) не копировать:** миграция данных не должна зависеть от режима макросов — отдельный хук `ready` под `isActiveGM`, повтор безопасен (идемпотентность по самому ключу).
- **Честно о полноте:** миграция не затронет несвязанные токены/актёров без загруженного мира, предметы внутри **компендиумов мира** (они не мигрируются; чтение не ломается — нормализация), чужие модули с собственными правилами. Всё это продолжает работать за счёт чтения `cast`.
- **Не переименовывать:** флаг счётчика `uses`, опцию `origin:item:cast:actions:N`, `origin:item:cast-by-activation`, id эфемерной записи `af-cast-<предмет>-<активация>`, обработчик чата `cast-item`, имя файла `cast.mjs`, **внутренние ключи ошибок `rules.err.cast.*` и поля формы Мастерской** (дифф меньше; новые ключи — `activate.*` только для новых проверок). Флаг сообщения `cast` — у `variable-cast` остаётся, у активации свой `activation` (§5.4).
- **Затрагивает:** `scripts/rules.mjs` (`vCast`, `coatPlaces`/`ruleStates`/`hasSteps`/`withMarkupHead`, `deriveCast`), `cast.mjs`, `chat.mjs`, `use.mjs`, `checks.mjs`, `apply.mjs`, `builtin/lib.mjs`, `tools/cast-batch.mjs`, `tools/validate.mjs`, `tools/triage.mjs`, **`tools/prompts/draft-rule.md` (строки 23, 61, 153)**, README (длинная ячейка схемы — разбить), тесты `cast.test.mjs`, `tools.test.mjs`, `copy-guard.test.mjs`, `events.test.mjs`, `workshop.affliction.test.mjs`, `tests/live/cast-activation.js`, `party-actions-npc.js`, `varris-*.js`, `suite.js`; Мастерская (`sheet.mjs`, `workshop/*`) — ключ в `ruleToForm`/`formToRule`. Полный список — `grep -rn "\.cast\b\|cast:\|\"cast\""` перед работой.
- **Тесты миграции:** юнит на нормализацию (cast→activate, оба ключа → `activate` + предупреждение), на 137 записях каталога, на старый снимок сообщения; живой — предмет мира и вложенный спеллхарт со старым флагом до и после `ready`.

## 13. Риски

- **Сообщение активации [J]:** `kind:"use"` создаётся модулем без `useKindOf`; откат, `undoApplied`, регион из шаблона сообщения активации не проверены вживую. Запасного пути «шаги в `castItem` у игрока» нет (нет прав на цели).
- **Чужие модули** читают `flags.pf2e.origin`: поэтому он не копируется, метка `activation` (§5.2.4); проверить `castOrigin`, `shield-ward`, `prey-share`, `apparition-sense` в сценарии 6.
- **Двойное исполнение:** корневой `onUse` модели на карточке pf2e + `activate[i].onUse` — следить в выборке (как `@Check`/`cast.dc` плана v2).
- **`partial` завышает «готово»:** отдельная строка в coverage.
- **Вывод шагов модельный:** `low` до выборки; кнопки `low` — только ведущему.
- **Переименование ломает чужое:** мир/флаги/экспорт/снимки с `cast`; чтение обоих ключей, `activateOf`, тесты на 137 записей, вложенные предметы — через родителя.
- **`awaitingActions`** не должен подвесить `execUse`: без таймаута — значит, `variable-cast` обязан снимать флаг на каждом выходе (число, отмена окна, ошибка); при `macro≠off` флаг не ставится.
- **Мастерская:** вложенный `onUse` — самая дорогая часть; допустима JSON-строка.
