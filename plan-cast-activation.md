## 1. Что реально встречается
Долг пачки 1 (`b01-save-conditions.json`): `missing: cast a spell activation` — 73 документа (+3 «armor/weapon effect choice» — те же спеллхарты). Ещё ~18 записей с «cast spell…» — другие примитивы (триггер по сотворению, список заклинаний, `next-cast`), сюда не входят.

**СЛ.** Три источника: `@Check[will|dc:38]` в Effect активации (30); фраза «The spell DC of any spell cast by Activating this item is 24» (спеллхарты, 21 предмет); ничего (11 активаций заклинаний с испытанием: Dominate у The Betrayal, Curse of Lost Time, Mind Probe…) — для NPC («high spell DC of the creature's level») — `dc:{level:"high"}`, см. §3. Атака заклинанием — СЛ−10 (как у NPC-статистики pf2e, **[J]**).

**Что pf2e уже умеет (слой 1, не дублируем):** свитки/палочки/spell-gem — `ConsumablePF2e#consume` -> `castEmbeddedSpell` (стр. ~51042, 51092), в долг не входят. `system.frequency` есть только у action/feat/NPC-способностей (стр. 119232, 120068); у снаряжения поля нет. У action/feat pf2e сам списывает частоту в `createUseActionMessage` (стр. 54101) — модуль её **только показывает**.

## 2. Как исполнить в pf2e
- **Эфемерное заклинание.** По образцу `ConsumablePF2e#embeddedSpell` (стр. 50994): `new CONFIG.Item.documentClasses.spell(src, {parent: actor, parentItem: item})`; `src` = `fromUuid(spellUuid).toObject()` с правкой источника (ранг ниже), `system.location.value = "af-cast-<itemId>-<castId>"`. `performLatePreparation` не нужна **[J]**.
- **Ранг.** `castRank` в `toMessage`/`getRollData` НЕ передавать: `toMessage` <-> `loadVariant` уходит в бесконечную рекурсию (стр. 52961, 53330, 53205). Ранг пишем в источник, как `createConsumableFromSpell` (стр. 39893): `system.location.heightenedLevel = rank` (явный), для кантрипа — `system.location.autoHeightenLevel = ceil(item.level/2)`; нет ранга и не кантрип — базовый.
- **Запись заклинателя — детерминированная и ленивая, на всех клиентах.** Простая регистрация на время `toMessage` не годится: `ChatMessagePF2e#item` (стр. 29390) пересобирает заклинание из `flags.pf2e.casting.embeddedSpell` с `location.value = casting.id` (стр. 53351) на любом клиенте и в любой момент, а `ActorSpellcasting#initialize -> clear()` (стр. 33917) стирает записи при каждом `prepareData`. Без записи `rollAttack` падает (стр. 53430), `getDamage` пуст, `saves.mjs:80` и `apply.mjs:615` берут СЛ первой записи. Решение: модуль оборачивает `actor.spellcasting.constructor.prototype.get` (тот же приём, что у pf2e для `trick-*`, стр. 33936): id вида `af-cast-<itemId>-<castId>` -> предмет актёра -> `rules.resolveRule` -> `cast[i]` -> дак-тайп запись `{id, name, actor, statistic, tradition, original, category:"items", isEphemeral:true, canCast:()=>true, counteraction}`. Запись **не кладётся в `contents`/`collections`**: иначе её увидят `getStatistic("spell-dc")`, `class-spell`, выбор лучшей записи для свитков (стр. 34366, 35201, 51094). Для `cast` без `dc` — `original` = лучшая запись владельца по СЛ (как у свитка, стр. 34392–34400), `statistic` = её статистика.
- **Statistic.** Конструктор — базовый `Statistic`, не `actor.getStatistic("perception").constructor` (это `PerceptionStatistic`, подмешивает Мудрость): `Object.getPrototypeOf(actor.perception.constructor)` либо через `statistic.withRollOptions` (стр. 14918) **[J]**. `new Statistic(actor, {slug, label, domains:["spell-attack-dc","spell-dc","<tradition>-spell-dc"], check:{type:"attack-roll", modifiers:[Modifier(attack ?? dc-10)]}, dc:{modifiers:[Modifier(dc-10)]}})`; `game.pf2e.Modifier` выставлен. Ранг null, атрибута нет -> СЛ ровно СЛ предмета (стр. 14882).
- **`counteraction`.** Без него `rollCounteract` на карточке получает null. Дать `counteraction` из `game.pf2e`-фабрики недоступно (`createCounteractStatistic` внутренняя) — собираем `Statistic.extend`-копией с доменами `counteract-check`; не получится в живом прогоне -> осознанный отказ: заметка в карточке «Развеивание — вручную», кнопка скрыта **[J]**.
- **Сотворение.** `spell.toMessage(null, {actualCast:true, create:false})` -> `updateSource({"flags.pf2e-automato.cast": {item, id, dc, attack}})` -> `ChatMessage.create(msg.toObject())`. Только после этого — счётчик частоты (порядок: сотворение, потом счётчик; гонка с `prepareData` закрыта ленивой записью).
- **Подключение автоматизации заклинания (ничего нового).** `message.item` восстанавливает встроенное заклинание (по `casting.embeddedSpell`, `parentItem` его пишет); `rules.resolveRule({origin,item})` находит правило каталога по slug/источнику — `challenge`, `zone`, `apply`, `repeat`, `move`, `onEvent` как у обычного каста. СЛ: ленивая запись даёт `item.spellcasting.statistic` на всех клиентах; снимок `flags.pf2e-automato.cast.dc` — страховка и **приоритетнее** `challenge.dc` правила заклинания (правка `use.mjs:121`, `resolveDC`).
- **Опции.** В `origin.rollOptions` сообщения добавляем `origin:item:cast-by-activation` (+ `origin:item:slug:<slug предмета>`). Бонусы после активации (спеллхарты: «+1d4 урона до конца следующего хода») — **отдельный примитив позже**, здесь не делаются.

## 3. Форма в схеме
Поле правила `cast: [Cast]` (рядом с `onEvent`, допустимо с любым содержимым; `wantsSnapshot` сейчас даёт `false` для правила без `onUse`/`macros` — расширить на `rule.cast?.length`):
```json
"cast": [ { "id": "electric-arc", "spell": "Compendium.pf2e.spells-srd.Item.kBhaPuzLUSwS6vVf",
            "rank": 4, "dc": 17, "attack": 7, "per": {"value":1, "unit":"days"},
            "requires": "invested", "label": "…", "note": "…" } ]
```
- `spell` — UUID, обязателен; `id` — slug (по умолчанию slug заклинания, уникален в правиле, часть id записи); `rank` 1–10 либо нет; `dc` — целое | `{level:"high"}` (СЛ по таблице уровня владельца, NPC; «high» — столбец high из таблицы СЛ pf2e) | нет (СЛ лучшей записи владельца; нет записи — блок «СЛ неизвестен» и `set-dc`); `attack` по умолчанию `dc-10`; `per` = `{value, unit}` с `unit` из `rounds|minutes|hours|days` (как `Apply.duration`, `rules.mjs:20`); `note` — текст для ГМа (ограничения Dominate, «to your specifications»).
- `requires` — поле правила-настройка: `"invested"|"equipped"|"held"|"none"`. **По умолчанию — запрет**: если поле не задано, берётся по предмету (investable -> `invested`, иначе носимое/в руках `equipped`; признаки pf2e `isInvested`, `isEquipped`, `carryType`), кнопка недоступна, пока условие не выполнено (в подсказке причина). `"none"` отключает проверку.
- Один элемент = одна активация (41 предмет — несколько). Своего `onUse` у активации нет: механику ведёт правило заклинания. **`cast` не зависит от `onUse` предмета**, кнопки рисуются при пустом `onUse`.
- **Валидатор** (`scripts/rules.mjs`): блок `cast` по образцу `onEvent`, ключ `cast.bad`, строки `rules.err.cast.bad` ru+en. **Мастерская** (`scripts/sheet.mjs`): `blankCast()`, `ruleToForm`/`formToRule` — строки «заклинание (перетаскиванием `@UUID`, `dropSpec`) / ранг / СЛ (число|по уровню) / раз в … / требует / заметка»; пустой список = поля нет; `reportEnv` показывает СЛ и ранг без каста. `DESIGN.md`, термины pf2ru.
- **Вывод из разметки (слой 2, `deriveFromMarkup`).** Разбор HTML по `<strong>Activate`: блок Effect с ровно одной ссылкой `spells-srd` + «cast» -> `cast`. Ранг — `(\d+)(st|nd|rd|th)-rank`; СЛ — первый `@Check[…|dc:N]` Effect, иначе «spell DC … is N» всего текста; `per` — из `<strong>Frequency</strong>`, **а при его отсутствии — из фразы «once per day for each spell» (спеллхарты, `per:{value:1,unit:days}` на каждый элемент)**. `@Check` блока активации, ушедший в `cast.dc`, **не выводится** в `onUse.challenge` предмета — ни в `deriveFromMarkup`, ни в промпте (иначе двойное испытание). `high` — одна ссылка и СЛ найдена либо у заклинания нет `defense.save`/атаки; остальное `low`; ссылок 0 или ≥2 не выводим. Проверка выборкой 50 (ROADMAP §10; `markup-derive-unreliable.md`).
- **Промпт черновиков** (`tools/prompts/draft-rule.md`): «You cast X» -> `cast`, `null` запрещён; `@Check` активации идёт в `cast.dc`, не в `onUse.challenge`; ограничения/выбор -> `note`.

## 4. Рантайм
- **Кнопка.** Блок модуля на карточке предмета (`kind:"card"`, `renderChatMessageHTML`, chat.mjs:19) — кнопка на каждый `cast[i]`: «Сотворить: Электрическая дуга (СЛ 17) · 1/день». Действие `cast-item` в `dispatch` (chat.mjs ~380).
- **Кто исполняет.** Только `actor.isOwner` (владелец или ГМ, нажавший кнопку); пути через ГМа (`callGM`) нет — не владельцу кнопка недоступна. Актёр — `fromUuid(use.actor)`; для несвязанного токена NPC это синтетический актёр токена (`Scene.x.Token.y.Actor.z`). Ленивая запись (§2) работает на любом клиенте по id, поэтому ГМ-вкладка применяет результат карточки без участия клиента автора. Лидер вкладок ГМа не двоит (`isLeader`).
- **NPC-способность без предмета** (3 action): та же форма `cast` в правиле action; `dc:{level:"high"}`; у action `system.frequency` pf2e списывает сам — только показываем «осталось».
- **Частота (снаряжение).** Флаг `flags.pf2e-automato.uses.<castId> = {n, at, log:[messageId]}` на предмете. Окно: rounds — по раундам боя, minutes/hours — `game.time.worldTime`, days — **сброс по хуку `pf2e.restForTheNight`** (стр. 25989; сбрасываются все `uses` предметов актёров хука), без отдыха — не сбрасывается. Исчерпано — **мягко**: кнопка активна, по клику `DialogV2.confirm` «использовано; всё равно?», не запрет. Счётчик пишется после сотворения.
- **Откат.** Карточка с `cast` удалена ГМом -> счётчик минус одно использование по `log` (`deleteChatMessage`).
- Нет заклинания в паке (мир без spells-srd) — кнопка неактивна с причиной.
