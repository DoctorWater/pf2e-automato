# План: ограждение копий по отпечатку текста (copy-guard)

Проблема (`ROADMAP.md` §5, «Известная проблема для всех пачек»): копия способности NPC с `source`, но с другим текстом, получает правило источника. Evil Eye у Kepgeda: источник (заклинание `f45JpY7Ph2cAJGW2`) — Sickened, текст копии — frightened, правило каталога вешает Sickened. Механизм общий, под все пачки; код не пишется до решения по двум развилкам внизу.

## 1. Как копия получает правило сейчас

`resolveRule` (`scripts/rules.mjs:1466`), порядок: флаг предмета -> world.bySource -> world.bySlug -> builtin.bySource -> builtin.bySlug -> builtin.byName -> разметка.
- По источнику: `sourceOf` = `_stats.compendiumSource ?? flags.core.sourceId ?? origin.sourceId`. Совпал uuid -> правило, текст не смотрится вовсе. **Здесь дыра.** Ограждений нет ни одного (`bySrc` не проходит блок «правило нашлось только по slug»).
- По slug: `bySlugOf(map, slug, type)` (ключ `slug@type`, затем общий). Ограждения есть, но не текстовые: `isSelfEffectOnly`, `slugCollides`, `lacksOwnRoll`, «СЛ из текста без спасброска» — и все только при `!sourceUuid`. Копия со slug и другим текстом (Nimble Dodge у NPC) проходит, если в тексте есть бросок.
- По имени: `byName` для копий без slug и source — вне задачи.
- Параллельный путь без `resolveRule`: `scripts/reactions.mjs:103` (индекс `onAttackedIndex`, тот же порядок slug/src) — **ограждать и там**, иначе реакция сработает с чужим правилом.
- Сборка: `tools/pa-port.mjs` `bySlug` — «все предметы с этим slug, в т.ч. NPC-копии без source, — одна способность»; `bySource[c.src]` — из копий одной способности одно правило. Каталоги: `catalog.json` (2 src/6 slug), `catalog.pa.json` (503/617), `catalog.model.json` (579/0), `catalog.campaign.json` (41/39), `catalog.onhit.json` (0/10 `slug@action`).

## 2. Масштаб (`tools/out/items.json` + `html.json`, скрипт — scratchpad `scale.mjs`)

Единицы — уникальные встроенные предметы NPC после дедупа `extract.mjs` (`тип|slug|normText`); в скобках экземпляры (Σ `dupCount`).
- Встроенных копий: 24 023 (70 516). Есть опорный документ компендия (по `source` или `тип+slug`): 5 254 (4 219 по source, 1 035 по slug).
- Текст расходится с источником (`normText`): 3 770 (72%; 14 849 экз.).
- Из них механически важно по «узкому» отпечатку: **981 (19% от опорных; 4 441 экз.)**. Остальные 2 789 — перевод/форматирование/имя существа/числа.
- Для сравнения: отпечаток «все токены включая числа» (`@UUID`, `@Check` с СЛ, `@Damage` с кубами, цифры) ложно мечет 2 713 (52%) — СЛ и урон у NPC всегда свои. Отпечаток всего текста — 3 770. Оба непригодны.
- Только копии, у которых в каталогах есть правило (по source или slug): 855. Текст расходится 634; узкий отпечаток — 177 (1 617 экз.); из них реальный конфликт (в копии есть состояние/эффект/проверка/тип урона, которых нет у источника) — 72, «копия лишь потеряла ссылку/токен» — 105. Цельнотекстовый отпечаток отключил бы правила у 634, то есть у 457 без причины.
- Evil Eye: 3 копии в дампе, 1 с расхождением (Kepgeda: frightened без `@UUID`; Irrokcis — тот же текст, правило остаётся).
- Оговорка: опорный документ для slug-пути — первый топ-документ с тем же `тип+slug`, приближение.

## 3. Механизм

**Что сравнивать — узкий отпечаток (множество, не мультимножество):**
- состояния: `@UUID` на conditionitems -> slug состояния; голые слова-состояния из текста (frightened, sickened…) — те же токены `U:slug`, поэтому «ссылка vs слово» не расходятся;
- `@UUID` на эффекты (spell-effects, feat-effects) и макросы — по uuid;
- `@Check` — только статистика (без `dc:`, без options: СЛ у копии свой, голову испытания уже берёт `withMarkupHead`);
- `@Damage` — только типы урона (не кубы); `[[/act slug]]`.
Числа, длительности, имя существа, прозу — не сравнивать (длительность и срок иммунитета тоже решает `withMarkupHead`/`immunityDuration`).

**Где хранить:** отдельный файл `rules/fingerprints.json` `{v, bySource:{uuid:{m,w}}, bySlug:{slug:[{m,w}]}}`, строит новый `tools/fingerprint.mjs` из текста источника (`html.json`/паки) после пересборки каталогов. Схему правил и четыре сериализатора не трогаем. `bySlug`: набор отпечатков всех предметов группы, из которых собрано правило. Ключ без отпечатка (правила-носители на эффектах, byName) — не огораживается (fail-open: ограждение не должно ломать готовое).
**Две хэш-версии:** `m` — только разметка (`@…`), `w` — разметка + слова-состояния. Функция `textFingerprint(html, condSlugOf)` живёт в `scripts/rules.mjs` (как `immunityFromText`: инструмент импортирует её оттуда), `condSlugOf` — из `ConditionManager` в рантайме и `refs.conditions` в инструменте.

**Рантайм (ru).** Текст копии в ru-мире переведён (pf2ru/babele), слов-состояний на английском нет; разметка `@UUID/@Check/@Damage` переводом сохраняется. Правило: в тексте есть кириллица -> сравниваем `m`, иначе `w` (та же проверка кириллицы уже есть в `markupHead`). `flags.babele.originalDescription` в коде не используется, в репозитории встречается лишь `originalName` — наличие оригинала описания **проверить живьём** (`Object.keys(item.flags.babele)`); если есть — сравнивать английский оригинал и тогда `m`-ветка не нужна. Источник сравниваем только по сохранённому отпечатку, документ компендия в рантайме не грузим (асинхронно, дорого).
**Для ru-копий — только «конфликт»:** отпечаток хранить как набор токенов (строка), а не хэш, тогда «копия ⊄ источник» считается точно; потерю ссылки при переводе не считаем расхождением. Развилка 1 ниже.

**При расхождении:** `resolveRule` пропускает builtin-правило (`bySrc`/`bySlug`) и идёт в `derive()`; результат — `found(d.rule,"markup", low…)` с `diverged:{from: sourceUuid}`. Выполняется только кнопкой ГМа (решение пачки 1: вывод ~50% неверен, в рантайме low). Если `derive()` пуст — `null`, `diverged` остаётся для бейджа/Мастерской: «текст копии отличается от источника, правило каталога не применено». Единая функция `guardCopy(key, item)` вызывается из `resolveRule` и `reactions.mjs`.
**Что не огораживаем:** правило-флаг на предмете и мировой каталог ГМа (`world.*`) — это явный выбор человека; кнопка «принять» в Мастерской уже пишет флаг.

**Производительность:** `resolveRule` зовётся на каждый бросок. `WeakMap<item, {desc, ok}>`: пока строка описания та же (`===`), результат переиспользуется; регэкспы идут один раз на предмет. Предметы без записи в `fingerprints.json` не считаются вообще.

## 4. Влияние на готовые каталоги и проверка до релиза

`node tools/fingerprint.mjs --report` по `items.json`/`html.json`:
1. **Инвариант:** копии с тем же `normText`, что у источника, расходиться не могут — 0 срабатываний (иначе баг отпечатка).
2. Список копий, чьи правила каталога отключаются (ожидаем 177 уник. / 1 617 экз.; 72 — при «только конфликт»), с причиной токенов; сортировка по экземплярам.
3. Выборка 50 по правилу §10 `ROADMAP.md`: человек/Haiku помечают ложные срабатывания; допустимо ≤ 5%. Ложные кладём в `rules/fingerprint-accepted.json` (`uuid копии`) — копия принудительно считается равной.
4. Тот же отчёт на ru-текстах (`RU_PACKS`, `descRu` в `items.json` усечён — брать из пака): доля расхождений `m` ru против `m` en при равном тексте должна быть 0, иначе переход на «только конфликт».
5. Гейт сборки: `tools/validate.mjs` падает, если у ключа каталога с известным источником нет записи в `fingerprints.json`.

## 5. Тесты

Юнит `tests/copy-guard.test.mjs` (по образцу `tests/core.test.mjs`/`af-harness.js`): отпечаток не зависит от СЛ, кубов, имени существа, порядка и регистра; зависит от смены состояния, добавления `@Check`, смены типа урона; «слово vs ссылка» равны; кириллический текст с теми же `@UUID` даёт тот же `m`; Evil Eye Kepgeda -> `diverged`, `source:"markup"`, `confidence:"low"`; Irrokcis -> `catalog`; предмет без записи -> правило применяется; флаг и мировой каталог не огораживаются; кэш пересчитывается при смене описания; `reactions.mjs` отдаёт то же решение.

## Открытые вопросы пользователю

1. Копия **потеряла** токен источника (105 из 177), но ничего чужого не добавила (развернула ссылку, убрала `@Check`): отключать правило каталога (симметрично, 177) или оставлять (только конфликт, 72)? Рекомендация: конфликт — всегда отключаем; потерю — только если потерян токен состояния/эффекта.
2. Расхождение: оставлять `derive` уровня low (кнопка ГМа) или «ничего + заметка»? Рекомендация: low, как везде.

Сравнивать отпечаток по `originalPayload.description`, если есть.
