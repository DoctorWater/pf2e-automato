# pf2e-autoflow proto-1: конвейер поверх чата (как MIDI)

Движок слушает `createChatMessage` и `createRegion` pf2e, собирает контекст (предмет по slug, цели, область) и прогоняет декларативное правило (`save` -> `byDegree` -> `apply` / `zone` / `reaction`). Результат - блок в чате с кнопками «Применить»; чужие токены меняются через `socketlib` (executeAsGM).

## Установка
Junction (создаёт Руководитель, не модуль):
`mklink /J "C:\Users\USER\AppData\Local\FoundryVTT\Data\modules\pf2e-autoflow-proto-1" "D:\ClaudeFun\pf2e-autoflow\prototypes\proto-1"`
Включить модуль в мире pf2e (нужны lib-wrapper, socketlib). Настройка «Режим Autoflow»: кнопка / сразу / выкл. Вся логика на клиенте активного ГМа - ГМ должен быть в сети.

## Проверка
Во всех тестах открыть консоль (F12) и следить за ошибками.

1. **Дымовая шашка.** Сцена с 2-3 токенами. У токена с «Дымовой шашкой (малой)» (`smoke-ball-lesser`) нажать использование, в карточке нажать `@Template` (burst) и разместить шаблон над токенами. Ожидание: в чате «Зона ...»; у региона появилась поведение «Зона Autoflow» (Настройки региона); токены внутри получили состояние concealed. Перетащить токен наружу - состояние снимается; затащить обратно - возвращается. Продвинуть мировое время на 60 с+ - регион удаляется, состояние снимается. Если Toolbelt удалил шаблон после «Target» - регион удаляется, и состояние снимется (зона теряется, см. «Заглушено»).
2. **Испытание по степеням.** NPC с «Дыханием огнём» (`breathe-fire`): использовать, разместить шаблон на токенах. Ожидание: блок с броском Рефлекса каждой цели, степень и множитель урона (текст; урон не применяется). Для степеней: выбрать цели (T) и использовать `frightful-presence` (Устрашающее присутствие, если у NPC есть) - блок с Волей и кнопкой «Применить» (frightened 1/2/3 по степени). Проверить кнопку у одной цели и «Применить всё».
3. **Эффект от предмета.** Персонаж использует «Бравую брагу (малую)» (`bravos-brew-lesser`). Ожидание: блок на самого пьющего, эффект из `@UUID` описания; «Применить» (или сразу в режиме auto) - эффект появляется на листе.
4. **Реакция.** У Лиарэль должна быть «Ловкое уклонение» (`nimble-dodge`). Бросить по ней атаку (Strike с выбранной целью Лиарэль). Ожидание: ей (и ГМу) шёпот «Доступна реакция» с итогом против КБ и предупреждением, если +2 меняет исход; кнопка создаёт эффект +2 КБ.

## Заглушено
- `breathe-fire` / `frightful-presence`: DC берётся из `@Check[...|dc:NN]` описания, иначе 17; урон не применяется (вне объёма).
- Слаг действия «Дымовая завеса» (`smoke-screen`) - догадка.
- Реакция: эффект +2 КБ живёт до начала следующего хода, не «только против этой атаки»; пересчёта попадания нет; только подсказка.
- Нет вкладки в листе предмета и редактора правил; правила - объект `RULES` в `scripts/main.mjs`.
- Применение зон всегда автоматическое (режим на них не влияет). Состояние-«Плохая видимость» = `concealed`; снимается только состояние с флагом нашей зоны.
- Цели для не-области: `User#targets` автора (синхронизация между клиентами не проверялась).
- Toolbelt Template Helper: если он удаляет регион после «Target/Cancel», зона исчезает по правилам (выход из удалённого региона снимает состояние). Не обходится.

## Чем хуже других подходов
- Привязка к разметке сообщений pf2e (`flags.pf2e.origin/context/messageId`): меняется между версиями, любое событие вне чата невидимо.
- Движок только на клиенте ГМа; без ГМа ничего не работает.
- Конфликт/дублирование с pf2e-automations и Toolbelt на тех же сообщениях (нет защиты).
- Правила по slug - свой каталог придётся вести вручную; вывод из разметки даёт только «применить эффект», не степени.
