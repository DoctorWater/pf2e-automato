# pf2e-autoflow proto-2: поверх Rule Elements pf2e

**Идея.** Автоматизации — собственные типы Rule Element (`AutoflowZone`, `AutoflowSave`, `AutoflowEffect`, `AutoflowReaction`), зарегистрированные в `game.pf2e.RuleElements.custom`. Мини-каталог по `system.slug` (фолбэк — `flags.babele.originalName`) подмешивает их предметам через lib-wrapper на `RuleElements.fromOwnedItem`; те же RE можно вписать в предмет руками (редактор правил pf2e) — тогда каталог не трогает предмет.

## Установка
Junction (создать самостоятельно):
`mklink /J "C:\Users\USER\AppData\Local\FoundryVTT\Data\modules\pf2e-autoflow-proto-2" "D:\ClaudeFun\pf2e-autoflow\prototypes\proto-2"`
Включить в мире вместе с lib-wrapper и socketlib. Настройка «Режим применения»: auto / button / off.

## Проверка (персонажи на сцене, ГМ + желательно игрок во втором окне)
1. **Дымовая шашка** (`smoke-ball-lesser`). Применить предмет у токена. На карточке нажать кнопку шаблона (в pf2e 8.6.1 это регион, не MeasuredTemplate) и поставить его на 1–2 токена. Ожидаем: сообщение «Зона: …», токены внутри получили состояние `concealed` (Плохая видимость). Вытащить токен из региона — состояние снялось; завести обратно — вернулось. «Закрыть зону» в чате (или удалить регион, или прокрутить мировое время на 1 мин) — всё снято.
2. **Испытание** (`breathe-fire` у гоблина-пиромана или `frightful-presence`). Вариант А: выделить цели (T), применить способность -> блок «СЛ …» с целями. Вариант Б: без целей, применить, поставить область из карточки -> цели = токены в области. Режим auto: сразу бросок и применение; button: «Бросить за всех» -> «Применить» -> «Отменить». У `frightful-presence` состояние `frightened` 1/2/3 по степени; у `breathe-fire` только степени (урон модуль не трогает). СЛ берётся из первого `@Check[...|dc:N]` описания, иначе 15.
3. **Эффект предмета** (`bravos-brew-lesser`). Использовать у токена. Ожидаем блок «эффект» и (auto) эффект из первой ссылки `@UUID[...equipment-effects...]` описания на пьющем. Кнопка «Отменить» снимает.
4. **Реакция** (`nimble-dodge`, Лиарэль). Атаковать Лиарэль целью-токеном. Ожидаем шёпот владельцам и ГМу: «Атака X против КБ Y: степень. С +2: степень» и кнопка «Использовать реакцию» -> на Лиарэль создаётся эффект +2 КБ (circumstance) до начала её следующего хода.

## Что заглушено
- Реакция срабатывает **после** броска атаки (подсказка и пересчёт степени; без нат. 1/20), не до него; не проверяется «реакция потрачена» и «видит атакующего».
- СЛ спасброска — из `@Check`/каталога/15, без СЛ заклинаний и классов. Броски идут без сообщений в чат (Dice So Nice не показывает).
- Слаги `breathe-fire`, `frightful-presence`, `nimble-dodge`, `bravos-brew-lesser` — по памяти, не сверены с паками (LevelDB не читал). Действие «Дымовая завеса» не в каталоге (слаг неизвестен).
- Зоны только из регионов pf2e; MeasuredTemplate и Toolbelt Template Helper не обрабатываются. Нет вкладки «Автоматизация» в листе предмета, нет живого списка внутри зоны, нет вызова `pf2e-vision`.
- Состояния кладутся как предметы из `ConditionManager.getCondition(slug)`, помеченные `flags.<id>.tag`; существующее такое же состояние не заменяется и не стакается.

## Чем хуже других подходов
- У RE в pf2e **нет события «предмет использован»** (есть onCreate/onDelete/beforeRoll/afterRoll…): `onUse` — наша конвенция, диспатчится из `createChatMessage`. Значит, половина логики всё равно живёт во внешних хуках, а RE — только носитель данных.
- Каталог вшит через обёртку `RuleElements.fromOwnedItem`; конструктор RE ждёт `sourceIndex` из `system.rules`, мы даём `null` — листы/редактор правил не знают про подмешанные RE.
- RE живут только на предметах **у актёра**: сработать с предмета, удалённого при использовании (расходник), нельзя — поэтому спека едет флагом в сообщении.
- Зависимость от внутренностей pf2e (`RuleElements.custom`, `fromOwnedItem`, формат `flags.pf2e.origin/context`) и `RegionDocument#_handleEvent` ядра. Любое обновление системы — риск.
