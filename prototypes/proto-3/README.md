# pf2e-autoflow-proto-3 — документы как состояние (регионы + флаги)

**Идея.** Движка-центра нет: зона — регион с собственным Region Behavior `pf2e-autoflow-proto-3.zone` (ГМ видит и правит его в конфиге региона), испытания/эффекты/реакции — флаги на ChatMessage и на созданных состояниях/эффектах (`flags.pf2e-autoflow-proto-3.meta`: кто, откуда, до когда). Триггеры — события регионов и хуки (`updateWorldTime`, `pf2e.startTurn`, `createChatMessage`). Состояние переживает перезагрузку, потому что лежит в документах. Чужие токены меняет только активный ГМ (`socketlib.executeAsGM`).

## Установка

Foundry v14.366, pf2e 8.6.1, нужны lib-wrapper и socketlib. Junction (cmd, от обычного пользователя):

```
mklink /J "C:\Users\USER\AppData\Local\FoundryVTT\Data\modules\pf2e-autoflow-proto-3" "D:\ClaudeFun\pf2e-autoflow\prototypes\proto-3"
```

Включить модуль в мире. В настройках модуля — режим для трёх автоматизаций (применять сразу / кнопкой / выкл.; по умолчанию кнопкой).

## Сценарии проверки

**1. Дымовая шашка (`smoke-ball-lesser`) — зона.**
1. Поставить два токена рядом, один — в предполагаемой области.
2. От персонажа использовать «Дымовая шашка (малая)» и поставить шаблон (регион pf2e).
3. Ожидание: в регион добавилось поведение «Зона Autoflow»; токен внутри получил «concealed» (с флагом `meta.source`); токен снаружи — нет.
4. Вывести токен из региона — состояние снялось; ввести — появилось. Удалить регион — состояние снялось.
5. Продвинуть мировое время на 60 с (или раунд боя x10) — регион удаляется сам, состояния снимаются.
6. Перезагрузить страницу посреди зоны — поведение и состояния на месте. Правка `expiresAt`/`condition` — в конфиге региона (вкладка Behaviors).
7. С включённым Template Helper (toolbelt) нажать Target/Cancel: регион, удалённый в течение 2 минут после создания, пересоздаётся один раз (опция «Восстановить…» в поведении).

**2. Испытание по степеням (`breathe-fire`, `frightful-presence`).**
1. Выбрать цели (T) и использовать способность; либо поставить шаблон после использования.
2. В сообщении появится блок «Спасбросок … СЛ …» со списком целей. Кнопка «Бросить спасброски» — бросок за каждую цель, степени цветом.
3. Для `frightful-presence` кнопка «Применить» накладывает frightened по степени; для `breathe-fire` показывается только множитель урона (урон не применяется — вне объёма).
4. Если целей нет, берутся существа в регионе с `flags.pf2e.messageId` этого сообщения.

**3. Эффект от предмета (`bravos-brew-lesser`).**
1. Использовать «Бравая брага (малая)» на персонаже.
2. В сообщении кнопка «Применить к <имя>» (в режиме «сразу» — без кнопки). На актёре появляется эффект из `@UUID[...equipment-effects...]` описания с флагом `meta` (by/from/until).

**4. Реакция (Nimble Dodge, `nimble-dodge`).**
1. У Лиарэль должен быть предмет со slug `nimble-dodge`.
2. Атаковать её токен (цель выбрана). После броска в сообщении атаки (видно ГМу и владельцу) блок «Доступна реакция» с расчётом «с +2 КБ».
3. Кнопка создаёт эффект с FlatModifier +2 КБ, истекает в начале её хода; блок помечается «Реакция использована» (флаг на сообщении).

## Что заглушено

- Правила — таблицы по slug в начале `scripts/main.mjs` (`ZONES`, `CHALLENGES`), без UI и без вкладки в листе предмета. DC/эффекты по степеням для `frightful-presence` выдуманы; slug «Дымовой завесы» (`smoke-screen`) — догадка.
- «Плохая видимость» = состояние `concealed` (отдельного состояния в pf2e нет; pf2e-vision не вызывается).
- Урон не применяется; реакция применяется постфактум (бросок атаки уже сделан — pf2e не даёт прервать его), трата реакции не отслеживается.
- Длительность зоны — мировое время; вне боя зона не истечёт, пока ГМ не продвинет время.
- Блок в чате не для обычных бросков, только для сообщений карточек предметов и атак.

## Чем хуже других подходов

- Нет единого места логики: состояние размазано по флагам, «что сейчас активно» не посмотреть списком; отладка — по документам.
- Автоматизации без области (реакции, одиночные испытания) втиснуты во флаги сообщений — неестественно и привязано к жизни сообщения (удалили чат — потеряли блок).
- Все клиенты получают события региона; единственность обеспечивает проверка `isActiveGM` — при смене ГМ посреди события возможны пропуски/дубли.
- Зависимость от того, что делают чужие модули с регионами (toolbelt удаляет регион — мы пересоздаём, это костыль).
- Правки в поведении региона меняют `system` документа и могут триггерить пересчёты у всех клиентов.
