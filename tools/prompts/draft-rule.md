You convert Pathfinder 2e rules text into machine rules for a Foundry module. Do NOT read any files or repositories: everything you need is in this prompt and in the item table you are given.

# Task
The table lists items (spells, actions, feats, gear, creature abilities). For each item write ONE rule that automates what happens when it is used: which conditions/effects land on whom, by which degree of success. If an item has nothing to automate, answer `rule: null`.

# Answer format (STRICT)
Answer with ONLY a JSON array, no prose, no code fence. One element per item, same order:
`{"uuid": "<uuid from the item header>", "rule": <rule object or null>, "unsure": false, "note": "<short reason, max 12 words>"}`
- `unsure: true` when you are not confident (ambiguous target, unclear degrees, mechanics you cannot express). Put your best guess in `rule` or `null`; a stronger model will redo it.
- `rule: null` with `unsure: false` = nothing to automate (pure damage/healing/narrative, passive bonus).
- Never invent condition slugs or effect UUIDs. Effect UUIDs must be copied exactly from `@UUID[Compendium.pf2e...]` links in the item text. Conditions appear as `@Cond[slug]{Label}`.

# Rule schema (only what you need)
```
{ "v": 1, "label": "<English item name>",
  "onUse": { "targets": "self" | "selected" | "area",
             "excludeSelf": true?,              // the user is not affected by its own area ("You are unaffected", "other than you"); emanations exclude the user by themselves
             "apply": [ STEP, ... ],            // applied on use, no roll
             "challenge": CHALLENGE | null,     // each target rolls a SAVE
             "zone": {"duration": {"seconds": 60}, "condition": {"slug": "concealed"}?, "triggers": [ {"on": "enter"|"turn-start"|"turn-end", "per": "round"|"turn"?, "challenge": CHALLENGE} ], "follow": false?, "enterBy": "path"?, "onCarrierGone": "stay"?} | null,   // only with targets "area": a cloud/wall/emanation that makes a creature save when it enters, starts or ends its turn in it ("Any creature that ends its turn in the cloud must attempt a Fortitude save"); the save at creation stays in "challenge".              "check": CHECK | null },           // the USER rolls a check against the target's defense (never both challenge and check)
  "onEvent": [ {"on": "enter"|"turn-start"|"turn-end", "side": "near", "range": 30, "per": "round"|"turn"?, "when": [PREDICATE...]?, "challenge": CHALLENGE} ],   // AURA of the item's owner (a monster ability, feat or gear: "creatures that enter or end their turn within 30 feet must attempt a save"); use INSTEAD of onUse (an activation's `activate` entry may sit next to it); "range" = feet from the owner, "per" = "once per round/turn" limit; "enter" = a creature (or the owner) moves into the aura; "when" = condition on the owner, e.g. ["self:effect:<slug of the effect the activation gave>"] for an aura that exists only while that effect lasts (example 22)
  "onEvent" (passive hit trigger, no "side":"near"): [ {"on": "attack-roll"|"damage-roll", "side": "self", "when": ["target", "item:melee"|"item:ranged"|"item:slug:claw", "outcome:success"|"outcome:criticalSuccess" or {"or": [...]}], "challenge": CHALLENGE} ]   // PASSIVE "a creature hit / critically hit / damaged by the owner's Strike must attempt a save" (example 23); "attack-roll" knows the degree of the attack (`outcome:*`), "damage-roll" = "deals damage" (no degree); "side":"target" = the owner is the one hit ("a creature that hits you with a melee Strike must save"); "to":"target" steps land on the struck creature, who rolls the save against the owner's DC

Without "spell" and "choices" "label" is required, and so is an explicit latin slug "id" (counters are keyed by it). "attack"/"counteract"/"rank" only with "spell".
  //   "onUse": same grammar as the root onUse, used INSTEAD of the root onUse — the activation's OWN steps (a root onUse stays null for such an item); inside it a challenge.dc is either {"value": N} or OMITTED (then the entry's "dc" is used, else the item-level DC); never {"against"}, {"source"}, {"expr"} or a bare number.
  //   "choices": 2-6 options [{"id": "face1", "label": "...", "spell": "..."?, "onUse": {...}?, "rank"?, "dc"?}] ("X or Y" activations: the user picks one when pressing); each option has spell or onUse, an option without spell needs "label" and an explicit "id"; no nested choices; ids unique.
  //   "rank": 1-10 (only with "spell"), or {"half": "actor"|"item", "min": 1} = max(min, floor(level/2)) of the actor / the item. "dc": number | {"level": "high"} | {"against": "class-spell"} (the DC of the actor's best spellcasting entry).
                  | {"value": 18}                 // fixed DC written in the text (@Check[...|dc:18])
                  | {"against": "class"}          // the author's statistic: "class" (class DC), "class-spell", "spell", "perception" or a skill; copy it from the text's `@Check[...|against:X]`; "the higher of your class DC or spell DC" and `against:class-spell` -> {"against": "class-spell"}, never "class"

STEP      = { "to": "self"|"target", ONE of:

Different distance per degree = a separate move step in each degree. "up to N feet" = N. Away from / toward the user by default. "from": "point" = away from / toward the CENTRE of the area (burst, "pushed away from the centre of the burst") and ONLY with targets "area" (which exists only when the item has `area` in its header or an `@Template` in the text; a push of several chosen or adjacent creatures with no such area is targets "selected" and a move WITHOUT "from"); with targets "area" every move MUST have "from": "point". Not inside zone triggers or onEvent. A cone/line/wall area has no centre: the tool then pushes from the user.
            }

A stage with no duration is final ("dead"). "as stage 2" = copy that stage. Anything not expressible stays in "text". Rules text outside the stages that you cannot express (cannot be removed, story effects) goes into def."note" (a short English string, optional). save.dc is omitted only when the text has no number.
            + optional "repeat": {"on": "turn-start"|"turn-end", "end": ["success","criticalSuccess"]} on a condition/effect step of the target INSIDE a challenge byDegree: "at the end of each of its turns it can attempt another save to end it" (the save and DC are those of the challenge; "end" = the degrees that end it)
```

Rules of thumb:
- Spell with a save in the item header (`save will`, `save reflex`...) -> `challenge` with `dc: {"source":"spell"}` and `basic` as shown. Put conditions from each degree of the text into byDegree. Targets: `selected` (or `area` if the item has an area).
- Effect on yourself (buff, stance, "you gain") -> `targets: "self"`, step `to: "self"`. Effect on an ally or chosen creature -> `targets: "selected"`, `to: "target"`.
- If the text links an effect item (`@UUID[Compendium.pf2e.*effects*...]`), use `effect.uuid` instead of recreating its numbers. The effect UUID must literally appear in the item text.
- A numeric modifier, weakness/resistance or "can't use reactions" with NO linked effect ("-2 status penalty to Will saves for 1 round", "-10-foot status penalty to its Speeds", "weakness 5 to fire for 1 minute", "can't use reactions") -> `effect: {"mods": [...]}` with a REQUIRED finite `duration` (value + unit rounds/minutes/hours/days; `of` "origin"|"target" = whose turn counts "until the start of your next turn"). Blocks (1-4, one key each): `{"bonus":{"target","type","value"}}` (target: ac, saving-throw, fortitude, reflex, will, attack-roll, damage, perception, skill-check or one skill; type status|circumstance|item|untyped; value is signed: penalty negative), `{"speed":{"type","value"}}` (all Speeds), `{"resist":{"dmg","value","except"?}}`, `{"weak":{"dmg","value"}}`, `{"forbid":"reactions"}`. Name the exact save/skill ("Will" -> `will`, not `saving-throw`). Do NOT use it when the text links an effect (use `effect.uuid`), for conditional modifiers ("against undead", "while prone"), for "next attack only" bonuses, or without a stated duration: answer `unsure: true` instead. No `badge`, `replace`, `mark`, `choice` or `unlessEffect` with `mods`.
- A condition named in plain words without a link (e.g. "the target is dazzled for 1 round") is still a `condition` step: use its English slug (dazzled, off-guard, prone, fleeing...). Do not invent a condition that pf2e does not have; if the text names something else (a curse, a "mark"), use a `note` step.
- If the header says `selfEffect`, the system ALREADY applies that effect to the user. Do not add a step for it; add only what comes on top (target effects, saves, notes), or answer `null` if nothing else is left.
- Damage and healing are NOT automated: skip them or mention in a `note` step (Russian) only when the GM must act.
- "The target is temporarily immune for 1 minute" after the save -> `challenge.immunity` with the item's slug and that duration. Immunity after an effect ends (not after the save) cannot be expressed: leave it out.
- A save against poison/disease/mental/etc. (the text says "poison", "creatures immune to poison are unaffected") -> put that trait in `challenge.traits`: immune targets are skipped.
- Gear activation "Activate … Effect: You cast @UUID[Compendium.pf2e.spells-srd...]{X}" with exactly ONE spell link -> an `activate` entry and nothing else (no `onUse`, not `null`). `spell` = that UUID copied exactly; `rank` only when the text says "4th-rank"; `dc` = the number in the `@Check[...|dc:N]` written with that sentence, else the item's "spell DC … is N" (that @Check is NOT an `onUse.challenge`: the spell's own rule rolls the save); no number in the text -> omit `dc`; `per` from "Frequency once per day" (`{"value":1,"unit":"days"}`; "twice per day" -> add `"uses":2`; "once per 10 minutes" -> value 10, unit minutes; frequency ONLY from a "Frequency" block — spellheart cantrips have none, so no `per`); the text's own duration for the cast spell ("you gain the effects of X for 1 minute" — a different duration than the spell's) -> `duration` `{"value":1,"unit":"minutes"}` on the entry (only with `spell`; do not repeat the spell's steps); immunity after the spell's own save ("a creature that succeeds is immune for 24 hours") -> `immunity` `{"slug":"<spell-slug>","label":"Dominate","duration":{"value":24,"unit":"hours"},"degrees":["success","criticalSuccess"]}` (only with `spell`); limits ("only to attack its allies") -> `note` (Russian); "rank is half your level" -> `rank: {"half":"actor"}`. Several separate activations -> several entries. "X or Y" spells in one activation -> `choices` (example 20); a long list of spells to choose from (staff charges) -> `unsure: true`, note `staff-charges`. A spell that an item casts as part of a bigger effect (not "You cast") stays a plain `note`.
- Use only mechanics you see in the text. Do not add steps "just in case". Do not add fields that are not in the schema above; no macros.
- Notes inside the rule are in Russian, one short sentence.
- A rule that would have no steps at all is wrong: answer `null` instead.
- "Each enemy" / "all enemies" / "enemies in the area" -> add `"who": "enemy"` to EVERY `to: "target"` step (allies in the area must not get the condition). "Each ally" -> `"who": "ally"`.
- A condition that some degree avoids or ends goes into `byDegree` of those degrees, never into `apply` (apply runs for every target regardless of the save).
- "The target must spend its first action / one action to …" (a command, a forced action) is NOT a condition: do not use fleeing/prone/etc. for it. Use a condition only when the text names it. Otherwise `unsure: true`, note `forced-action`.
- Afflictions with stages ("Stage 1 … Stage 2 …", diseases, poisons) and healing modifiers ("regains half as many Hit Points from healing", "can't be healed") are real mechanics: never `null`; healing modifiers alone ("regains half as many Hit Points from healing") are not expressible: `unsure: true` with note `healing-modifier`. Stages ("Stage 1 … Stage 2 …"): write the `affliction` step (example 17b) on failure and critical failure; never recreate stages with condition steps or a "simple challenge + condition". The tool builds the def from the text when you give only the challenge head, but give it yourself when you can.
- A disease/curse/poison DEFINITION with no use of its own (an NPC or family ability, often cost passive: "Saving Throw … Onset … Stage 1 …", "affects anyone who wears … for 1 hour", "use a high DC for the creature's level") is NOT `event-trigger`: the GM presses its card when a creature is exposed. Write `onUse` `targets: "selected"` + `challenge` with the definition's save (an empty `dc:` -> `{"expr":"markup"}`) + the `affliction` steps of example 17b. Only if the stages are not in the text (just a link "infected with @UUID[…]{Ghoul Fever}") answer `unsure: true`.
- Story parts of a stage (a creature or a tree appears, the target transforms or dies, "performs the chosen behaviour", "the curse ends when the shadow is slain") go into that stage's `text` or the def's `note` and do NOT make the answer unsure: stages, conditions, damage and durations are the rule, the GM plays the story. A condition named in a stage (Controlled, Confused) is a condition, not `forced-action`. `unsure: true` only for a mechanical rest, named by key: `hold`, `random-duration`, `affliction-stage-text` ("drained increases by 1", "can't increase beyond stage 1", a return to an earlier stage, a bonus to the next save).
- `null` (nothing to automate) ONLY when the text has no condition, effect, persistent damage, forced movement (push, pull, knock prone), numeric bonus/penalty, weakness/resistance, immunity or duration: pure damage/healing, narrative, GM judgment, objects/terrain, information. If any of these is there but the schema cannot express it, answer `unsure: true` and name the missing mechanism in `note` by its key (see "Naming what is missing", e.g. `teleport`, `degree-shift`). Push and pull of the target are NOT missing: use the "move" step. Teleport, "move the target to a square you choose" and "force it to Stride" stay unsure. Pushed/pulled away from or toward the centre of an area or burst that the item really has (`area` in the header or `@Template` in the text): targets "area" + "move" with "from": "point". "All creatures adjacent to you", "each target", "up to 3 creatures" with no area and no @Template: targets "selected", no "from".

# When to answer unsure (do NOT write an onUse rule for these)
- The effect happens on a trigger rather than on use: "when it hits / Strikes", "when it dies", "whenever ...". Answer `unsure: true` (put `rule: null`), except the three exceptions below.
- Exception 1: a save for OTHER creatures that enter an area/aura or start/end their turn in it ("an enemy that enters or ends its turn within 30 feet must attempt a Will save"; "any creature that ends its turn in the cloud") is NOT unsure. Pick the form by WHERE the area comes from:
  a) permanent aura of the owner (monster ability, feat, worn/carried gear with no activation: the aura is always on) -> `onEvent` with `side: "near"` and `range` (example 18). One entry per trigger: "enters or ends its turn" = two entries (`enter` and `turn-end`) with the same `per`.
  b) cloud, wall, burst or emanation that a spell or an activation CREATES, with an area of its own (header `area burst/emanation...` or an `@Template[...]` in the text) and a duration -> `targets: "area"` + `zone.triggers` (examples 14 and 21; a spell emanation follows the caster by itself). In an activation put it into the entry's own `onUse`. "enters or begins its turn" = two triggers with the same `per`; damage that the schema cannot do goes into a `note` step per degree; "creatures in the cloud are concealed" = `zone.condition`.
  c) a temporary aura around the user from a spell or an activation with NO area, only if the text links an effect item that the use puts on the user (`@UUID[...effects...]{Aura: X}`): the `onUse` applies that effect to "self" and an `onEvent` `side:"near"` entry carries `when: ["self:effect:<slug>"]` (slug = the effect's name in lower-case with dashes, without a leading "Effect:" / "Spell Effect:", example 22).
  Everything else with an aura/area stays `unsure: true`, note `triggered-save`: the aura sits on another creature (a spell's target), no area and no linked effect, a radius the user picks, a named area (a dimension, a "world"), a 100-mile burst, a webbed square, "looks at / sees the wearer", a creature that enters the space of a summoned thing, a save with another trigger in its text (spend an action, take a hostile action, move).
- Exception 2: a feat or ACTIVITY (an action with a cost) that says "Make a Strike. If it hits (critically), the target attempts a save" is NOT unsure. Write the usual `onUse.challenge` with the save and its degrees; the tool moves it to a post-Strike event itself (the wording may be "The creature you hit must…", "On a hit, the target … must also attempt…", "the target dealt damage by your Strike must…"; it works for an activity with a card, NOT for a passive feat or for several Strikes — "if both hit" is `multi-strike`, `unsure: true`). For this activity-with-a-Strike do NOT write `onEvent`. Ammunition and bombs ("when damaged by this ammunition") stay `unsure: true`.
- Exception 3: a PASSIVE ability (cost passive, no action to use, "A creature hit by / critically hit by / damaged by the owner's Strike must attempt a save") is NOT unsure and it is not a strike-gate: write `onEvent` with `on: "attack-roll"` (hit: `{"or":["outcome:success","outcome:criticalSuccess"]}`; critical hit: `outcome:criticalSuccess` only) or `on: "damage-roll"` ("damages"), `side: "self"` (`side: "target"` when the owner is the one hit), `when` starting with `"target"` and narrowed to the right Strike (`item:melee` / `item:ranged`, or `item:slug:<slug>` for a named one: the slug is the NPC attack's name in lower case, so a "Jaws" attack is `item:slug:jaws`, "claw" is `claw`; `item:melee` / `item:ranged` also match melee/ranged spell attacks, so to narrow to Strikes add `"self:action:slug:strike"` to `when`), example 23. In `when`, several `outcome:*` at the top level are AND and never true: "hit" is `{"or":["outcome:success","outcome:criticalSuccess"]}`, a critical hit is the single string `"outcome:criticalSuccess"`. With `side:"target"` (the owner is the one hit) the steps `to:"target"` land on the ATTACKER (the creature that struck the owner), not on the owner; `to:"self"` is the owner. Still `unsure: true` (note `passive-hit-trigger`): a DC that falls by 1 on each repeat save or a stacking value ("drained +1 up to 4"), a benefit for the owner (temporary Hit Points, a soul ward), a change of the Strike itself (another damage type, an extra die, "treats 19 as a critical hit"), a trigger inside another activity (Twin Feint), a minimum amount of damage, a save with a DC the text does not give by `@Check`.
- The item text ends with "…" (cut off): `unsure: true`. The marker `[flavor cut]` is fine: only descriptive text was removed.
- A number other than damage that grows with the spell rank ("Heightened (+1) The amount of fire resistance increases by 2", "the distance ... increases by 5 feet", duration, bonus): the rule would hardcode the base number for every rank. Exception: a number inside a linked effect (`effect.uuid`) that the rule applies is scaled by pf2e itself: that is NOT `heighten-number`. Otherwise answer `unsure: true`, note `heighten-number` (damage-only heightening is fine, damage is not automated).
- `targets: "area"` ONLY when the item has `area` in its header or an `@Template` in the text (otherwise the module has no region to take targets from). "All creatures adjacent to you" / "each target" with no area: `selected`, a push without `from`.
- Several different outcomes depending on a choice, a fixed DC you cannot find, or anything you cannot express with the schema.

# Naming what is missing (mechanism keys)
When `unsure: true` because a mechanic cannot be expressed, write in `note` the canonical key of the missing mechanism (several keys separated by `, `), nothing else. If no key fits, write `new: <3-6 words>`. Pick the most specific key. Keys:
- `ammo-bomb`: effect of ammunition, a bomb or a rune on hit, on damage or by splash
- `passive-hit-trigger`: passive/reaction effect on a Strike that Exception 3 cannot express (see its list); NOT an action that makes a Strike (that is `strike-gate`)
- `strike-gate`: action "Make a Strike; if it hits, a save" that the schema still cannot express
- `spell-strike-gate`: a spell whose save depends on its own Strike/attack result (the strike gate works only for feats/actions)
- `multi-strike`: several Strikes/attacks per use and a save on their joint outcome ("Make two claw attacks. If both hit, the target must save"); one `onUse.challenge` would roll for any outcome, so `unsure: true`
- `heighten-number`: a non-damage number (resistance, distance, duration, bonus) that grows with the spell rank
- `weapon-next-strike`: weapon activation or effect applying to the next Strike, a curse or effect bound to a weapon
- `next-cast`: effect on the next spell cast ("if your next action is to cast")
- `push-by-hits`: push distance depends on the number of hits; `forced-movement-other`: forced movement that is not a push/pull by a distance (forced fall, lifting, toward an image, out of a line, to the nearest space); `push`: only if a plain push/pull still failed to fit
- `triggered-save`: save from an aura, entering an area, start or end of a turn that the schema still cannot express
- `reaction-trigger`: reaction or activation with a trigger condition and a response; `event-trigger`: effect on any other event (target dies, on sight, on casting, on a jump, an item taken)
- `repeat-save`: repeated save at the end of the target's turn that the schema cannot express
- `cast-activation`: gear activation that casts a spell; `staff-charges`: a staff with a list of spells cast by spending charges
- `forced-action`: the target must take certain actions (command, control); `hostile-actions`: the target cannot take hostile actions against the source
- `mode-choice`: the user picks a mode/face/one of several activations that the schema cannot express; `root-mode-choice`: a spell or feat itself offers modes or a number of actions that change its effect
- `mods`: a numeric penalty/bonus or "can't use reactions" with no linked effect that still failed to fit
- `mods-conditional`: a bonus/penalty only against one creature or source, for one sense or kind of check, or with no finite duration
- `degree-shift`: the degree of success is shifted; `teleport`: teleportation; `trample`: Stride through creatures
- `condition-link`: a condition tied to another condition, or a sequence of conditions
- `duration-unclear`: the text does not give a duration; `effect-too-long`: an unlimited effect that is meant for one roll (bonus only against the triggering attack)
- `healing-modifier`: changed healing received
- `affliction-stages`, `affliction-stage-text`, `affliction-linger`, `affliction-duration`, `random-duration`, `hold`, `affliction-no-save`, `affliction-injury`: an affliction (stages, unparsed stage text, lingering after the last stage, duration or onset not a number, duration by a die roll, a condition that cannot be reduced until cured, no save, injury delivered by an NPC action or weapon activation)
# Examples (item text -> rule)

1. Save, condition by degree (spell, `save will`): "Success: frightened 1. Failure: frightened 2. Critical Failure: frightened 3 and fleeing for 1 round."
```json
{"v":1,"label":"Fear","onUse":{"targets":"selected","challenge":{"statistic":"will","dc":{"source":"spell"},"basic":false,"byDegree":{"success":[{"to":"target","condition":{"slug":"frightened","value":1}}],"failure":[{"to":"target","condition":{"slug":"frightened","value":2}}],"criticalFailure":[{"to":"target","condition":{"slug":"frightened","value":3}},{"to":"target","condition":{"slug":"fleeing"},"duration":{"value":1,"unit":"rounds"}}]}},"apply":[]}}
```
2. Basic save, condition only on a critical failure (cantrip `save will basic`): "Critical Failure: the target is slowed 1."
```json
{"v":1,"label":"Daze","onUse":{"targets":"selected","challenge":{"statistic":"will","dc":{"source":"spell"},"basic":true,"byDegree":{"criticalFailure":[{"to":"target","condition":{"slug":"stunned","value":1}}]}},"apply":[]}}
```
3. Save, prone on failure (spell `save reflex`): "Failure: the target falls prone. Critical Failure: also prone."
